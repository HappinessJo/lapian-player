语义/约束：

- **下拉目录请求**：`qn=80/fourk=1` 一次返回账号允许的完整档位梯；`fourk=1` 不等于选 4K。T8.10 若需要“4K 手动切档”，应复用同一目录并按用户选择重新取流/下载。
- **档位判定**：只用 `dash.video[].id`；`data.quality`/`accept_quality` 只记录。`DefaultQn()` 永不自动选 116/74/≥120。
- **size**：DASH 响应没有总字节；`DashStream::size=0` 表示未知。T8.10 必须用 Content-Length/末段 Range/分片对账，不能拿带宽×时长当真值。
- **init/index**：独立闭区间（不保证相邻）；T8.10 的初始化段/索引段 Range 请求应直接用 `ToString()`/`start/end`。
- **菜单（T8.9）**：`dash_playback_available=false` 时 DASH 档 `enabled=false`，`disabled_reason` 写 T8.10；T8.10/T8.12 接入后把该开关置 true，模型会自动允许手动切档（`manual_only` 仍为 true，不自动）。
- **缓存/记录**：T8.9 不改缓存键；缓存命中目录来自 meta（qn/codecid/fps/分辨率，可能缺 fps/宽高），不联网。

## 4. 关键决定与解释

1. **一次 fnval=4048 请求拿完整梯子**：实测 `dash.video[]` 与请求 qn 基本无关（16/32/64/80 都返回），所以菜单无需逐档请求；请求 qn 只影响 `data.quality`。这也是“档位菜单只列示”的依据。
2. **档位只信 `dash.video[].id`**：匿名请求 qn=80 返回 `quality=64`，dash 只有 16/32；单测/探针都断言 `quality` 不参与判定。`data.quality` 只写入 `claimed_quality` 供证据。
3. **默认 AVC、60/4K 只手动**：`DefaultQn()` 只挑非手动档的 AVC；116/74/≥120 永不自动。HEVC-only 60fps 返回 0，不自动、不静默降帧。
4. **T8.9 不切档**：DASH 播放需要 T8.10 双输入，所以菜单里 DASH 档置灰并写明原因；“当前播放”勾选的是 **durl 实际档**（例如 OB-1 720P），不假装已经是 DASH 1080P。`dash_playback_available` 是给 T8.10/T8.12 的开关。
5. **目录请求放在首帧之后**：不把 fnval=4048 的 JSON 拉进 OP1 关键路径；失败只提示、不影响播放；缓存命中不发请求（0 网络）。代价是每次在线打开多 1 个 API 请求（M1 E2E first_frame 640ms 未退化）。
6. **不要在状态栏用 `QPushButton::setMenu()`**：实测首次绘制阻塞 UI ~620ms（`QEvent::Paint` + `QPushButton`），M1 E2E 的 `ui_gap` 62→679ms、first_frame 656→1276ms；改成“普通按钮 + 点击时按需创建/弹出 QMenu”后恢复 59ms/640ms。T8.12/T8.15 加菜单时沿用这个做法。
7. **`--no-quality-catalog` 是诊断开关**：只关闭首帧后的目录请求，做 A/B/回归；不是产品功能。
8. **不新增缓存键**：DASH 视频/音频的缓存键与目录约定留给 T8.10（尤其音频单独键）；T8.9 不碰 `CacheStore` 写语义，避免半成品键污染现有 durl 缓存。

## 5. 已知缺口

1. **大会员档不可得/未验证**：`vip_status=0`，`dash.video[]` 无 116/74/120；4K 真实请求、HEVC/AV1 解码、HDR 颜色未验；O11/T8.15 才能做，不写成 MVP。
2. **DASH 播放未接**（T8.10）：init/index Range、双流缓存、共享时钟、seek fan-out、单流 EOF 都没做；菜单里的 DASH 档**有意置灰**。
3. **`size` 未知**：DASH 不返回总字节；T8.9 记 0，不伪造。
4. **只测 3 条 OB**：其他稿件可能出现只有 HEVC/只有低档/无音轨；解析层有无音频/坏条目单测，但**没有真实无音轨在线样本**（OB-6 未选）。
5. **`dolby`/`flac` 未解析**：多音轨/杜比不在 T8.9；`dash.audio` 的 `codecid=0`，用 `codecs` 区分 AAC/HE-AAC。
6. **UI 只在 OB-1 跑**（OB-2/3 无 GUI）；100%/200% DPI 下菜单布局未单独复测。
7. **目录请求失败重试/缓存未做**：失败只提示“不影响播放”；未在断网/限频下跑 20 次。
8. **OP1 未做 20×3 复测**：T8.9 未改 OP1 口径；M1 E2E first_frame 640ms（基线 656ms）说明关键路径未退化，但完整 OP1 矩阵仍属 T8.14。
9. **M1 E2E 是 1 条样本**（OB-1；28/0）；T8.8 的 3/3 结论未重跑（T8.9 未改 durl 请求/下载/读层）。
10. **`quality` 字段在 DASH 请求下**与本机账号表现一致（80），但匿名会撒谎；未来接口可能变化，档位判定必须继续只信 `dash.video[]`。
11. **缓存命中 0 网络未在 T8.9 重跑**：需要完整缓存 + `--online-offline-test`（本次未下载完整样本）。代码路径上缓存命中在 `EmitCacheHitReady` 用 meta 构造目录、不启动目录线程，按设计 0 请求；完整离线复测留给 T8.10/T8.14。
12. **目录请求失败/限频未压测**：只验证了正常路径与 M1 E2E；断网/412/429 下只保证“不影响播放”的代码路径，没有 20 次重复。

## 6. T8.10 需要什么 / 下一步

- **双输入**：视频/音频各自 `GrowingSource` + `DownloadJob` + `AVFormatContext`；用 `DashStream/DashAudioStream` 的 `url/backup_urls/init_range/index_range` 建计划；音频缓存键（bvid+cid+audio_id+…）由 T8.10 决定并写进 `meta.json`（不改 schema 的前提下加字段或新 key 约定，需在 T8.10 里明确）。
- **总字节**：DASH 没有 `size`；用 Content-Length/末段 Range/分片对账，`DashStream::size` 继续保持 0=未知，不要伪造。
- **默认档**：直接复用 `DefaultQn()/DefaultStream()`；4K/60fps 只可能来自菜单手动选择（`IsManualOnlyQuality`）。
- **菜单**：把 `QualityMenuContext::dash_playback_available` 置 true 后，模型会允许手动切档（`manual_only` 仍不自动）；切档的重取流/索引重建/标记 PTS 映射是 T8.12。
- **回归**：M1 durl 路径不得回退（`--online-m1-test` 28/0、first_frame/UI gap）、缓存命中 0 网络（`--online-offline-test`）、本地 P1/P2/P7、`ctest`。
- **不要**把 T8.9 的“菜单列示”当 M2 通过；M2 门是 T8.14。
