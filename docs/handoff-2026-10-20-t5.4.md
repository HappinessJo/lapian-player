## 2. 本轮做了什么

### 2.1 截图来源：按键瞬间已显示的帧

- `MainWindow` 新增 `displayed_frame_`（`AVFrame*`）与 `displayed_frame_index_/displayed_rotation_`。
- 只在这几条“精确呈现”路径更新：
  - 打开文件后的首帧；
  - `GoToFrame` 的精确落帧；
  - `OnFrameReady` 的播放/循环/定帧帧。
- 更新方式是 `av_frame_unref` + `av_frame_ref`，按键路径不重新 seek、不做像素拷贝；硬解帧的纹理引用由 `av_frame_ref` 保持。
- 拖动预览帧**不**写入 `displayed_frame_`。拖动中按 `S` 会提示“拖动预览中，松开后再截图”，避免把降采样预览当成源分辨率截图。这是对 spec 未覆盖边界的明确选择。

### 2.2 `SnapshotService`（后台线程）

- [src/app/SnapshotService.h](../src/app/SnapshotService.h)/[.cpp](../src/app/SnapshotService.cpp)：
  - 有界队列（4）；`Capture` 在 UI 线程只做 `av_frame_ref` 并返回。
  - 工作线程：硬解帧 `av_hwframe_transfer_data` → `sws_scale` 到 BGRA → 按显示方向旋转 → WIC PNG 编码到内存 → `QFile::NewOnly` 写盘。
  - `Drain()`：切文件、关窗、析构前等待队列清空，避免工作线程持有旧会话/解码器资源。
  - 目录选择每个任务重新探测；图片目录回退由 `SnapshotNaming` 负责。
- D3D11 立即上下文不是线程安全的。新增 [D3D11Context.h](../src/platform/gfx/D3D11Context.h) 的递归锁：
  - `VideoDecoder` 仅硬解路径加锁（软件预览解码不抢锁）；
  - `GfxWidget::SetFrame/PresentFrame/UpdateSwapChainSize` 加锁；
  - 截图硬解回读加锁。
- 硬解回读不在 UI 线程；UI 线程只做 `av_frame_ref`、目录/文件名之外的入队与状态提示。

### 2.3 命名/目录/旋转纯函数

- [src/media/SnapshotNaming.h](../src/media/SnapshotNaming.h)/[.cpp](../src/media/SnapshotNaming.cpp)：
  - `SanitizeSnapshotBaseName`：Windows 非法字符/控制字符替换 `_`，去尾部点/空格，避开 `CON/PRN/AUX/NUL/COM1-9/LPT1-9` 等设备名，超长截到 120。
  - `FormatSnapshotTimecode`：NDF `HH-MM-SS-FF`，按标称帧率（23.976→24、29.97→30）；无效帧率回退 30fps。
  - `BuildSnapshotBaseName`：`{视频名}_f{帧号}_{HH-MM-SS-FF}`；`{视频名}` 是去掉扩展名的完整文件名。
  - `ResolveSnapshotDirectory`：`<视频目录>/snapshots` → 用户图片目录下 `拉片软件/`；用同目录临时文件真实探测可写性，而不是只看只读属性。
  - 重名由 `QFile::NewOnly`（`CREATE_NEW`）保证不覆盖；序号为 `_1`、`_2`…。
- [src/app/SnapshotImage.h](../src/app/SnapshotImage.h)/[.cpp](../src/app/SnapshotImage.cpp)：
  - display matrix 角度与渲染器一致，四舍五入到 90°；
  - `SnapshotDisplaySize` 对 90/270 交换宽高；
  - `RotateSnapshotImage` 用 `QTransform().rotate(-rotation)` 实现 FFmpeg 逆时针语义。

### 2.4 MainWindow 接入

- 新增 `S` QAction，`WindowShortcut`，打开文件后启用。
- `CaptureSnapshot`：
  - 文本输入框聚焦时让位（`IsTextInputFocused`，MarkPanel 的 `ShortcutOverride` 是第二层）；
  - 无画面/拖动预览/队列满时给状态栏提示；
  - 请求只含视频路径、帧号、rotation、帧率；
  - 状态栏“正在保存截图（帧 N）…”；成功后显示实际路径；回退时显示“视频目录不可写，截图已保存到图片目录：…”。
- `OpenFile`/`closeEvent`/析构调用 `Drain()`；`OpenFile` 成功时清空截图测试状态。
- 新增测试入口：`CaptureSnapshotForTest`、`PressSnapshotKeyForTest`（发送真实 `QKeyEvent`）、`DrainSnapshotsForTest`、`ClearFocusForTest`、`SnapshotStateForTest`、`SnapshotSavedPathsForTest`、`SnapshotDisplaySizeForTest`、`SnapshotPerfSummaryForTest` 等。

### 2.5 自动化

`main.cpp` 新增 `--snapshot-test`（可配 `--file A --file-b B`）：

1. A 帧 100 连拍 3 次，等待队列清空，断言 3 个文件、3 个不同名、PNG 尺寸为显示方向源尺寸、文件名含 `f100`；
2. 帧 100 发送真实 `S` 键，断言快捷键生效；
3. 打开备注编辑器，发送 `S`，断言不新增截图（焦点隔离）；
4. 帧 20 播放中按键，断言保存帧 == 按键瞬间帧，播放状态保持；
5. 用同名文件占住 `snapshots`，断言回退图片目录、提示、当前标记不丢；
6. 若给了 `--file-b`，打开带 90° display matrix 的 B，断言 PNG 1080×1920；
7. 断言工作集合在 P11 上限内（1080p 800MB / 4K 1.5GB；开发机工作集，不是正式 P11）。

测试图片回退根通过 `--snapshot-pictures`/`SetSnapshotPicturesRootForTest` 注入，避免污染真实用户图片目录。

## 4. 口径与决策

1. **截图来源是“最后一次精确呈现的帧”**：不在 `S` 时重新 seek；播放中是按键前最后一次 `frameReady`。F6-A4 的 ±1 帧由“保存帧号 == 按键时记录帧号”自动化断言。
2. **拖动预览中不截图**：预览帧是降采样且可能不是目标帧；给出提示而不生成伪源分辨率文件。spec 未覆盖拖动中按 `S`，这是实现边界，已写入本文件。
3. **重名序号**：`_1`、`_2`，不覆盖；由 `QFile::NewOnly` 兜底，避免检查与写入之间的竞态。
4. **时间码**：NDF、按标称帧率（与 UI 时间码一致）；VFR 下帧号仍是主键，时间码只是文件名辅助。
5. **目录回退**：真实写入探测；回退根为图片目录下的 `拉片软件/`；提示走状态栏，不弹模态框，避免打断播放。
6. **线程边界**：UI 线程只 `av_frame_ref`；回读/转换/旋转/PNG/写盘都在工作线程；D3D11 立即上下文用递归锁与解码/渲染串行化。
7. **队列上限 4**：满足同帧 3 连拍，同时给 4K 帧引用设上限；超过时明确提示。
8. **不改 sidecar/schema**：截图不写 sidecar，不新增第三方库，WIC 编码。

## 5. 缺口 / 不宣称

1. **不是 V5/V4 正式验收**：竖屏样本是 V9 加 90° display matrix，4K 样本是 V9 放大的合成片；真实 V5 VFR 手机录屏、V4 4K 片未跑。
2. **不是真人验收**：F6-A3/A4/A5/A7 都是自动化（程序化按键/直接入口），没有真人看画面/听播放连续性；`S` 是 `QKeyEvent`，不是物理键盘。
3. **只读目录只测了同名文件阻塞**：`snapshots` 被同名文件占用触发回退；没有在 T5.4 重跑 ACL 只读目录。T5.1 的 ACL 只验证 sidecar 存储回退，不等于截图回退。
4. **回退目录是注入的 workspace 路径**：自动化用 `build/t5.4-snapshot-pictures`，没有写真实 `%USERPROFILE%\Pictures\拉片软件`；F6-A7 的“用户图片目录”真实路径仍未手测。
5. **P11 不是正式数字**：4K 工作集 452.8MB（峰值 502.6MB）是开发机进程工作集，不是基线机 P11；1080p 147.6MB 同理。没有 10min/2h soak。
6. **播放连续性只验证“未暂停/帧号正确”**：没有统计 4K 回读期间的丢帧数或音频 underrun；D3D 锁可能让单帧呈现延迟，未做 P9。
7. **软解/10-bit 未端到端**：自动化样本走 D3D11VA 硬解（`hardware=1`）；软件帧转换路径与 P010 10-bit 没有截图验收。
8. **VFR 时间码未单独验收**：文件名按标称帧率；VFR 的真实 PTS/帧号对应仍是 T2.2 的范围。
9. **长 GOP F4-A2 未改善**：仍为 T7 优化项；T5.4 未在长 GOP 上测截图。
10. **拖动中截图未实现**：按 §4.2 明确提示；若以后要求拖动预览也能截源分辨率，需要另立任务/改 spec。
