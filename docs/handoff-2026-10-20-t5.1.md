## 2. 本轮做了什么

### 2.1 文件、库与 schema

- 新增 [src/core/MarkStore.h](../src/core/MarkStore.h)、[src/core/MarkStore.cpp](../src/core/MarkStore.cpp)，编译为独立静态库 `lapian_marks`（只依赖 Qt6::Core，不依赖 FFmpeg/UI）。
- 新增 [tests/mark_store_test.cpp](../tests/mark_store_test.cpp)；`ctest` 第 5 项为 `lapian_mark_store_test`。
- **没有改 MainWindow**：T5.1 只做存储层；Ctrl+M、侧栏、时间轴标记留给 T5.2。

sidecar 路径：视频同目录的 `<视频完整文件名>.lapian.json`，例如 `测试.mp4.lapian.json`。
spec/ADR 写的是 `<视频名>.lapian.json`，对“含不含扩展名”有歧义；这里选择**含扩展名**，避免同目录 `a.mp4` 与 `a.mkv` 共用同一个 sidecar 而串数据。若用户明确要求 stem 命名，只需改 `ResolveMarkPaths` 一处，T5.2 前改动成本最低。

AppData 回退：`%APPDATA%\拉片软件\marks\<SHA-256(规范化路径)>.json`。

schema v1（UTF-8、缩进 JSON）：

```json
{
  "schema": "lapian.marks",
  "schema_version": 1,
  "video": {
    "path": "C:\\...\\测试.mp4",
    "path_key": "c:\\...\\测试.mp4",
    "size": 201407930,
    "duration_us": 120000000
  },
  "marks": [
    {
      "id": "26f0e0d4-...",
      "frame": 100,
      "pts": 3333333,
      "label": "帧 100",
      "note": "第一处转场",
      "created_at": "2026-10-20T03:40:00.000Z",
      "updated_at": "2026-10-20T03:40:00.000Z"
    }
  ]
}
```

- `pts` 单位是微秒（AV_TIME_BASE），与 `FrameIndexEntry::pts_us` 一致。
- `created_at`/`updated_at` 是 ISO-8601 UTC、毫秒。
- `id` 是 UUID（无花括号）。
- 路径规范化：绝对化、解析 `.`/`..`、反斜杠、存在本地文件时解析 8.3/符号链接、去掉 `\\?\`、去尾分隔符；`path_key` 再小写，作为身份与哈希输入。UNC 只做字符串规范化，不做文件系统解析，避免离线网络路径阻塞。
- 哈希：规范化路径 UTF-8 的 SHA-256，64 位小写 hex。

### 2.2 读、合并、写

`MarkStore::Open(video_path, duration_us, options, lookup)`：

1. 计算 `VideoIdentity`（规范化路径、大小、时长）。
2. 同时读 sidecar 与 AppData 回退：
   - 损坏 JSON：改名备份为 `.bak`（已有 `.bak` 时用 `.bak.1`、`.bak.2`…），按无标记继续；
   - 更高 `schema_version`：**保留原文件、不备份、不覆盖**，返回 `kUnsupportedSchema`；
   - 读失败/备份失败：返回警告并阻止后续覆盖。
3. 两边都存在时按 mark `id` 合并；冲突取 `updated_at` 较新者，时间相同保留 sidecar 版本；结果按 frame/pts/created_at/id 排序。
4. `FrameLookup` 非空时做 frame+pts 校正：优先 frame；帧对应 PTS 不一致时用 `frame_of_pts` 找回帧号并更新 pts，发 `kPtsMismatch`；PTS 找不到则保留 frame 并更新/保留 pts。T5.2 从 `FrameIndex` 提供回调。
5. 空结果删除 sidecar 与回退文件（F6-A6）。
6. 有标记且需要合并/迁移/校正时，写当前规范位置：先 sidecar，失败回退 AppData；成功后清理另一副本（迁移回 sidecar 或清理旧回退）。

`Save()`：

- 空标记：删除 sidecar 与 AppData 文件（F6-A6），返回 `removed`。
- 非空：先写 sidecar；失败写 `%APPDATA%` 回退；两者都失败返回错误并写 `kSaveFailed` 警告。
- 原子写：同目录 `.tmp-<uuid>` → write → `QFile::flush` → `FlushFileBuffers` → `ReplaceFileW`（目标存在）/`MoveFileExW`；任一步失败删除临时文件，旧文件不变。

`MarkStore` 暴露给 T5.2 的接口：`marks()`、`FindMark()`、`AddMark()`、`SetMarkText()`、`RemoveMark()`、`Save()`、`storage_path()`、`using_fallback()`、`warnings()`。

### 2.3 只读目录手测入口

测试程序支持手动模式（不注册到 ctest）：

```powershell
$env:LAPIAN_MANUAL_VIDEO = "E:\...\readonly.mp4"
$env:LAPIAN_MANUAL_APPDATA = "E:\...\appdata\marks"
.\build\release\Release\lapian_mark_store_test.exe --manual-readonly
```

Windows 的 `main()` argv 是 ANSI 代码页，中文路径会坏；因此手动路径用环境变量传（Qt 读取为 Unicode）。正式 ctest 不依赖这个入口。

## 4. 缺口 / 不宣称

1. **F6-A1/A2、F6-A6 的 UI 验收未做**：T5.1 只有存储层；Ctrl+M、侧栏、删除确认、时间轴标记是 T5.2。
2. **F8-A2/A3 的 UI 验收未做**：存储层的“备注落盘/按文件隔离”已测；关窗 flush、失焦/回车保存是 T5.2/T5.3。
3. **无删除墓碑**：如果旧 sidecar 在只读目录里删不掉，AppData 里删除的标记下次打开仍可能被合并回来；会发 `kMigrationFailed` 提示。ADR-006 未要求墓碑，多实例风险按 ADR 接受。
4. **无跨进程锁**：多实例同时写仍可能分叉，靠 id+updated_at 合并缓解。
5. **网络盘延迟/UNC 真实读写未测**：只测了 UNC 字符串规范化；T7.5 再验。
6. **8.3 短路径**没有单独断言；依赖 `QFileInfo::canonicalFilePath` 解析，T7.5 可补。
7. **`storage_path()` 在“无标记且无文件”时是预测的 sidecar 路径**，不是已落盘位置；第一次保存后才是实际位置。T5.2 UI 可显示“尚未保存”或该预测路径。
8. **sidecar 命名含扩展名**：见 §2.1 的歧义说明；如改 stem，需要同时改单测与交接。
9. **F6-A8（100 标记 UI 响应）未测**：T5.2 的验收，不是 T5.1。
10. 正式 V1–V8/V10、基线机、4K、10min soak、设备拔出、波形/听感真人验收仍待 T7。
