## 2. 本轮做了什么

### 2.1 Bug 1：B 在文件末帧时循环停住

根因：B 不是末帧时有 B+1 作为边界；B 是末帧时只能等 EOF，而 EOF 分支依赖
`current_frame_ >= B`。如果音频时钟在 B 的 PTS 之前停住（音频先 EOF），
`pending_pts > target` 会让 Tick 一直 return，B 永远不“到点”，EOF 也进不去。

修复（[`src/app/PlaybackController.*`](../src/app/PlaybackController.cpp)）：

- `loop_out_reached_`：`pending_frame_ >= loop_out_` 或 B 被 emit 即记录；
  EOF 分支用 `loop_out_reached_ || current_frame_ >= B || last_decoded_frame_ >= B`。
- B 等待上限：`max(100ms, 一帧媒体时长 / rate * 1.25 + 30ms)`；超时先把 B
  放进 best_frame 呈现，再回 A。这样 0.25x 不会提前跳。
- `JumpToLoopStart` 失败最多重试 3 次，打 `loop_jump_failed`，不再直接停；
  第 3 次失败才 `Finish()`。
- `LoopJumpCountForTest()` 暴露成功跳转次数。
- 新增 `--loop-end-test`：A=last-20、B=last，5s 后断言 `jumps>=3`、
  `playing=1`、`loop=1`、当前帧在范围内。V9/1080p/4K 均通过（5/6/6 次）。

### 2.2 Bug 2：PgUp 后退画幅变大

根因：1080p D3D11VA 纹理分配 **1920×1088**，显示尺寸 **1920×1080**；
旧 `VideoRenderer::UploadHardwareFrame` 用纹理尺寸做 fit。T7.2 缓存命中返回的是
1920×1080 软件帧，PgUp 时 fit 从 1088 切到 1080，画幅轻微变化。
4K 2160 能被 16 整除，通常不复现。

修复（[`src/platform/gfx/VideoRenderer.*`](../src/platform/gfx/VideoRenderer.cpp)）：

- 硬解帧用 `frame->width/height`（显示尺寸）创建目标纹理；
- `CopySubresourceRegion` 用 `D3D11_BOX` 只拷贝有效显示区域；
- `video_width_/height_` 也用显示尺寸；
- 新增 `video_width()/video_height()` 回归 getter。

回归（[`tests/video_renderer_test.cpp`](../tests/video_renderer_test.cpp)）：

- 断言渲染尺寸 == `AVFrame` 显示尺寸（不是纹理分配尺寸）；
- 同一帧写入 `FrameCache` 再取回、上传，断言缓存回拷前后渲染尺寸一致；
- 新增 1080p 硬解素材；4K/10-bit 继续测。
- `lapian_frame_cache_test` 增加 1080p 回拷尺寸断言（1920×1080，不是 1088）。

## 4. 决策与口径

1. **B=末帧用显式 `loop_out_reached_`，不再只看 `current_frame_`**：末帧没有 B+1，
   EOF 前可能因音频时钟停住而不更新 current。
2. **B 等待上限按帧时长/速率缩放，不用固定 250ms**：0.25x 的 24fps 单帧墙钟约
   166ms，固定 250ms 会跳早；当前公式约 238ms。
3. **循环跳转失败重试 3 次再 Finish**：避免一次 seek 失败就停；也不无限重试。
4. **硬解帧只渲染显示区域**：1080p 的 1088 分配行不参与 fit/采样；缓存软件帧
   与硬解帧口径统一。
5. **不改 T7.2 缓存策略**：仍只在后退步进 `kBackwardWindow` 预热；普通跳转/
   前进/播放 `kNone`。
6. **不提前宣称用户画幅验收**：自动化只证明渲染尺寸一致；PgUp 的人眼观感、
   真实 4K/VFR/10-bit/HDR 仍要用户/T7.7 复测。

## 5. 缺口 / 不宣称

1. **不是正式 V1/V10/V4**：V9、152s 1080p、450 帧 4K proxy。
2. **没有用户物理复测**：循环次数和渲染尺寸已自动化；画幅观感待用户确认。
3. **没有 0.25x 的 B=末帧长跑**：hold 公式按 rate 缩放，但本次只跑 1x 5s 回归。
4. **没有 2h soak**：T7.3。
5. **真实损坏文件/设备丢失**：连续 3 次 seek 失败会 Finish，归 T7.5。
6. 不把本文写成 F4-A1/A2 正式验收、P7 通过、用户画幅验收或基线机结论。
