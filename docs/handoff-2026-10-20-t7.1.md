## 2. 本轮做了什么

### 2.1 启动埋点

[`src/app/main.cpp`](../src/app/main.cpp)：

- 进程启动时间取在 `QApplication` 构造之前（P1/P2 从进程创建算起）；
- `--startup-test` 自动打开日志，记录 `app_created` / `window_created` /
  `window_shown` / `ui_ready` / `open_begin` / `open_returned` / `first_present`；
- 无文件时在 `ui_ready` 后 120ms 退出（P1）；有文件时等 `first_present` 后 80ms 退出（P2）；
  10s 超时 exit 3，打开失败 exit 2；
- `LAPIAN_STARTUP_LOG=1` 也可只开日志、不自动退出。

[`src/app/GfxWidget.*`](../src/app/GfxWidget.cpp)：`SetVideoFrame` 置 `present_pending_`，
`Present` 成功后发 `framePresented`（在 D3D11 锁外发）；MainWindow 转发给 main。

[`src/media/MediaSession.*`](../src/media/MediaSession.cpp)：`MediaOpenTimings` 记录
probe / decoder open / first frame / index 的耗时；`OpenFile` 打印 `open_timing`。

### 2.2 索引后置（真正的 P2 优化）

- `MediaSession::Open(..., bool build_index)`：产品路径 `false`，只探测 + 解码首帧；
  `BuildIndexNow()` / `InstallIndex()` 分开；默认 `true` 保持既有同步语义。
- `FrameIndex::BuildFromFile(..., cancel)`：每读一个包检查取消；取消返回 false，
  不留下半成品索引。
- MainWindow：
  - `BeginIndexScan()`：`SetTotal(Scanning)`、时间轴用容器估算帧数但禁用、步进/跳转/
    缩放/标记/波形开关禁用、清空旧标记 UI、预览器置空；
  - `StartIndexBuild()`：`std::thread` + generation + `atomic<bool>` cancel；
    完成后 `QMetaObject::invokeMethod` 回 GUI 线程；
  - `ApplyIndexState()`：索引就绪后时间轴/导航恢复、`SetTotal(Exact/Estimated)`、
    用索引做 frame+pts 校正后加载 MarkStore、创建 PreviewDecoder；
  - `CancelIndexBuild()`：generation 失效 + 置取消 + join；析构/空态/切文件都调用。
- **标记延后到索引完成才加载**：MarkStore 的 frame+pts 校正需要索引；扫描中标记按钮
  禁用，用户不可能在窗口期改标记，因此不会丢编辑。
- **VFR 不因索引完成改写总帧语义**：仍显示“扫描中”（T6.5 口径）；
  CFR 才从 Scanning → Exact/Estimated。
- 旧 GUI 回归（key/mark/note/snapshot/fullscreen/banner/dpi/ab/loop/settings）在 main 里
  调用 `SetIndexSynchronousForTest(true)`，保持“打开后立即可导航”的既有语义；
  产品路径和 `--startup-test` 走异步。**不要把这个开关改成产品默认。**

### 2.3 新回归与脚本

- `--index-test`：用 1080p 152s 素材观察扫描中（`ready=0 scanning=1 nav=0 timeline=0
  total=1`）→ 就绪（`frames=4573 nav=1 timeline=1 total=3`）→ 再开 V9 验证标记在
  索引完成后加载（`count=1`）；12 项、0 失败。
- `--startup-test`：冷启动测量；不是功能测试，不参与常规回归矩阵。
- [`scripts/startup-bench.ps1`](../scripts/startup-bench.ps1)：20 次 P1/P2、CSV、
  p50/p95、19/20 判定；T7.8 基线脚本可复用。
- `lapian_frame_index_test` 增加取消 3 断言（返回 false、不留下索引、错误文案）。

## 4. 决策与口径

1. **P1 = `ui_ready`（事件循环第一次派发）**：窗口已 show、可见、能处理事件；
   不是“首帧画面完成”。spec 的 P1 是“窗口可交互”，这个口径可复现且不把 GPU 首帧
   混进来。P2 才量首帧 Present。
2. **P2 用 `Present` 成功作为呈现点**：DWM 合成延迟未单独测，与 T0.2 口径一致；
   不把“SetVideoFrame 返回”当首帧呈现（那会少算一次绘制）。
3. **异步索引而不是“先显示索引中再同步建”**：同步后置仍会冻结 UI 数秒；
   V1 上限 10 分钟（spec §8），1080p 索引约 0.37s/152s，10 分钟约 1.5s，
   2 小时约 17.7s（外推）。后台线程 + 扫描中禁用依赖索引的交互，是唯一不阻塞
   首帧且不假装可交互的做法；ADR-003 本来写的就是“后台 PTS 索引”。
4. **扫描中禁用时间轴/步进/跳转/缩放/标记**：这些动作都需要精确索引；禁用比
   “拖了没反应/帧号乱跳”诚实。播放仍可立即开始（顺序解码不需要索引）。
5. **标记加载延后，而不是先加载再校正**：窗口期标记按钮禁用，不存在用户编辑；
   先加载旧 frame 再重写会引入“未保存修改被覆盖”的风险。侧栏在扫描中短暂为空，
   换取零数据丢失。
6. **VFR 总帧数保持“扫描中”**：T6.5 的 VFR 语义是“帧号按显示帧计数、总数不承诺”；
   索引完成也不改这条，否则 `--banner-test` 的 VFR secondary 断言与 F2-A7 提示会回归。
7. **旧 GUI 回归用同步索引开关**：这些测试在 `OpenFile` 后立即导航（400ms 内），
   而异步索引在这台机器上要 19–374ms；同步开关保持测试确定性，不改变产品路径。
   异步路径由 `--index-test` + `--startup-test` 覆盖。
8. **D3D11 不懒初始化**：P1 255ms，距 1.5s 有 5.9 倍余量；把设备创建挪到首帧后
   只会把“窗口出来但视频区卡 227ms”变成新的体验问题。若基线机 P1 逼近 1.5s 再评估。
9. **索引线程 join 而非 detach**：取消标志每包检查，join 通常在毫秒级；避免
   “关窗后 worker 还向已销毁 QObject post 事件”的生命周期风险。网络盘卡死是 T7.5。

## 5. 缺口 / 不宣称

1. **不是冷缓存 P1/P2**：没有清 OS 文件缓存/重启后首次启动；20 次是暖文件缓存。
2. **不是基线机/正式 V1**：6C/12T + RTX 4060 + 32GB，不是 4C/8GB/集显；
   素材只有 720p 代理、152s 1080p 与 4K 代理，没有 V1 的 3–10 分钟真实片。
3. **不是文件关联验收**：P2 用 `--file` 模拟双击入口；ProgID/安装/双击在 T7.6。
4. **没有 V10/2h 实测**：索引时长/内存是外推；10min soak 归 T7.3。
5. **没有真实 4K VFR/HDR、200% 真实显示缩放、多显示器、IME/AltGr**；归 T7.7。
6. **索引线程 join 可能被卡死的 `av_read_frame` 拖慢**（网络盘/异常设备），归 T7.5。
7. **P1 的 D3D11 成本未拆成更细的 device/swapchain/shader 三项**；只知道在 `show()`
   内约 227ms。需要时再加分段埋点，不要凭印象优化。
8. 不宣称 P1/P2 在基线机、正式 V1、冷缓存下通过；不把开发机数字写成 F1-A1 正式验收。
