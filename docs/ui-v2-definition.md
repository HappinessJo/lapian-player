## 0. 本轮结论（先看这里）

1. **改的是壳，不是引擎。** 重做顶栏、Transport、Inspector、空状态、状态与横幅的
   信息架构与视觉；键位、0 基帧号、点击即暂停、拖动降质/松手精确、M1/M2/P4/P6/P7
   门槛与数字**一律不动**。
2. **当前壳有三个真实缺陷，且都能被截屏+代码证伪**：
   - `InfoBar`（文件名/规格/帧号/时间码所在条）**实际是浅底 + 浅色文字**，
     实测对比度 **1.28:1**，等于不可读（§1.2）；
   - 产品**没有任何可见播放控件**：没有菜单栏、没有工具条、没有播放按钮，
     `Space` 之外全靠记快捷键（§1.3）；
   - 200% DPI 下画面只剩 687×242，占窗口高度 **53.5%**（§1.4）。
3. **骨架定为四区**：顶栏 + 视频 + 底部 Transport/时间轴 + 右侧可折叠 Inspector，
   保留系统标题栏（不做无边框）。
4. **本轮不解决**：上述缺陷不在定义阶段修（零代码）；它们进入 3A 的必做清单。
5. **下一步**：用户批准本文件的范围/原则/指标后，另开会话做规划（信息架构、
   设计令牌、可点原型、迁移顺序），仍不写产品代码。

## 1. 现状盘点（为什么改）

### 1.1 视觉是"三个世界"拼起来的

| 区域 | 背景 | 来源 | 真实观感 |
|---|---|---|---|
| 视频区 | 纯黑 | D3D11 交换链 | 正常 |
| 时间轴 | `#18181b` / `#2a2a30` | `TimelineWidget` 自绘 | 深色，正常 |
| 右侧标记栏 | `#18181b` | `MarkPanel`（显式 `WA_StyledBackground`） | 深色，正常 |
| **InfoBar** | **系统浅色 `#f3f3f3`** | `InfoBar` 样式表**未生效** | **浅底浅字，不可读** |
| 状态栏 | 系统浅色 | 原生 `QStatusBar` | 浅色，深色字 |
| 对话框（在线打开/设置） | 系统浅色 | Qt 默认 | 浅色 |

证据：`src/app/InfoBar.cpp:33-37` 只调 `setStyleSheet()`，**没有**
`setAttribute(Qt::WA_StyledBackground, true)`；同仓 `src/app/MarkPanel.cpp:61-68`
显式设置了该属性（代码注释写明"否则列表以外的区域会露出窗口底色"）。
`InfoBar` 不是 `QFrame` 子类，纯 `QWidget` 不画样式表背景。

### 1.2 信息条对比度 1.28:1（实测）

对 `build/ui-baseline/build/t6.4-dpi-dpi125-normal.png` 采样：

- InfoBar 底色**众数 `(243,243,243)`**（出现 17,910 像素），
  **不存在**本应出现的 `#202024`（`(32,32,36)`）；
- InfoBar 文字像素为 `(216,216,220)`（样式表 `#d8d8dc`，采样 311 像素）；
- WCAG 对比度 **1.28:1**（正文要求 ≥4.5:1）。
- 放大裁图 `build/ui-baseline/crop-infobar-125.png` 可直接肉眼确认：
  `sample.mp4`、`1920×1080 · h264 · 30.000 fps`、`帧 0`、`00:00:00:00`、
  `总帧数 4573` 几乎融进背景。

这解释了用户长期反馈的"信息看不清"——不是字体小，是**前景和背景撞色**。
新壳若继续用"普通 QWidget + 样式表"写容器，会以同样方式踩坑，必须写进
3A 的验收（§6-M2）。

### 1.3 没有可见的播放/步进控件

- `MainWindow` 中**不存在** `menuBar()`、`addToolBar()`、`QToolBar`（已 grep 确认）。
- 播放、步进、循环、速度、静音、标记、截图、全屏全部只是 `QAction` +
  `Shortcut`；唯一可见入口是状态栏里一个 `设置` 按钮（在线时才多一个 `清晰度`）。
- 状态栏塞了 **9 个 permanent widget**：其他提示、音频、速度、循环、波形、
  音量滑条、设置、清晰度、版本/状态文本；100% 下状态栏高 28px。
- 实测空状态截屏（`build/ui-baseline/empty-100.png`）：整屏黑，唯一引导是
  时间轴里一行极淡的"打开视频后显示帧刻度"；**看不到"打开"入口**。
- 状态栏文本还会互相挤：空状态时左侧红色缓存告警 + 右侧"无音频 1x 循环…"
  紧贴在一起，长错误文本没有省略策略。

结论：**可发现性**是当前最大问题——**用户得先知道怎么按，才知道能干什么**。
这不是"换肤"能解决的，属于信息架构（§3 范围已含）。

### 1.4 高 DPI / 窄窗口下画面被挤扁

T6.4 `dpi_state` 实测（逻辑像素）：

| DPI | 窗口 | 视频区 | Inspector | 时间轴 | InfoBar | 画面占高 |
|---|---|---|---|---|---|---|
| 100% | 1280×720 | 980×530 | 300 | 128 | 34 | 73.6% |
| 125% | 1280×720 | 980×528 | 300 | 128 | 35 | 73.3% |
| 150% | 1248×624 | 948×432 | 300 | 128 | 35 | 69.2% |
| 200% | 928×452 | **687×242** | 241 | 128 | 53 | **53.5%** |
| 窄窗口 | 820×500 | 580×293 | 240 | 128 | 51 | 58.6% |

固定 128px 时间轴 + 34–53px 信息条 + 28px 状态栏在高 DPI 下把画面压到一半。
新壳必须让**画面优先**（§5-P1），下栏高度进令牌、按可用高度收缩。

### 1.5 信息分层混乱（同类信息散落）

| 信息 | 现在放哪 | 问题 |
|---|---|---|
| 文件名 | InfoBar 左下 | 与规格同行，且不可读 |
| 规格（分辨率/编码/fps） | InfoBar 底部 | 本该是次要信息，却占一行 |
| 帧号 | InfoBar 底部中间（16pt 粗体） | **主锚点**却在最暗、最小的位置 |
| 时间码 / 总帧数 | InfoBar 底部右侧 | 与帧号挤在一起 |
| 播放状态 | 状态栏文本（"已打开，停在第 0 帧"） | 与错误/缓存告警抢同一行 |
| 循环/速度/波形/音量 | 状态栏 | 与状态消息混排 |
| 标记/备注/存储位置 | 右侧固定 300px 栏 | 无媒体时也常驻，占 23% 宽 |
| 降帧/VFR/10-bit/无音频/4K 提示 | InfoBar 单条横幅 | 出现在底部，视线不经过；且同样不可读 |

一句话：**一件事的信息被切成三处，三处又都不是为它设计的位置。**

## 2. 目标用户与核心场景（不重开）

沿用 [AGENTS.md](../AGENTS.md) §4 与 `spec.md` §3：静止系 MAD / PV / MG / 动画师，
Windows 桌面端，本地为主、在线为辅。首期验收优先服务 **MAD/PV 的"卡点 + 逐帧看转场"**。

UI v2 只服务这五条既有场景的**可达性**，不新增场景：

| 场景 | UI v2 要回答的问题 |
|---|---|
| S1 找卡点 | 波形、播放头、帧号是否一眼可读？拖到某帧是否 1 次操作？ |
| S2 拆运动 | A/B 循环状态是否始终可见？0.25–0.5x 速度是否可见可改？ |
| S3 精确回访 | 帧号能否直接输入？当前帧是否永远显示在同一位置？ |
| S4 记录 | 打标记/写备注/截图是否有可见入口？存储位置是否不打扰？ |
| S5 快速过片 | 播放/暂停是否有按钮？速度是否一眼看到？ |

## 3. 范围与非目标

### 3.1 用户已拍板（2026-10-25）

| 决策 | 结论 | 说明 |
|---|---|---|
| 范围 | **布局 + 视觉 + 信息架构** | 不动交互模型与键位 |
| 骨架 | **顶栏 + 视频 + 底部 Transport/时间轴 + 右侧可折叠 Inspector** | 保留系统标题栏，不做无边框 |
| 视觉 | **深色专业工具**（单一深色主题） | 不做浅色、不做跟随系统 |
| 产品契约 | **全部保持** | 键位 `spec.md` §3.7、0 基帧号、点击/拖动时间轴即暂停、拖动降质预览 + 松手精确、M1/M2/P4/P6/P7 门槛与数字 |

### 3.2 改什么（本期范围）

1. **主区域骨架**：顶栏（文件/来源/规格/动作）、视频区、Transport、时间轴、
   右侧 Inspector、状态栏；删除"InfoBar 既当信息条又当横幅"的职责。
2. **信息架构重排**：帧号/时间码升为主锚点（Transport 中央大号）；
   规格降为次要（顶栏副标题）；播放/循环/速度状态各归其位；
   存储位置降到 Inspector 页脚。
3. **视觉系统**：单一深色调色板 + 间距/字号/控件高度令牌 + 3 个语义色
   （就绪 / 缓冲 / 错误）+ 可见 focus ring；全部自绘容器显式
   `WA_StyledBackground`（堵住 §1.2 的坑）。
4. **空状态**：从"整屏黑"改为可操作占位（打开本地 / 在线打开 / 拖放提示）。
5. **横幅与状态**：统一 banner 槽（仅一条、可关闭的降帧横幅、不遮挡画面与时间轴）
   + 状态栏单一消息位 + 次级指标（音频/缓存/波形）。
6. **在线状态可见化**：解析/加载/缓冲/缓存命中/错误/切档/扫码都在壳内有明确位置；
   DEC-4 的 fps 角标保留（位置从帧号旁改到顶栏/Transport 副信息）。
7. **可发现性**：从 `spec.md` §3.7 键位表生成"键位 → 可见入口/tooltip"对照，
   覆盖率 100%；不新增功能，只让已有能力被看见。

### 3.3 不改什么（硬边界）

- **不新增功能**；候选池（播放列表、分镜识别、导出…）一律不进 UI v2。
- **不改产品契约**：`spec.md` §3.7 键位、0 基帧号语义、点击/拖动时间轴即暂停、
  拖动降质预览 + 松手精确、A=B 定帧、VFR 提示口径。
- **不改性能路径**：`GfxWidget` 呈现、`PreviewDecoder`/`DragStrategy`、
  `OnlineSession` 状态机、`CacheStore`；不做 4K/60 与 `post_seek_immediate` 修复。
- **不重开验收门**：M1/M2、P4/P6/P7/P9、DEC-1…6、ADR-001/004/007、
  `lapian-cache-1` schema、缓存键（含 `audio-<id>`）。
- **不换栈**：不引入 QML/Electron/新 UI 框架（ADR-004）；Qt Widgets 内解决。
- **不做主题切换/自定义快捷键**（候选池项）。

## 4. 目标（可验收的"为什么"）

按优先级：

- **G1 一眼可用**：新用户看空状态 5 秒内能说出"怎么打开片子"；
  老用户不用回忆快捷键就能找到播放/步进/循环/标记。
- **G2 帧号是第一公民**：当前帧在任何状态（播放/暂停/拖动/全屏）都在同一个
  位置、同一字号、足够对比度可直接读出；可点击输入。
- **G3 画面优先**：视频区是唯一可以"变大"的区域；其余栏位高度受令牌约束，
  高 DPI 与窄窗口先收栏位、不收画面。
- **G4 状态不打架**：同一时刻只有一条横幅；错误/缓冲/缓存命中/降帧互不覆盖；
  状态栏只有一条主动消息。
- **G5 视觉统一**：除标题栏与系统文件对话框外，不出现"浅色系统控件"
  （状态栏、滑条、按钮、滚动条、对话框全部进主题）。
- **G6 零性能代价**：P0 parity 61/0、T8.6.1b 35/0、key 77/0、A 42/0、local 9/0
  不变；P1/P2/P4/P6 不退化。

## 5. 设计原则（8 条）

- **P1 画面优先**：任何新增栏位都要回答"它值得从画面拿走多少高度"。
  固定高度只给顶栏、Transport、状态栏；时间轴按可用高度收缩（下限于标尺可读）。
- **P2 一个信息一个家**：同类信息不得出现在两处（帧号只在 Transport 中央；
  播放状态只在 Transport 的播放按钮 + 状态栏消息，不重复到三处）。
- **P3 控制必须在画面外**：视频区是独立 HWND（`WA_NativeWindow` /
  `WA_PaintOnScreen`）。**不做浮在画面上的控制条/进度条/角标**；
  唯一例外是"空状态/错误状态隐藏 HWND 后用 Qt 占位"（§11-Q1 需实测）。
- **P4 键盘与原语不变，按钮是"看得见的快捷键"**：所有按钮都必须映射到已有
  `QAction`/既有行为，`spec.md` §3.7 主备键位全部保留；tooltip 显示快捷键。
- **P5 深色是唯一主题，但不是"全黑"**：视频纯黑 `#000`；壳层 3 级灰
  （`surface` / `surface-raised` / `border`）；正文对比度 ≥4.5:1，大字/图标 ≥3:1。
- **P6 状态用颜色+文字双编码**：就绪/缓冲/错误/缓存命中各自有语义色，
  但永远同时有文字，不靠颜色单独传达（色弱可读）。
- **P7 不遮挡、不跳动**：横幅参与布局（出现时推下内容，不覆盖）；
  面板展开/折叠瞬时完成，不做动画（避免 UI 线程无谓负载）。
- **P8 每个控件可寻址**：新组件必须有稳定 `objectName`，供 `--key-test`、
  `--dpi-test`、`--banner-test` 与布局断言使用；测试缝在设计阶段就留好。

## 7. 约束（定义/规划/实现都要遵守）

1. **视频区是独立 HWND**（`src/app/GfxWidget.h`）：`WA_NativeWindow` +
   `WA_PaintOnScreen`；Qt 控件叠在画面上会与 D3D11 子窗口冲突。
   控制放画面外；空态/错误态若要居中卡片，需先隐藏 HWND（§11-Q1）。
2. **Qt Widgets + 冷启动**：不引入 QML/Electron（ADR-004）。
   新壳不得增加启动期重活（不预创建菜单、不预加载图标集、不预热对话框）。
   已知反例：T8.9 记录 `QPushButton::setMenu()` 首次绘制阻塞 UI ~620ms，
   现用"点击时建菜单"规避——新壳不许把它改回去。
3. **键位与帧语义是产品契约**（`spec.md` §3.7）：改键位要单独走 spec 版本记录。
4. **测试耦合必须先列清单**（本轮已列，见 §7.1）：重做前确定哪些测试改、
   哪些不能改。
5. **性能路径不能碰**：`GfxWidget` 呈现、`PreviewDecoder`/`DragStrategy`、
   `OnlineSession` 状态机、缓存读写；UI 重做只做壳与视图。
6. **渲染一致性**：所有容器显式 `WA_StyledBackground`；滚动条/滑条/工具提示/
   应用内对话框都要进主题（系统文件对话框可保持原生）。
7. **不伪造**：截屏、对比度、布局数字必须可复现；本轮所有数字均来自
   `build/ui-baseline/` 的真实截屏或 `T6.4 dpi_state` 实测日志。

### 7.2 新骨架的布局底线（规划阶段定稿，实现阶段守）

**令牌预算（逻辑像素）**

| 栏位 | 常规档（客户区高 ≥600） | 紧凑档（<600：200% DPI、窄窗口） |
|---|---|---|
| 顶栏 | 36 | 32 |
| Banner 槽 | 28（仅出现时占位） | 26 |
| Transport | 40（控件高 26–30） | 36 |
| 时间轴 | 112（标尺 48 + 波形 50 + 滚动条 14） | 96（标尺 44 + 波形 40 + 滚动条 12） |
| 状态栏 | 24 | 22 |
| **固定栏合计** | **212** | **186** |

- 视频区吃剩余高度：1280×720 → **508（70.6%）**；1248×624（150%）→ **412（66.0%）**；
  928×452（200%，紧凑档）→ **266（58.9%）**；820×500（窄）→ **314（62.8%）**。
  与 §6.1-M4 的门槛一致；规划阶段可用真实窗口尺寸复核，但不许降低门槛。
- **为什么要预算**：现状把 128px 固定时间轴 + 34–53px InfoBar + 28px 状态栏顶着，
  200% 下画面只剩 53.5%（§1.4）。新壳多了顶栏与 Transport，若不压栏位会**更糟**，
  所以"紧凑档"是硬要求，不是优化项。
- 视频区宽度下限沿用现状 `gfx ≥320×120`；时间轴可在 96–160 间收缩，
  但不低于标尺可读高度；Inspector 展开 300 / 折叠 44、240–300 响应式（沿用现值），
  只影响宽度。
- 全屏：隐藏顶栏/Inspector/状态栏，保留精简 Transport；**不做**淡出/自动隐藏动画
  （见 §11-Q6）。
- 状态栏最多 1 条主动消息 + 3 个次级指标。

### 9.2 采集方法与坑（复现必读）

- `--dpi-test` 的截图/断言**必须带 `--file`**：所有 GUI 测试定时器都挂在
  `if (!file_path.isEmpty() && ...)` 分支内（`src/app/main.cpp:1853`），
  不带文件时进程不退出、不截图。
- 截图写到 `<cwd>/build/t6.4-dpi-<tag>-<phase>.png`；**父目录不存在会静默 `save=false`**，
  需先创建。
- **`PrintWindow` 在有活动 D3D11 交换链时会挂起**（本轮实测，需强制结束进程）；
  抓真实画面要用屏幕区域抓取（`Graphics.CopyFromScreen`）并保证窗口在前台。
- `QWidget::grab()` **抓不到视频画面**（独立 HWND），只适合布局/颜色/文字评审。
- `fullscreen` 相位不稳：`dpi100`（20 标记样本）与 `dpi200` 两轮
  `IsFullScreenForTest()=0` 且截图与 normal 同 SHA256；但同样 100% 的
  `clean100` 一轮通过（fullscreen 1920×1080）→ 判定为窗口激活/切换时序 flake，
  **不是布局结论**。这两张不能当全屏证据，需在规划阶段重跑；
  125%/150% 的 fullscreen 有效。
- 进程是 Low integrity（工作区直接启动）：写 `%APPDATA%` 会失败，空态截图里出现的
  红色"在线缓存目录不可用"就是这么来的。**基线截屏要在 3A 之前用 Medium 副本重拍**
  （`%LOCALAPPDATA%\Programs\拉片软件\lapian.exe`），否则错误横幅是环境噪声。

## 11. 待决问题（规划阶段必须给结论）

- **Q1 空态是否隐藏 `GfxWidget`？** 建议：隐藏，用 Qt 占位卡片；需先测 P1/P2 影响。
- **Q2 Inspector 默认展开还是折叠？** 建议：有媒体且有标记时展开，空态折叠为 44px 条。
- **Q3 系统标题栏保留？** 骨架已排除无边框，建议**保留**（换取贴边/最大化/DPI 行为，
  避免自绘命中测试）。
- **Q4 横幅槽位置？** 建议顶栏下方全宽（推下视频区），而不是视频区内部（HWND 约束）。
- **Q5 帧号输入形态？** 建议 Transport 中央的帧号本身可点击编辑（保留 `Ctrl+G` 对话框）。
- **Q6 全屏是否保留 Transport？** 建议保留精简 Transport，不做 3 秒淡出（避免定时器/透明度）。
- **Q7 波形配色强度？** 现状 `#7aa2f7` 满饱和、视觉压过画面；建议降饱和并加 30% 透明度。
- **Q8 状态栏放哪些次级指标？** 现状 9 个 permanent widget；建议压到 3 个（音频/在线状态/波形）+
  1 条消息；速度/循环/音量移到 Transport。
- **Q9 是否保留 `InfoBar` 组件？** 建议**拆掉**：文件名/规格进顶栏，帧号/时间码进 Transport，
  提示进 banner 槽。保留它会继续诱导"一个控件装三类信息"。
- **Q10 新壳开关形态？** `--ui-v2` 环境变量 vs 设置项；建议先 `--ui-v2`（对测试友好），
  旧壳在 3D 收口后删除。
- **Q11 设计令牌落地？** 建议 `Theme` 单例 + 单个 `.qss` 模板（`QString::arg` 注入令牌），
  不引入第三方主题库。
