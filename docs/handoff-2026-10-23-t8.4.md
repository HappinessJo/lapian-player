## 2. 接口（给 T8.5 / T8.6 / T8.10）

```cpp
namespace lapian::online {

class GrowingSource {
 public:
  explicit GrowingSource(std::int64_t total_size);   // <=0 → IsValid()==false
  bool IsValid() const; QString InvalidReason() const;
  std::int64_t Size() const;                         // 已知总字节
  std::int64_t Published() const;                    // 已发布连续前缀（MVP 无空洞）
  GrowingWaitResult WaitFor(std::int64_t offset);
  GrowingWaitResult WaitForTimeout(std::int64_t offset, std::int64_t timeout_ms);
  void Publish(std::int64_t published_bytes);        // 写盘后调用；单调；clamp 到 Size()
  void Fail(int av_error);                           // 0 → EIO
  void Cancel();
  bool IsCancelled() const; bool HasFailed() const; int ErrorCode() const;
  GrowingSourceStats Stats() const;
};

class GrowingCursor {
 public:
  static std::unique_ptr<GrowingCursor> Open(std::shared_ptr<GrowingSource>,
                                             const QString& part_path, QString* error);
  AVIOContext* avio() const; std::int64_t Pos() const;
  int Read(std::uint8_t*, int);
  std::int64_t Seek(std::int64_t, int);
  void SetWaitTimeoutMs(int);   // 仅诊断；产品 0=无限
  GrowingCursorStats Stats() const;
  void Close();
};

class GrowingFormat {
 public:
  bool Open(std::shared_ptr<GrowingSource>, const QString& part_path, QString* error);
  void Close();
  AVFormatContext* context() const;
  GrowingCursor* cursor() const;
};

QString AvErrorText(int av_error);
}
```

语义（详见证据 §3）：

- 读未发布区阻塞；`Cancel` → `AVERROR_EXIT`；`Fail` → `AVERROR(EIO)`（**绝不能 EOF**）；`pos>=Size` → `AVERROR_EOF`；失败后已发布前缀仍可读。
- seek 只改 `pos`，不触发网络；`AVSEEK_SIZE` 返回 `Size()`；越界 `AVERROR(EINVAL)`（不静默 clamp）。
- `GrowingFormat` 的 `pb` 不交给 FFmpeg 释放；`GrowingCursor` 析构时 `av_freep(&avio->buffer)` + `avio_context_free` + `CloseHandle`。
- 每读者独立 `AVIOContext`/文件句柄；`GrowingSource` 只共享范围/条件变量/统计。
- 锁顺序 `OnlineSession → CacheStore → GrowingSource`；读层不回调 `CacheStore`，`CacheStore` 不回调读层。

## 4. 关键决定与解释

1. **每读者独立 AVIO + 句柄，共享 `GrowingSource`**：多个解码/索引/波形线程共用同一 `.part` 时，绝不能共用一个 `AVIOContext`（会互踩 `pos`）。T8.4 用 `GrowingCursor` 把 `pos`+句柄+64KB 缓冲封装成一个 reader；`GrowingFormat` 再包 `AVFormatContext`。
2. **失败映射 EIO，不映射 EOF**：FFmpeg 把“读不到”当文件结束会生成半截索引，后续 seek 全错。`Fail()` 后等待中的读返回 `AVERROR(EIO)`；`pos>=Size` 才 EOF。
3. **取消是终态 + notify_all**：`Cancel()` 置位并唤醒；读回调在入口与等待返回后都检查取消；`Publish` 在取消/失败后不再推进。取消延迟实测 ≤0.3ms。
4. **seek 不 clamp**：`avio_seek()` 会把 callback 返回值当成“已到请求位置”；如果 callback 把越界目标 clamp 到 `Size()` 却返回 `Size()`，AVIOContext 的 `pos` 会与真实文件偏移不一致。T8.4 对越界返回 `AVERROR(EINVAL)`。
5. **`AVSEEK_SIZE` 必须返回 `Size()`**：否则 FFmpeg 认为不可 seek，帧精确退化。`avio_size()` 走的就是这个回调。
6. **publisher 先写盘再 `Publish`**：`GrowingCursor::Open` 检查 `Published <= 文件长度`；探针 publisher 每次写后 `GetFileSizeEx` 对账，`OverFileViolations=0`。`Published` 不得超前文件长度。
7. **`FILE_SHARE_DELETE` 故意不加**：reader 句柄不带 delete，`CacheStore::EvictToQuota` 才能识别“正被读取”并返回 busy + `evict_pending`；加了会误删正在读的文件。
8. **读层不碰 `CacheStore`**：`GrowingSource` 只认路径与 `Size()`；`CacheStore` 仍是唯一知道缓存目录/meta/配额的地方。T8.5 负责 `Reserve→OpenPart→写→Publish→MarkComplete`，锁顺序不反转。
9. **不在读层建线程**：等待由解码/索引/波形线程驱动；read 回调只阻塞调用线程。UI 线程绝不调用 `Read`/`WaitFor`（T8.6 约束）。
10. **探针用 fake publisher 而非 HTTP**：T8.4 DoD 是读层语义；用真实 `CacheStore` 临时根 + 本地 faststart 样本 + 固定速率写 `.part`，可重复、离线、不依赖 CDN。10min 版把发布速率压到约 62KB/s，确保 4 读者真的在未缓存区等待。
11. **`avio_context_free` 不释放 buffer**：FFmpeg 7.1 的 `avio_context_free` 只释放 `AVIOContext`；buffer 必须先 `av_freep(&avio->buffer)`（文档明确“must be later freed with av_free”）。
12. **诊断超时只用于压测**：`SetWaitTimeoutMs` 在 4 读者压测里用 20s 看门狗把“丢唤醒/死锁”变成可断言的 `TimedOut`；产品读路径仍无限等待，靠 `Cancel` 退出。

## 5. 已知缺口

1. **没有真实 HTTP / T8.5**：假 publisher 只模拟“顺序写 + 发布”；Range 起点、服务端忽略 Range、CDN 限速、断网/重试/备份 URL/URL 过期未测。
2. **没有 `MediaSession`/UI（T8.6）**：`GrowingFormat` 只是打开器；SeekEngine/PreviewDecoder/Index/Waveform 尚未接 `GrowingSource`，缓冲 UI/SeekWait/自动恢复未做。
3. **0.3MB 只对当前 faststart 1080p 样本**：moov 更大的文件阈值更高；非 faststart 样本不适用。样本在 `build/`，不入库。
4. **4 读者是 demux（不接解码器）**：真实 v1 的 4 类读者（ExactDecoder/PreviewDecoder/Index/Waveform）+ D3D11/帧缓存并发留给 T8.6。
5. **取消/等待延迟是本机数字**：未做高负载/杀软/慢盘注入；10min 版 close 见证据。取消瞬间 reader 可能正在 frontier 读一个 67KB 大包，mov/h264 各打印 1 条 `Packet corrupt`（`AVERROR_EXIT` 路径），不是数据损坏；`stress_errors=0`、同源 ffmpeg 解码 0 警告。
6. **内存只采 WS**：无 2h soak/句柄泄漏专项；4 读者上限由调用方控制。
7. **4GiB−1 只做稀疏文件算术/seek**：没有真实 4GB 连续读写/磁盘吞吐。
8. **ADR-007 回填**：附条件接受要求“T8.2/T8.4 通过后回填评审记录”；T8.2/T8.4 均已完成，但本任务按边界未改 ADR 正文；建议下一次文档同步在 ADR-007 评审记录里回填“T8.2/T8.4 已通过”。D1–D5 不变。

## 6. T8.5 / T8.6 / T8.2.2 需要什么

### T8.5（durl 取流，直接消费者）

- `CacheStore::Reserve(total)` → `OpenPart()` → 写 `.part`（顺序）→ **每次 WriteFile 后** `GrowingSource::Publish(written)`；每 1–2s `UpdateProgress(n,false)`。
- `total_bytes` 必须已知（playurl size 或 HEAD Content-Length）；未知时不要进可增长播放（`GrowingSource` 会拒绝）。
- HTTP 失败/磁盘满/取消：`source->Fail(AVERROR(EXDEV/ENOSPC/EIO))` 或 `Cancel()`；读层会把等待中的读映射为 EIO/EXIT。
- 完成：**关闭写句柄** → 长度校验 → `MarkComplete`；读层只读句柄可在 MarkComplete 前关闭（reader 先 `Cancel` + join）。
- 读层不提供 HTTP/重试/备份 URL/URL 过期，T8.5 自己实现；`Publish` 必须在写盘之后，建议每次写后 `GetFileSizeEx` 对账（探针同款）。
- 真实并发：T8.6 的多读者会同时 `OpenPart`（各自句柄），T8.5 不要持有 reader 的句柄或 `CacheStore` 锁去等解码。

### T8.6（会话/UI，入口已在）

- `MediaSession` 增加“从 `GrowingSource` 打开”的最小入口：用 `GrowingFormat`（或 `GrowingCursor`+`AVIOContext`）替换本地 `avformat_open_input`；**本地路径分支不变**。
- `Cancel` 按 generation：新 seek/关窗先 `source->Cancel()`，旧等待 `<100ms` 退出；不要用旧帧覆盖新目标。
- UI 线程不 `WaitFor`/`Read`；缓冲提示/等待估算来自 `Stats()`（等待次数/累计等待/发布速率）+ `Published()/Size()`；`WaitForTimeout` 只用于诊断。
- 4 读者（Exact/Preview/Index/Waveform）各自 `GrowingCursor`；`AVIOContext` 不可共享。
- 关窗：`Cancel` → join 解码/索引/波形 → 关 reader → 关 `GrowingSource`；实测短版 close 3ms。
- 已缓存 P7 仍按 v1 路径；未缓存不承诺 80ms。

### T8.2.2（扫码，非门）

- 与读层无关；按计划排在 T8.4 之后、可与 T8.5 并行。T8.4 未新增网络/依赖，不影响扫码。
