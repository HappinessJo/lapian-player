## 6. 本机已知坑（都已在脚本/文档里处理，别重复踩）

1. PowerShell 5.1 按 ANSI 读 `.ps1`：**必须 UTF-8 带 BOM**；编辑脚本后要重加 BOM。
2. 执行策略：用 `-ExecutionPolicy Bypass` 或进程级 `Set-ExecutionPolicy -Scope Process Bypass`。
3. CMake 4.2.0 在 configure 崩溃；CMake 3.31 读取已有 `CMakeCache.txt` 重配也崩溃 → 脚本配置前删缓存（保留增量编译）。
4. CMake FetchContent 捕获 `git` 子进程管道会崩溃 → **不引入 FetchContent**；依赖都用脚本预取。Catch2 因此推迟到 T1.1。
5. Python 3.14 的 `tempfile.mkdtemp` 建目录后本人不可写 → `scripts\python\sitecustomize.py` 改 0o777（构建期）。
6. aqt 需要命名管道与 `%APPDATA%\aqt` → 用工作区 APPDATA 重定向，且在完全权限下运行。
7. `windeployqt` 会多带 QtNetwork/TLS/网络插件与 D3dcompiler_47 → 构建脚本删除，`check-imports.ps1` 断言。
8. FFmpeg+MSVC 构建：用 `bash -c`（不是 `-lc`）、先改名 MSYS2 的 `link.exe`、显式 `--enable-d3d11va`、改 `config.h` 的 `CC_IDENT`（中文会让 RC 报 RC2001）、`.lib` 从 `bin/` 归位到 `lib/`、**改组件集必须 `make clean`**、**必须同时启用 d3d11va2**（否则 `Invalid pixfmt for hwaccel`）。
9. GUI 子进程会继承命令 stdout 管道导致挂起 → 启动应用/测量时显式重定向 stdout/stderr。
10. 探针进程在本机写 `docs\` 会 EACCES（cmd/python 正常）→ `seek-probe.ps1` 先写 `build\seek-tmp` 再拷回证据目录。

## 7. 未决问题（需要用户拍板）

1. **P6/P7 口径**：长 GOP 下随机 seek 的物理成本已超预算。可选：
   - 限制保证档 GOP（例如关键帧间隔 ≤2s），超出归可用档；
   - 放宽 P7/P6，拆分“±1 步进（缓存）”与“随机距离步进”；
   - 帧缓存/预取（只能解决 ±N 内的步进）；
   - 组合（推荐：限制 GOP + 缓存）。
2. **素材**：`media\` 目前只有合成的 `V9.mp4` 与 `proxy\proxy-V1/V3/V4.mp4`；正式 T0.3 需要真实 V1/V3/V4（至少），完整验收需要 V1–V10。命名见 `docs/media.md`。
3. 顺带指出：P7（随机单步 ≤80ms）比 P9（输入跳转 ≤200ms）更严，但两者是同一次随机 seek；决策时应一并处理。
