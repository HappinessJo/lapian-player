## 2. 接口（给后续）

```cpp
namespace lapian::online {

QString BuildQrGenerateUrl();
QString BuildQrPollUrl(const QString& qrcode_key);
QrGenerateResult ParseQrGenerateJson(const QByteArray& body);
QrPollResult ParseQrPollJson(const QByteArray& body,
                             const QString& sessdata_from_cookie = {});

class QrLoginSession {  // 纯单线程状态机
  bool Start(); bool OnGenerated(const QrGenerateResult&);
  bool OnPolled(const QrPollResult&); bool OnVerified(bool nav_ok, const QString&);
  bool Expire(); bool Cancel(); bool Fail(const QString&); void Reset();
  QrLoginState state() const; QString message() const;
  QString qrcodeKey() const; QString qrUrl() const; QString sessdata() const;
};

class QrLoginController : public QObject {  // UI 线程；worker 做 HTTP/nav
  void Start(); void Refresh(); void Cancel(); void Close();
  QrLoginState state() const; QString message() const; QImage qrImage() const;
  AuthResult authResult() const;
 signals:
  void stateChanged(int state, const QString& message);
  void qrImageChanged(const QImage& image);
  void loginSucceeded(); void loginFailed(const QString& message);
};
}
```

约定：

- `passport.bilibili.com` 只用于 QR generate/poll；QR 请求**不带** SESSDATA；CDN 不带 Cookie。
- 成功 SESSDATA 可来自 `data.url` 查询参数或 `Set-Cookie`；只保留 SESSDATA，其它字段丢弃。
- `verifying` 是内部态：poll 成功还不算已登录；nav `code=0/isLogin=true` 且 DPAPI 保存成功才是 `success`。
- 控制器 `Cancel()` 置 token 后 join，实测 **16ms/0ms**（≤100ms）；`Close()` 在成功时保留登录，未成功时取消。
- 180s 从 generate 成功起算；过期停 poll，刷新重新 generate，旧 key 丢弃。
- `OnlineResolveDialog` 粘贴入口与扫码入口并存；扫码失败/过期/取消只影响二维码面板，不清除已有粘贴凭据。

## 4. 关键决定与解释

1. **QR 请求匿名**：generate/poll 不带 SESSDATA，符合 §6.1 白名单；`HttpResponse::response_sessdata` 只在 passport 响应上提取，避免通用 Cookie API 扩大暴露面。
2. **成功只留 SESSDATA**：`data.url` 和 Set-Cookie 都可能含多参数；解析后只 `NormalizeSessdata` 一项，其它字段直接丢弃。DPAPI 文件格式不变。
3. **nav 通过才保存/显示**：poll 成功先进入 `verifying`；worker 里 `CheckNav` 通过后才 `CredentialStore::Save`，失败不保存、不显示已登录，提示回退粘贴。比“先保存再 nav”更安全，且满足“nav 通过才已登录”。
4. **本地二维码渲染**：Nayuki MIT 单文件/对；无 QtNetwork/WebEngine/新 DLL；不加载远程资源；`check-imports` 不变。
5. **UI 线程不阻塞**：HTTP 在 worker；结果 queued 回 UI；QTimer 1.5s 只在 waiting/scanned 触发；取消置 token 后 join，实测 16ms。
6. **过期/刷新**：180s 从 generate 成功起算；过期停 poll、清 key/URL/image；刷新重新 generate；旧 key 丢弃。
7. **两入口并存**：粘贴入口永久保留；扫码失败/过期/取消提示“仍可用上方粘贴 SESSDATA”；保存/清除粘贴凭据会先取消进行中的扫码。
8. **关闭行为**：扫码成功保留凭据；未成功取消并 join；不在关窗时弹错误。
9. **`--ui` 不显示窗口**：构造真实 `OnlineResolveDialog`，不 `show()`；在 build/dist 都用默认 Windows platform 通过（dist 只有 qwindows 插件，不再强制 offscreen）。
10. **真实接口先实测**：generate 字段 `url`/`qrcode_key`、poll `data.code=86101`、成功 cookie 位置以官方为准；未知结构 → 可读失败 + 粘贴回退。

5. **UI smoke 覆盖有限**：扫码成功/状态/凭据/面板；未自动覆盖 DPI/全屏/粘贴焦点隔离（沿用既有 UI 测试/人工）。

7. **无账号体系/多账号**：按边界不做。
