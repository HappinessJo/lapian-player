## 1. 完成到哪

DP-2 给本地拖动预览加了三层：

1. **有界精确缓存**：保留 32 帧热缓存（DP-1 容量不变），新增
   `PreviewRingCache`（软件 NV12，默认 192MiB，LRU/窗口）。`Begin/
   UpdateTarget` 在 UI 线程先查缓存，命中直接发布；不再等 worker seek。
2. **预取**：独立低优先级软件解码线程，慢速局部反向时解“上一 GOP”的
   1280 NV12 入缓存；目标跨 GOP/换会话/松手时取消。worker 空闲也有
   1–2 帧兜底预取。
3. **远跳粗帧**：新增 `PreviewThumbnailCache`（320×180，默认 64MiB）与
   远跳触发；软件用关键帧缩略图，硬件用刚解出的关键帧全分辨率 clone
   （零回拷、不占表面池）；粗帧带 `coarse` 标记，精确帧随后替换。

关键文件：

- `src/media/PreviewRingCache.h/.cpp`：两个有界缓存（精确环 + 粗帧/缩略图）。
- `src/media/PreviewDecoder.h/.cpp`：缓存查询、反向粗帧、预取线程、缩略图
  线程、硬件关键帧粗帧、`PreviewFrame.coarse/from_cache/hardware`、诊断。
- `src/media/FrameIndex.h/.cpp`：`KeyframeAtOrBeforeFrame`/`PreviousKeyframe`/
  `NextKeyframe`。
- `src/app/MainWindow.*`：`PreviewTestDiagnostics` 扩展、显示帧 coarse/
  from_cache 记录。
- `src/app/DragTestRunner.*`：`--drag-fast` 输出缓存/粗帧/预取/分段耗时，
  新增 `--drag-far-test`、`--drag-fast-cycles`。
- `tests/preview_cache_test.cpp`：预算/LRU/窗口/最近关键帧单测。

## 2. 关键实现点（不要改坏）

1. **硬件帧仍不缓存**：目标路径不做 `av_hwframe_transfer_data`。实测
   1080p 回拷+缩放 4–15ms/帧，放进 `-20` 会把 47fps 拖到 33fps、
   空档 70ms；也会增加 D3D11 锁持有。硬件远跳粗帧直接用
   `av_frame_clone` 关键帧（`coarse=true, hardware=true`），渲染上传后释放。
2. **缓存预算**：热缓存 32 帧（≤48MiB 字节上限）+ 环缓存 192MiB +
   缩略图 64MiB；`cache_peak_bytes` 实测 244,684,800B（233.4MiB）。
   环缓存至少保留 32 帧，LRU 从尾部淘汰；`Begin` ±1800 帧裁剪，
   `End` 收到 32MiB，缩略图 End 收到 16MiB。不要改成无界。
3. **命中率口径**：`cache_hits / (cache_hits + cache_misses)`，分母是每次
   `Begin/UpdateTarget` 的精确目标查询；同一目标重复调用 early-return。
   粗帧命中 `coarse_*` 单独统计，不混入精确命中率。
4. **粗帧单调约束**：`TakeLatestFrame` 中反向粗帧必须比上一张已显示帧更早；
   正向粗帧不能比上一张更早；粗帧索引必须 ≤ 当前目标。不满足就丢弃，
   不能用“向前跳”换 fps。
5. **远跳阈值**：目标一次跳 ≥300 帧才先发粗帧。普通 +60/-60 不走粗帧
   （硬件已 60–69fps；软件粗帧追不上目标）。正向远跳会抑制中间精确帧，
   只发关键帧粗帧 + 精确目标，保证“先粗后精”。
6. **预取隔离**：预取线程用独立软件解码器/读层，不碰主播放/预览硬解
   D3D11 上下文；只写缓存、不发布；每次 decode 前检查 generation/session/
   目标 GOP，取消后 `position_valid=false`，下个目标重新 seek。
7. **Begin/End 缓存生命周期**：`Begin` 不清空缓存（跨拖动命中），只按目标
   ±1800 帧裁剪；`End` 不 join 线程，只停请求并收窄预算；`Close` 才 join
   并清空。设备丢失重建走 `Close+Configure`，缓存清空是预期。
8. **粗帧/精确帧区分**：`PreviewFrame.coarse`、`from_cache`、`hardware`
   三个 bool；MainWindow 记录 `displayed_coarse/from_cache`；探针可区分
   精确帧、粗帧、缓存命中、硬件帧。松手 `GoToFrame` 不改。

## 4. 残余/下一步

1. **强制软件快反向 `-20/-60` 未达 25/45fps**：1080p 软件解码 5–8ms/帧，
   目标 15.6ms 后退 20–60 帧，精确路径物理追不上；粗帧也常因目标已经
   更早而变成“未来帧”被正确丢弃。已在证据中如实记录，不写成通过。
2. **DP-3**：快拖/慢拖/远跳策略与 `target_lag` 门；DP-2 已提供
   `coarse/from_cache/hardware`、`cache_hit_rate`、`first_coarse_ms`、
   `cache_bytes/peak`、分段耗时等诊断。
3. **DP-4**：全量回归/dist/Medium 副本/证据；本提交未重建 dist。
4. 4K 硬解仍关闭；4K/HEVC 只记录。
5. 连续拖动跨 `End` 的命中率低于单轮（End 收窄到 32MiB）；若 DP-3 需要
   更高跨拖动命中率，可评估放宽 idle 预算，但不得突破 256/64MiB。

## 5. 不要做

- 不要把粗帧标成精确帧，或让粗帧向前跳；松手必须精确。
