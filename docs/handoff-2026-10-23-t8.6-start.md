## 2. 硬缺口（T8.6 的主要工作，不是简单接线）

### 2.1 `MediaSession`/解码器只接受路径

- `MediaSession::Open(const std::string& utf8_path, ...)` → `ProbeMedia(path)` → `VideoDecoder::OpenWithD3D11Device(path, ...)`；两者内部各自 `avformat_open_input(path)`。
- `AudioDecoder::Open(path)`、`WaveformGenerator::Start(path)`、`PreviewDecoder`/`FrameIndex::BuildFromFile(path)` 同样按路径打开。
- `GrowingFormat` 已经能打开自定义 AVIO 的 `AVFormatContext`，但**目前没有消费者**；T8.4 只在探针里用。
- 直接传 `.part` 路径不可行：FFmpeg 读到当前文件末尾会 EOF，未发布区不会阻塞；会把“还在下载”误判成文件结束/损坏。

### 2.2 没有部分索引

- `FrameIndex::BuildFromFile` 全文件 demux；`FrameIndex` 没有“只覆盖已下载前缀”的状态。
- 在线首帧可以无索引；但 `PgUp/PgDn`/seek/`MediaSession::SeekToFrame` 依赖 `index_.IsReady() && !empty()`。
- 不能在 UI 里等整片下完再建索引；也不能把部分索引的“当前帧数”冒充全片总帧数。

### 2.3 UI 线程不能阻塞

- `GrowingCursor::Read` 在未发布区阻塞；`MediaSession::SeekToFrame` 可能触发这种读。
- T8.6 要求“UI 停顿 >200ms = 0”；未缓存 seek 要 ≤100ms 显示“缓冲中”，不能在 UI 线程等网络。
- v1 的 `PlaybackController`/`MediaSession` 目前都在 UI 线程；直接调用在线 seek 会把 UI 冻住。

### 2.4 完成改名与 reader

- `DownloadJob::FinishCompleted()` 在写完后立刻 `MarkComplete`（`.part`→`.mp4`）。
- `GrowingCursor` 的读句柄**不带 `FILE_SHARE_DELETE`**（T8.4 的淘汰保护）；reader 还开着时 rename 会失败，Job 会 `Fail(EIO)`，源也会 `Fail`，正在播的画面会断。
- T8.5 探针在完成前关闭 reader；T8.6 必须设计“完成前停 reader / 延迟 MarkComplete / rename 失败重试”的机制，不能假设 rename 一定成功。

### 2.5 音频/波形也是路径打开

- `AudioDecoder::Open(path)`、`WaveformGenerator::Start(path)` 各自打开文件；在线 M1 durl 是带音轨的 MP4，不能只做视频。
- `WaveformGenerator` 是一次性全文件生成；在线需要“已缓存前缀渐进”，不能阻塞 UI，也不能每 100ms 重扫全片。

### 2.6 标记/截图/会话标识

- `MarkStore`/`SnapshotService` 目前围绕本地路径；在线需要 `lapian-online-1` 类标识（T8.7 完整记录）。
- T8.6 E2E 要求 `Ctrl+M`、`S` 能工作；至少先做**会话内**可用，完整持久化/目录/清单留 T8.7，并在证据写清边界。

## 3. 推荐架构（先 spike 再决定）

### 方案 A（推荐）：把 `AVFormatContext` 注入现有媒体层

不要用 `.part` 路径，也不要先下完再打开。

1. **探测**
   - 从 `MediaProbe` 抽出 `ProbeFormat(AVFormatContext*, ...)`（非拥有；复用现有 `MediaInfo`/VFR/display matrix 解析）。
   - `MediaSession::OpenGrowing(std::shared_ptr<GrowingSource>, const QString& part_path, ID3D11Device*, std::string* error, ...)`：
     - 用 `GrowingFormat::Open(source, part_path, ...)` 得到 context；
     - `ProbeFormat(context)`；
     - 用同一 context 开 `VideoDecoder::OpenWithFormat(context, stream_index, ...)`（非拥有，禁止 decoder 关闭 context）；
     - 解首帧；`MediaSession` 持有 `GrowingFormat`/`GrowingSource`，保证生命周期长于 decoder。
2. **音频/波形**
   - `AudioDecoder::OpenWithFormat(AVFormatContext*, stream_index, ...)`（非拥有）；
   - `WaveformGenerator::StartWithFormat(...)`，或独立 `GrowingFormat`/cursor 读同一 source；
   - 每个 FFmpeg context 一个线程/一个 cursor；不要共享 cursor。
3. **索引**
   - 给 `FrameIndex` 增加“从 `AVFormatContext` 建/从已有条目建”的入口；后台 worker 读**已发布前缀**，建部分索引；
   - 下载增长时增量/周期重建；UI 显示“扫描中/已缓存 N 帧”，不要显示假总帧数；
   - 已缓存区 `SeekToFrame` 走 v1 精确路径；目标超出索引/前缀 → `SeekingWait`，取消旧 generation。
4. **完成**
   - 给 `DownloadJob` 增加**可选**延迟完成钩子（默认关闭，T8.5 探针不变）：写完/关写句柄/`Publish(total)` 后进入 `kAwaitingFinalize`，由 `OnlineSession` 在 UI 线程停 reader 后调用 `FinalizeComplete()`（内部仍走 `CacheStore::MarkComplete`）；
   - 不能用“rename 失败后重试”掩盖 reader 未停；也不能改 `CacheStore` 写语义。
   - 如果不想改 `DownloadJob`，必须证明“完成前 reader 已关闭”的时序；否则会踩 rename busy。

### 方案 B（备选，不推荐先做）：FFmpeg 自定义协议

注册 `lapianpart:` 协议，把 source id 映射到 `GrowingCursor`，让现有 path API 直接打开。优点是少改 `MediaSession`；缺点是全局注册/生命周期/清理/测试隔离风险，且 `AudioDecoder`/`WaveformGenerator` 仍要处理。只有 A 被证伪时才考虑。

### 方案 C（拒绝）

先下完整片再 `MediaSession::Open(path)`：违背 5s 起播/0.3MB 首帧，T8.6 不接受。

## 4. 线程模型：先量，再定

推荐先做两个 spike：

1. **首帧 spike（无 UI）**
   - `.part` 下载到 `Published >= 307200`；
   - 在**同一个线程**调 `GrowingFormat::Open` + `ProbeFormat` + 首帧；
   - 记录 open/probe/first-frame/实际读取字节/是否阻塞。
   - T8.5 探针实测 0.3MB 后 open 8–9ms、首帧 10–14ms；若这里也能不阻塞，首帧可留在 UI 线程（但仍不能让 UI 等 0.3MB，等待应在后台/定时器）。
2. **未缓存 seek spike**
   - 在 UI 线程调用 `SeekToFrame` 到未发布区，测阻塞时间；
   - 若 >200ms，必须引入媒体 worker/异步 seek，不能硬上。
   - 可选：给 `FrameIndexEntry` 增加 `pos`（packet->pos），用“目标字节已 Published”做前置等待，避免 UI 线程进入阻塞读；这是比“整片等完”更好的折中，但需要索引/字节映射验证。

**硬规则**：UI 线程绝不等待网络/磁盘/`GrowingCursor::Read`；所有结果带 generation，旧结果不能覆盖新目标。

## 5. 建议分阶段（默认仍算一个 T8.6）

### 阶段 1：最小在线闭环（先证明架构）
- 确认 → `FetchPlayUrl` → `DownloadPlan` → `CacheStore` + `GrowingSource` + `DownloadJob`；
- 等 0.3MB → `MediaSession::OpenGrowing` → 首帧；
- 默认暂停；Space 播放/暂停；关窗取消/join；
- **暂不做** seek/PgUp/波形/标记/截图/音频；先让一条 OB-1 真正出画面。
- 通过标准：一条真实 OB-1 首帧 ≤5s、UI 不冻结、关窗 ≤1s、`.part` 保留/续传。

### 阶段 2：导航与缓冲
- 部分索引、已缓存 PgUp/PgDn/seek；未缓存 `SeekingWait` + 取消 + 进度；
- 缓冲耗尽自动暂停/恢复；
- cached P7 p95 ≤80ms；UI 停顿 0。
- 通过标准：3 条 E2E 的“首帧→Space→PgUp/PgDn→seek”通过，或明确记录哪条 blocked。

### 阶段 3：音频/波形/标记/截图
- 音频跟随播放；波形渐进；Ctrl+M；S；
- 完成前 reader/rename；错误提示/重试/关窗；
- 通过标准：完整 E2E 3 条 + 本地回归。

**如果阶段 1 就发现必须重构 `MediaSession`/`PlaybackController` 线程模型，或需要改 4 个以上路径 API：停下来向用户报告，建议拆成 T8.6a/b/c，不要在一个 commit 里硬塞。**

## 7. 已知风险/停止条件

1. `GrowingFormat::Open`/`ProbeFormat` 在 0.3MB 时阻塞超过 200ms → 先停下测阈值，不要加大到“等整片”。
2. 未缓存 seek 在 UI 线程阻塞 >200ms → 停止，改媒体 worker/异步；不要用“网络慢”解释。
3. 部分索引不可靠/帧号漂移 → 不冒充精确；显示“扫描中”，记录限制。
4. 完成 rename 与 reader 冲突 → 先停 reader/延迟 finalize；不要改 `CacheStore` 或 reader 的 `FILE_SHARE_DELETE`。
5. 音频/波形无法在 T8.6 内完成 → 向用户报告，拆阶段；不要静默静音/去掉波形。
6. 需要 DASH/1080P60/4K/扫码/记录才能继续 → 停止；这些不在 T8.6。
7. 真实样本不足/无凭据 → 用离线 fake + 已有 OB 缓存做阶段 1；真实 3 条写 blocked，不伪造。
8. 本地 P1/P2/P7 退化 → 停止；本地路径不能被在线代码改坏。
