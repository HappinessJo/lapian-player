## 1. 完成到哪

DP-3 把“慢拖/快拖/反向/远跳/松手”从隐含行为变成显式策略：

1. **`DragMode` 四模式**（`src/media/DragStrategy.*`，纯函数、可单测）：
   - `Exact`：`step ≤ 4`（含 +1/-1），精确优先，禁止粗帧替换；
   - `Fast`：`step 5..299` 向前，允许中间帧/缓存，允许目标滞后；
   - `Reverse`：`step 5..299` 向后，缓存命中优先，未命中走 DP-2 路径；
   - `FarJump`：`step ≥ 300`（前/后），先粗后精。
   判定输入同时记录方向、距上次目标时间、连续同向次数、速度；
   `reason` 是静态字符串，直接进诊断/探针。
2. **`PreviewDecoder::SetDragMode`**：
   - `Exact` 在 `Begin`/`UpdateTarget`/缩略图线程三处关闭粗帧；切回
     `Exact` 时丢弃尚未呈现的粗帧；
   - `FarJump` 增加“粗帧未呈现时精确帧进 `deferred_exact`，粗帧被
     `TakeLatestFrame` 取走后下一 tick 提升精确帧”的闸门；
   - 通用安全约束：精确目标已呈现后，任何粗帧不得再替换它（修复远跳
     反向落定后缩略图线程把画面拉回目标之前）。
3. **`MainWindow` 策略上下文**：每次目标更新计算 mode/step/interval/
   speed/run，写入 `PreviewTestDiagnostics`；逐帧记录
   `displayed_coarse/from_cache/hardware`；Present 时记录
   `target_lag_frames/ms`。
4. **新探针 `--drag-strategy-test`**：慢拖前/后、快拖 +60/-60、
   反向 -20、远跳前/后、4 个 P6 样本；每个场景输出 mode/step/
   interval/lag/coarse/缓存/硬件/松手/pass，最后 summary。
5. **回归**：`ctest` 37/37、key 77/0、T8.6.1b 35/0；`--drag-test`
   P4/P6/P7/P8/P9 全 pass；4K 只记录。

关键文件：

- `src/media/DragStrategy.h/.cpp`：四模式判定、阈值、名称。
- `src/media/PreviewDecoder.h/.cpp`：模式 gating、FarJump 闸门、
  精确后禁粗帧、逐帧硬件标记、诊断。
- `src/app/MainWindow.h/.cpp`：策略判定调用、诊断字段、逐帧记录。

## 2. 关键实现点（不要改坏）

1. **阈值写死**：`kDragExactMaxStep=4`、`kDragFarJumpStep=300`；后者与
   DP-2 粗帧阈值共用，不能出现第二份 300。改阈值必须同步证据/探针。
2. **Exact 不用粗帧**：三个入口都要挡；只挡其中一个会让缩略图线程把
   更早关键帧插到慢拖精确帧前后。
3. **FarJump 闸门只延迟精确帧，不 sleep、不阻塞 worker**；UI 正常取帧
   时下一 tick 到达。`End/Begin/UpdateTarget/Close` 都会清 `deferred_exact`
   或 `coarse_undelivered`，不能留下跨目标/跨会话的旧精确帧。
4. **精确目标已呈现后禁粗帧**：判据 `last_delivered_frame == target_frame
   && !last_delivered_coarse`；远跳反向尤其需要。不要放宽成“粗帧只要更早
   就允许”，否则画面会退回目标之前。
5. **硬件帧仍不缓存、不逐目标回拷**；粗帧仍是关键帧 clone 或软件
   320×180；`readbacks=0`。不要为了 far 粗帧打开回拷。
6. **缓存预算不变**：热 32 帧（≤48MiB）+ 环 192MiB + 缩略图 64MiB；
   `End` 收窄 32/16MiB；实测峰值 233.4MiB。不要改成无界/全片。
7. **探针节奏**：`--drag-fast` 仍 10ms PreciseTimer；本轮系统计时器粒度
   约 10ms，P4 因此从约 64 升到约 95fps，**不是 DP-3 改 P4**；P4 阈值
   30 不变，不能拿这个数字写“P4 提升通过”。
8. **慢拖门**：`+1/-1` 才是 DP-3 的慢拖门；33ms 节奏 p95=0、15.6ms
   节奏 +1 p95=1/-1 p95=2。`+3` 的 p95=3 是采样效应，不写通过。
9. **4K**：继续 `source_too_large` 软件预览；只记录，不设通过线。

## 4. 残余/下一步

1. **强制软件快反向 `-20/-60` 未达 25/45fps**：与 DP-2 同量级，物理成本；
   DP-3 只做策略/探针，不宣称改善。若要解决需要更低分辨率解码/代理或
   更快缩略图管线，属于另一轮，不在 DP-4。
2. **DP-4**：全量回归、dist 重建、Medium 副本验证、证据/交接；不改门。
3. **4K/HEVC**：仍只记录；不打开 4K 硬解。
4. **跨拖动命中率**：`End` 收窄 32MiB 的 DP-2 语义未改；`-1` 三轮命中
   从 85.5% 降到 47.0% 是预期。若 DP-4 需要更高跨拖动命中率，可评估
   放宽 idle 预算，但不得突破 256/64MiB。
5. **P4 计时器环境**：如果后续会话系统计时器粒度回到 15.6ms，P4 会回到
   约 64fps；不要把两种环境的 P4 直接对比成产品变化。

## 5. 不要做

- 不要把硬件帧塞进缓存或逐目标回拷；不要改 D3D11VA 表面池默认。
- 不要把环缓存/缩略图改成无界；不要超过 256MiB/64MiB。
- 不要让粗帧在精确目标之后替换画面；不要取消 FarJump 闸门。
- 不要在 Exact 模式重新允许粗帧；不要把 +3/15.6ms 写成慢拖通过。
- 不要改 `OnlinePreviewDecoder`/T8.6.1b、M1/M2/P4/P6/P7 数字、OB、schema、
  默认 AVC≤1080p。
- 不要重建 dist（DP-4 做）；不写 4K 通过。
- 不要提交 `build\dp1-test.mp4`、测量日志、缓存/记录目录。
