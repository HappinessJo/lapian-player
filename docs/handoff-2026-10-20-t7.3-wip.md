## 2. 本轮做了什么（已提交 `188c63e`）

### 2.1 `--memory-mode soak`

[`src/app/MemoryTestRunner.*`](../src/app/MemoryTestRunner.cpp)：

- 新增 `soak` 模式：打开文件 → 等异步索引就绪 → 设 A=0/B=last → 开循环 →
  从 0 播放；每隔 `--memory-interval`（默认 30s）采样。
- 新增 `--memory-interval`（秒，最小 1）。
- 采样字段：`WS/private/peak_ws/handles/threads/frame/playing/loop_jumps/
  audio_underruns/waveform/cache_entries/ui_gap_ms`。
- 结束：最后一帧采样后暂停、分析、打印 `T7.3 soak_summary`；通过 exit 0，
  阈值失败 exit 3，打开/设置失败 exit 2。
- UI 心跳 200ms；独立看门狗线程：10s 无心跳记 `soak_watchdog stall_ms`，
  30s 硬卡死打印 `hard_stall` 并 `_Exit(6)`，避免 2h 浸泡挂到外部超时。
- **已修**：原来 30s 链式 `singleShot` 会把 60s 跑成 70s；现在按剩余时长收敛
  （`delay_s = min(interval, seconds - elapsed)`），60s 复测精确 `duration_s=60.0`。

[`src/app/ProcessMemory.*`](../src/app/ProcessMemory.cpp)：

- `ProcessMemorySample` 新增 `thread_count`，用 `Toolhelp32Snapshot(TH32CS_SNAPTHREAD)`
  只统计当前进程线程；快照失败返回 0，不影响 WS/handles 有效性。
- `T7.2 memory` 行追加 `threads=%u`（既有 key=value 字段未变）。

[`src/app/MainWindow.*`](../src/app/MainWindow.cpp)：

- 新增测试 getter：`FrameCacheEntryCountForTest()`、`FrameCacheByteCountForTest()`、
  `AudioStateForTest()`、`AudioUnderrunCountForTest()`、`WaveformStateForTest()`。
- 产品播放路径、T7.1 异步索引、T7.2 缓存策略均未改。

[`src/app/SoakStats.*`](../src/app/SoakStats.cpp)（纯 C++，新增 `lapian_soak` 库）：

- 稳态窗口（默认 2h 去前 60s；短时探针取 10%，最小 5s，最大 60s）。
- 最小二乘 WS 斜率（MB/h）+ 绝对增量；只有斜率 >16MB/h **且**增量 ≥16MB 才判增长
  （避免一次性堆/解码器高水位误报）。
- 句柄增长 >64、线程增长 >2、缓存条目非空（含 warmup 前）、播放中断、帧号连续
  两个采样窗口不变、UI 心跳 >2000ms、WS >1200MB 都判失败。
- 音频 underrun 只记录，不判失败（设备恢复另列，归 T7.5/T7.7）。

[`scripts/soak-bench.ps1`](../scripts/soak-bench.ps1)：

- 驱动 2h/短时 soak；默认 7200s/30s，外部超时 `Seconds+600s`。
- 路径含中文/空白时自动建 ASCII 硬链接，规避 PowerShell 5.1 `Start-Process`
  的 ANSI 参数转码。
- **注意**：脚本是 UTF-8 **带 BOM**；Windows PowerShell 5.1 无 BOM 会把中文
  注释误解析成语法错误（本轮已踩过）。
