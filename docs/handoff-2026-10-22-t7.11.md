## 2. 本轮做了什么

### 2.1 合成 V10 2h soak 收口

- 命令：`scripts\soak-bench.ps1 -File media\synthetic-suite\V10.mp4 -Seconds 7200 -Interval 30 -Tag v10-synth -NoLoop`
- 日志：`build/soak/v10-synth-20261022-193018.log`；19:30:18 启动，21:30:27 结束。
- summary：`pass=1`、`flags=none`、`duration_s=7200`、`samples=242`、
  `ws_start=162.4`、`ws_final=164.8`、`ws_max=166.1`、`growth=2.4`、
  `baseline_slope=0.16MB/h`、`handles=691/675/712`、`threads=56/50/61`、
  `frame_stall_events=0`、`playback_stopped_events=0`、`audio_underruns=0`、
  `cache_max=0`、`ui_gap_max_ms=212`。
- 一条启动时 `[h264] missing picture in access unit with size 692`（拼接边界），
  之后播放到末帧 172626，无其他错误。
- 结论：**合成 V10 替身 P14 稳定性通过**；不写正式 V10/P14 通过。

### 2.2 V1–V9 合成冒烟（soak 后串行）

- V1/V2/V4/V5/V6/V7：打开 + 异步索引 ready；帧数 8657/4573/450/899/17263/4559；
  V5 的 `total=1`（扫描中）是 VFR 设计口径。
- V1：A/B 循环、101 标记重开、3 张截图 + 旋转 B、A=B 定帧路径全过。
- V4：4K 截图 3840×2160 + 旋转 1080×1920，3 连拍 save p95 209ms。
- V3：HEVC60 `hw=1`，P4 61.9fps、P6 1.8ms、P7 0.0/0.2ms、P8 13.1fps 26/26、
  P9 8.3ms；软解 5 步 exit 0（不作性能结论）。
- V5/V7：VFR 横幅与“无音频”横幅通过，4K/10-bit 提示无失败。
- V8：5/5 弹出“打开失败”对话框，0.31–0.35s；10s 是 `--startup-test`

- V9：`lapian_audio_test` 通过，click 峰值在视频第 100 帧 ±1 帧内。

### 2.3 P7 跨 GOP 边界后退专项

新增 `--gop-boundary-test`：目标帧取 GOP 第一个关键帧 K，`GoToFrame(K)` 后
计时一次 PgUp 到 K-1；`LAPIAN_SEEK_LOG=1` 证明每个 PgUp 都是
`hit=0 decoded=GOP 帧数`，不是缓存命中或 T7.9 handoff。

| 样本 | GOP | p95 | 阈值 | 结果 |
|---|---|---:|---:|---|
| `build/test-media/real-gop2s-full.mp4` 1080p | 60 帧 = 2.0s | **145.60ms** | 80ms | **未通过** |
| `media/synthetic-suite/V2.mp4` 1080p | 30 帧 = 1.0s | **92.65ms** | 80ms | **未通过**（收紧档仍超） |
| `media/proxy/proxy-V1.mp4` 1080p | 250 帧 ≈ 10.4s | 340.78ms | 无 | 长 GOP 单列 |
| `media/proxy/proxy-V4.mp4` 4K | 60 帧 = 2.0s | 451.53ms | 150ms（诊断） | 超 4K 档 |

分项（seek log）：2s GOP `seek 0.25ms + decode 36–42ms + cache 94–105ms`；
1s GOP `seek 0.13ms + decode 12–14ms + cache 76–78ms`。**缓存回拷是主因**；
不含回拷的 seek+解码约 31–48ms（2s）/12–23ms（1s），本来在 80ms 内。
这与 T7.8 的 step max（1080p 129.82ms、4K 421.92ms）是同一现象。

## 3. 口径 / 不宣称

- **不是 T7.7**：真实 V1–V10、F1–F8、P1–P14、基线机、冷缓存、Explorer 真双击未做。
- **不是正式 V10**：V10 是重复内容拼接；P14 只能写“合成替身稳定性通过”。
- **P7 边界未通过**：不得写“P7 1080p 全过”；不得把 T7.9 的 0.06ms 当作本专项；
  不得把 80 改成 145。spec 的“收紧到 1s”在当前实现下仍 92.65ms，说明 fallback
  无效，需要异步/延后回拷或规格决策。
- **V3/V4 是 proxy**；V5 是人工 VFR；V8 是合成坏文件；V9 只有 click 对齐，
  不是正式片单。
- T7.4 仍 4K proxy；T7.5 可达 SMB/物理设备丢失/真实 V8 未验；T7.6 F1-A1 只有
  热缓存预检。

## 4. 下一步（优先）

1. **P7 边界缺口（新，优先于 T7.7 P7 结论）**：当前后退第一步同步回拷 24 帧
   FrameCache 导致 90–145ms。可选方向：
   - 异步/延后回拷：先呈现目标帧，再在后台填缓存（需处理解码器表面生命周期、
     FrameCache 线程安全与取消）；
   - 缩小 1080p 回拷窗口并评估 P7 p95/基线机代价（不能用 4K 窗口换 1080p）；
   - 若产品决定改验收口径，必须走 spec §9 版本记录，不能静默改 80ms。
   修复后重跑 `scripts\gop-boundary-bench.ps1`（2s 与 1s 各 20 样本）+ T7.8 全量，
   并评估是否 `-UpdateBaseline`（有意的性能改动才更新）。
2. **T7.7 全量验收**：真实 V1–V10 + 基线机（4C/8GB/集显/SATA SSD/Win11）+
   冷缓存 F1-A1 + Explorer 真双击；P6/P9 按目标距前关键帧 ≤2s 分类，长 GOP
   单列；P7 边界按上面修复后的结果记录。
3. **T7.3 正式 P14**：有真实 V10 时用真实 V10 复跑 7200s（`-NoLoop`）；
   合成 V10 只作稳定性预检。
4. **T7.8 维护**：本轮无产品性能改动，不更新基线；不要用 `-Quick` 写基线；
   不要为漂移改 `thresholds.json`。
