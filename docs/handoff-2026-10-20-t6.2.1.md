## 2. 问题与根因

用户实测：物理按住 `PgDn`/`PgUp` 只前进/后退 3 帧就停；预期持续连发。`--key-test`
的合成长按 2s 能走 27 帧，说明连发定时器本身正常。

根因：

1. Qt 在物理长按时会额外发送 **`KeyRelease`**（自动重复事件），官方 FAQ 明确要求检查
   `QKeyEvent::isAutoRepeat()`。
2. T6.2 的 `HandleGlobalKey()` 只要 `KeyRelease` 且 `step_direction_ != 0` 就
   `StopStepRepeat()`，没有区分自动重复 release 与真正松开。
3. 3 帧的时间线：按下立即 1 帧；300ms 定时器 1 帧；70ms 后 1 帧；约 500ms 第一次 OS
   重复的 release 到达，连发被停。
4. `--key-test` 只发合成 `KeyPress`，没有自动重复 release，所以 75 项全过但漏掉物理路径。

## 3. 修复

[MainWindow.cpp](../src/app/MainWindow.cpp)：

- `KeyRelease` 为 step 键且连发中时：
  - `event->isAutoRepeat()` → 吞掉，继续连发；
  - 否则 `StopStepRepeat()`，真正松开停止。
- 自动重复 `KeyPress` 仍 `return true`，不额外走帧；连发仍由 300ms→70ms 定时器单源驱动。
- 焦点切走、窗口失活、文本/模态让位、边界停止均未改。

测试辅助：

- `SendKeyReleaseForTest(..., bool auto_repeat=false)`；
- `PressAutoRepeatReleaseForTest(key, modifiers)`；
- `--key-test` 新增 `autorepeat-release-active`、`autorepeat-release-ignored` 两项。
- `LAPIAN_KEY_LOG=1` 诊断日志：`key_event`（type/auto/dir/frame）与 `step_timer`
  （before/after）；只在环境变量开启时输出。

## 5. 决策与口径

1. **只忽略 `isAutoRepeat()` 的 KeyRelease**：不能把“任何 KeyRelease 都不停”作为修复，
   否则真正松开后连发会一直跑。
2. **不改自动重复 KeyPress 的处理**：仍然忽略，避免 OS 重复速率与 70ms 定时器叠加。
3. **不改连发速率/焦点语义**：300ms 首延迟、70ms 间隔、焦点切走/窗口失活停止保持 T6.2。
4. **诊断日志保留**：`LAPIAN_KEY_LOG` 只影响 stderr，不改变行为；以后物理键盘问题可直接
   看 auto 标志。

## 6. 缺口 / 不宣称

1. **本会话没有硬件级自动化**：新增测试注入的是 `QKeyEvent` 自动重复 release；用户已用
   物理键盘在 `测试.mp4`/60s 素材长按 PgDn/PgUp 复测正常（2026-10-20），但正式
   F3-A3/P8 仍按片单验收，不能把用户手测写成 agent 硬件自动化。
2. 中文输入法、AltGr、Ctrl+O 原生对话框仍未真人验收。
3. 正式 F3-A3/P8/F7 矩阵、基线机未做；27 帧是开发机合成片数字。
4. 不改 T2.9.1 预览缓存，也不做 T6.5。
