## 2. 本轮做了什么

### 2.1 窗口初始尺寸与侧栏

- [src/app/MainWindow.cpp](../src/app/MainWindow.cpp)：
  - `ApplyInitialWindowSize()`：按 `QScreen::availableGeometry()` 收缩初始窗口；
    `min(1280, 可用宽-32) × min(720, 可用高-64)`，再按实际尺寸居中。
  - 100% 仍 1280×720；125% 1280×720（可用 1536×826）；150% 1248×624；200% 928×452。
  - `UpdateResponsiveLayout()`：侧栏宽度 `clamp(窗口宽×0.26, 240, 300)`；
    `<1000` 逻辑宽度隐藏状态栏的 Qt/FFmpeg 版本标签（次要信息）。
  - `resizeEvent` 调用 `UpdateResponsiveLayout()`；全屏进入/退出也自动刷新。
- [src/app/GfxWidget.cpp](../src/app/GfxWidget.cpp)：最小尺寸 480×270 → **320×180**。
  200% 下原最小高度会把窗口最小高度推到屏幕可用区之外。

### 2.2 InfoBar 响应式

- [src/app/InfoBar.h](../src/app/InfoBar.h)/[.cpp](../src/app/InfoBar.cpp)：
  - 单行 QHBoxLayout 改为 QGridLayout；`width() < 760` 时：
    - 第一行：文件名 + 帧号 + 时间码；
    - 第二行：格式/编码/帧率 + 总帧数。
  - 宽度 ≥760 时保持原单行布局。
  - 文件名 `elidedText(..., ElideMiddle)`，tooltip 保留完整文件名；最小宽度 0，
    不再用 180px 硬下限推高窗口最小宽度。
  - 所有标签设置 objectName，供 `--dpi-test` 检查几何/重叠/裁剪。

### 2.3 自动化

- [src/app/main.cpp](../src/app/main.cpp) 新增 `--dpi-test`：
  - `--dpi-expect-scale <1|1.25|1.5|2>` 断言 `devicePixelRatioF()`；
  - `--dpi-tag <名>` 用于日志/截图文件名；
  - 正常窗口 → 全屏 → 820 宽窄窗口三态，逐态：
    - 打印 `LayoutStateForTest()`（窗口/frame/可用区/最小尺寸/各面板/InfoBar/状态栏）；
    - 打印 `LayoutProblemsForTest()` 的问题清单；
    - `QWidget::grab()` 截图到 `build/t6.4-dpi-<tag>-<phase>.png`。
- [src/app/MainWindow.h](../src/app/MainWindow.h)/[.cpp](../src/app/MainWindow.cpp) 新增：
  `LayoutStateForTest`、`LayoutProblemsForTest`、`AvailableScreenForTest`、
  `InfoFileLabelForTest`、`InfoFileNameForTest`、`InfoNarrowModeForTest`。
- 测试视频区黑是 D3D11 原生 HWND 的已知 grab 限制；截图只用于布局证据。

## 4. 决策与口径

1. **初始窗口以屏幕可用区为上限**：`可用区 - (32,64)`，100% 仍保持 1280×720；
   避免 1080p@150/200% 时 frame 超出屏幕。注释与测试都按逻辑像素。
2. **侧栏 240–300 响应式**：100%/125%/150% 维持 300；200% 约 241。
   MarkPanel 自身最小 240 不变，信息栏窄模式在 240 侧栏下仍放得下。
3. **InfoBar 断点 760 逻辑像素**：150% 正常窗口信息栏 948 宽，单行；200% 正常 687、
   全屏 711、窄窗口 580，均两行。断点取在 760，避免 700 附近文字挤在一起。
4. **文件名省略而不是隐藏**：保留完整名 tooltip；文件名的信息优先级高于格式字段，
   但不能让长名字把窗口最小宽度推大。
5. **状态栏版本标签在 <1000 隐藏**：Qt/FFmpeg 版本不是操作控件；音量/音频/循环/波形/
   帧号仍保留。若以后要求常显，需要重新分配状态栏宽度。
6. **GfxWidget 最小 320×180**：保证 D3D11 交换链仍有可用面积，同时 200% 下窗口最小
   高度 382 < 可用 516。
7. **不改时间轴映射**：时间轴/波形继续按逻辑像素绘制，Qt 按 DPR 输出物理像素；
   `8px/帧` 上限仍按逻辑像素，T2.7 的像素断言不变。
8. **不改全屏几何保存逻辑**：T6.1 的 `saveGeometry()`/恢复保持；T6.4 只让初始窗口
   和侧栏在高低 DPI 下都落在可用区内。

## 5. 缺口 / 不宣称

1. **不是真实显示缩放验收**：用 `QT_SCALE_FACTOR` 模拟 100/125/150/200%，没有改
   Windows「设置 → 显示 → 缩放」，也没有物理 4K 显示器/多显示器/每屏 DPI。
2. **不是真人字体/IME 验收**：中文文件名省略是程序化断言；不同系统字体、输入法候选框
   在 150%/200% 的位置未测。T6.2 的真人键盘/输入法缺口仍存在。
3. **未测运行中 DPI 变化**：Qt 通常需要重启应用；`QEvent::ScreenChangeInternal` 未处理。
   首期要求是启动时覆盖 100%–200%，不是热切换。
4. **未测空态在 200% 的截图**：`--dpi-test` 需要 `--file`，验证的是打开文件后的布局；
   空态 InfoBar 只显示“未打开文件/帧 —”，高度更小，但未单独截图。
5. **未测 4K 显示器 + 200%**：逻辑可用区会更大，理论上更宽松，但没有真实 4K 屏证据。
6. **不是基线机/T7.7 全量验收**：开发机 RTX 4060；P1/P2 冷启动与多显示器仍归 T7.1/T7.7。
7. **截图视频区黑**：原生 HWND grab 限制；截图只证明布局，不证明画面渲染。
