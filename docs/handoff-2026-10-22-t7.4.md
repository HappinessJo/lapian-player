## 2. 本轮做了什么

### 2.1 根因：228ms 不是解码慢，是两处结构问题

复现 T7.2 的 4K 后退 p95（本轮 259.43ms，T7.2 228.09ms），用
`LAPIAN_SEEK_LOG`/`LAPIAN_STEP_LOG`/`LAPIAN_PUT_LOG` 拆开：

1. **前进步进每一步都重新从关键帧解到目标**：`MediaSession::SeekToFrame(kNone)`
   无条件 `SeekToPts(keyframe)` + 解码 20–60 帧，4K 前进 p95 230ms。
2. **后退每 8 步未命中一次**：8 帧窗口只覆盖 8 步；未命中的大头是
   **D3D11VA 硬件帧回拷**：每帧约 11ms，每批第一帧约 88ms（等 GPU 队列），
   8 帧约 160ms；解码本身 25–172ms。

### 2.2 改动（`40bba7f`）

- `MediaSession`：新增 `sequential_frame_`（解码器下一帧帧号）。当
  `SeekToFrame(kNone)` 的目标正好是顺序下一帧时，只调一次 `DecodeNextFrame`；
  缓存命中、重新 seek、Open、InstallIndex 都会使顺序位置失效。
  **前进 4K p95 230ms → 4.12ms**。
- `FrameCache::LimitsForFrame`：4K 从 `96MiB/8` 改为 `256MiB/20`。仍只缓存
  “后退步进解码到目标前的软件 NV12 帧”；播放/普通跳转/前进不写缓存。
  40 步扫描未命中 5 → 2 次。
- 测试专用：`--drag-test`（P4/P6/P7/P8/P9，20 样本，产品拖动/键位/跳转入口）、
  `--drag-samples`、`--drag-tag`、`--force-software-decode`
  （设 `LAPIAN_FORCE_SOFTWARE=1`，只影响本进程；产品默认硬解优先不变）。
- 诊断日志（默认关）：`LAPIAN_SEEK_LOG`、`LAPIAN_STEP_LOG`、`LAPIAN_PUT_LOG`。
- 单测：`frame_cache_test` 更新 4K 预算 + 超大帧回退；`media_session_test`
  增加“顺序前进 / 后退命中缓存仍帧精确”。

### 2.3 没做什么

- 不改产品默认硬解/软解回退，不改缓存内容（仍是软件 NV12），不改 B 到达/
  显示尺寸，不改拖动预览语义（独立软件解码 + 1280 降采样）。
- 不为 P7 降质/丢帧，不放宽 150ms 阈值。
- 不为“seek 后 PgUp”预热缓存（会推高 P9 4K）；如实记录该单样本超限。

## 4. 口径 / 不宣称

- **不是正式 V4**：proxy-V4 是 15s/450 帧、简单合成内容的 4K H.264；P4 的
  60fps 与软解速度都可能因真实内容下降。
- **不是基线机**：6C/12T + RTX 4060 + 32GB，强于 4C/8GB/集显。
- **不是冷缓存**：未清 Windows 文件缓存/重启。
- **P7 只有 p95 过**：尖峰仍在；seek 后 PgUp 单样本超限。
- **软解 P6/P9 未过**；不写成软解通过。
- **P11 只测 15s**；没有 4K 2h/显存统计。
- **T7.3 仍未关闭**：V10 2h 未做、P14 未通过；本轮没有重开 T7.1/T7.2/T7.2.1/T7.3。
- 没有真实 V4/V5、H.265 4K、10-bit/HDR、多显示器/200% DPI、RDP/集显；
  这些留 T7.7。
