## 5. 已知缺口 / 不要误判为完成

1. **T2.4 的 LRU/预取缓存没做。** 当前每次步进走冷 seek；1s/2s GOP 已达标，长 GOP 仍可能超 P7。不要声称“缓存完成”。
2. **T2.2 的后台 demux worker 没做。** 索引在 `MediaSession::Open` 里同步构建；长片会增加打开耗时。T2.7 前建议决定是否先补 worker。
3. **T2.5/T2.6 是合并提交。** 如果要求严格一任务一提交，后续可拆，但当前代码共享 UI 输入路径。
4. **V1–V8 正式素材仍缺。** 现有 V9、真实 1080p30、proxy-V1/V3/V4，以及 `build/test-media` 下的合成 VFR/2s GOP/10-bit/旋转片；这些不是正式验收片单。
5. **4K seek 未测。** T2.3/T2.4 的 4K P6/P7/P9 要等 T7.4/T7.7。
6. **60Hz 呈现、DPI 125%/150%、VFR 真机、拖拽、5s 错误计时、T1.5 的 100ms 和严格 60s 计时** 都没有正式验收数据。
7. **没有音频/时间轴/标记。** `dist\lapian.exe` 只是当前可打开/播放/步进的版本，不是首期完整产品。
8. **UI 目前有两个隐藏测试入口**：`--play`（等价 Space）、`--goto <文本>`（等价 Ctrl+G）。发布前应移除或隐藏。
9. **H.264 seek 后会有 `missing picture in access unit` 警告**；落点 PTS 全部精确，seek 测试把 FFmpeg 日志压到 error。不要把它误判为落点错误。
10. **`SeekEngine` 与 `MediaSession::SeekToFrame` 有重复的“关键帧→目标帧”逻辑**；T2.7/T2.9 前可以合并，避免两套行为漂移。

## 6. 环境与命令

本机（非 spec 基线机）：

- Windows 11 x64 10.0.26200；RTX 4060（D3D11 FL 11_1，硬解可用）。
- VS2022 / MSVC 14.44 / SDK 10.0.26100。
- CMake 便携 3.31.6；Qt 6.8.3 msvc2022_64；FFmpeg 7.1.1 最小构建（LGPL、`--disable-network`、D3D11VA/D3D11VA2）。
- 基线机应为 4C/8G/集显/SATA SSD/Win11；当前所有性能数字都不是最终验收。

```powershell
# 完整构建 + 测试 + 打包 + 自检 + 体积
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1

# 单测
ctest --test-dir build\release -C Release --output-on-failure

# 应用
build\release\bin\lapian.exe media\proxy\proxy-V1.mp4
build\release\bin\lapian.exe --file media\V9.mp4 --play
build\release\bin\lapian.exe --file media\proxy\proxy-V1.mp4 --goto 00:00:05:12
```

环境坑（本会话遇到过，按需处理）：

- Qt `moc` 在受限沙箱下会出现 `libuv process spawn failed: operation not permitted`；需要完全访问，且把 `TMP`/`TEMP` 指到工作区（例如 `build\tmp`），否则 MSBuild 的 `%TEMP%\MSBuildTemp` 可能不可写。
- 直接 `cmake --build` 时先设置 `$env:TMP`/`$env:TEMP` 到工作区；`build-release.ps1` 已处理构建期临时目录。
- GUI 子进程必须重定向 stdout/stderr，否则可能继承管道挂起。
- 新加的 `.ps1` 必须 UTF-8 带 BOM（PowerShell 5.1 按 ANSI 读）。
