## 4. 关键实现地图

| 文件 | 作用 |
|---|---|
| [src/core/TimelineModel.*](../src/core/TimelineModel.h) | 帧↔像素、fit/8px 上下限、缩放锚点、滚动 clamp、1/2/5×10ⁿ 刻度、只生成可见区 |
| [src/app/TimelineWidget.*](../src/app/TimelineWidget.h) | QPainter 时间轴、播放头、滚动条、滚轮/Shift+滚轮、点击/拖动信号 |
| [src/media/PreviewDecoder.*](../src/media/PreviewDecoder.h) | 独立软件解码线程、关键帧 seek、latest-frame mailbox、generation、15ms 切片、1280 降采样 |
| [src/app/MainWindow.cpp](../src/app/MainWindow.cpp) | 拖动开始/目标变化/松手、16ms 预览轮询、松手取消预览并精确 `GoToFrame` |
| [tests/timeline_test.cpp](../tests/timeline_test.cpp) | 时间轴几何/命中/信号/43.2 万帧离屏绘制 |
| [tests/preview_decoder_test.cpp](../tests/preview_decoder_test.cpp) | 预览打开、首帧延迟、2s 拖动发布帧率 |

行为要点：

- 第 N 帧占 `[N, N+1)`，按物理像素对齐后 floor；150%/200% DPI 的实机验收仍待 T6.4/T7.7。
- 拖动按下即暂停；大号帧号先显示目标帧，画面显示最新预览帧。
- 松手先停 16ms 定时器、`PreviewDecoder::End()` 清空 mailbox，再无条件走精确 seek；预览帧不会成为落点。
- 设置 `LAPIAN_TIMING_LOG=1` 会向 stderr 输出 `release_exact_ms` / `preview_tick_ms`，用于 T7 回归。
- 预览线程把 FFmpeg 日志压到 error，避免 H.264 “missing picture in access unit” seek 警告刷屏。

## 5. 环境与命令

本机（非 spec 基线机）：

- Windows 11 x64 10.0.26200；RTX 4060；VS2022 / MSVC 14.44；Qt 6.8.3 msvc2022_64；FFmpeg 7.1.1 最小构建。
- CMake 便携 3.31.6。

```powershell
# 完整构建 + 测试 + 打包 + 自检
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1

# 单测（必须带 Qt bin 与工作区 TMP/TEMP）
$tmp = Join-Path $PWD '.deps\tmp'
$env:TMP = $tmp; $env:TEMP = $tmp
$env:PATH = "E:\拉片软件开发\third_party\Qt\6.8.3\msvc2022_64\bin;$env:PATH"
ctest --test-dir build\release -C Release --output-on-failure

# 运行打包版（自带 DLL，推荐给用户手测）
.\dist\lapian.exe .\media\proxy\proxy-V1.mp4
.\dist\lapian.exe .\media\proxy\proxy-V1.mp4 --goto 137
.\dist\lapian.exe .\media\proxy\proxy-V1.mp4 --play
```

环境坑：

- 直接 `ctest` 不设 Qt bin 会 `lapian_smoke` 0xc0000135；不设 TMP/TEMP 会让 media_probe 的临时文件用例失败。`build-release.ps1` 已处理。
- 改过 `CMakeLists.txt` 后直接 `cmake --build` 可能在本机 CMake 3.31.6 重配阶段崩溃；用 `build-release.ps1`（会删 cache 重配）最稳。
- GUI 子进程要重定向 stdout/stderr，否则可能继承管道挂起。
- 新加的 `.ps1` 必须 UTF-8 带 BOM（PowerShell 5.1）。

## 6. 已知缺口（不要误判为完成）

1. **没有音频。** 没有 WASAPI/音频解码/波形；`M`、`W`、音量都还没有。T2.10 的“拖动静音”留给 T3.7，不能宣称 F3-A6/F5 静音完成。
2. **T2.4 的 LRU/预取缓存没做。** 当前每次步进走冷 seek；1s/2s GOP 已测达标，长 GOP 仍可能超 P7。P7 的“热解码器 + 缓存/预取”前提未满足。
3. **T2.2 的后台 demux worker 没做。** 索引在 `MediaSession::Open` 同步构建；长片打开可能慢，P2/VFR P9 未正式验。
4. **正式 V1–V8 素材仍缺。** 现有 V9、真实 1080p30、proxy-V1/V3/V4、合成 VFR/2s GOP/10-bit/旋转片，不是正式验收片单。
5. **P6/P7/P9 没有正式 p95。** T2.10 是单样本；20 样本、V1/V4、基线机、长 GOP 分类仍待 T7.7。
6. **P5 只有合成 10s 拖动探针。** 60Hz/DPI/专业帧时间戳/ETW 未覆盖。
7. **4K 拖动预览可能低于 30fps。** 预览用软件解码；spec 的 4K 放宽档是 ≥20fps，待 T7.4。
8. **预览打开失败不弹 UI 错误。** 只影响拖动预览；松手/步进/输入仍走精确路径。
9. **T2.10 计时日志是诊断用**，受 `LAPIAN_TIMING_LOG` 控制；不是用户功能。
10. **没有安装包/文件关联。** `dist` 只是便携目录；`--play`/`--goto` 仍是隐藏测试入口，发布前应移除或隐藏。
11. **无标记/备注/截图/持久化/循环/变速/全屏。** UI 上按到这些键没反应是正常的。
12. 预览当前为降采样 NV12，不是全质量帧；拖动中的画面“软”是设计行为。
