语义/约束：

- **DASH 默认档**：`DashCatalog::DefaultStream()`（AVC、非手动档）+ `BestAudio()`；60/4K 不自动。
- **总字节**：`Range: bytes=0-0` 的 206 Content-Range；拿不到就走 durl，**不伪造 size**。
- **缓存命中**：DASH 视频+音频两个条目都 complete 才走；缺一个明确报“需要清空该视频缓存后重下”，不静默降级/不联网。
- **seek**：`MediaSession::SeekToFrame` 用 `SeekToKeyframePts` + PTS 校验；T8.11 的渐进索引/未缓存等待不要绕过。
- **音画偏移**：`av_offset_us = -视频首帧 PTS`（音频首包实测 PTS=0）；OB-3 = -21ms。
- **durl 回退**：`--force-durl` 只用于回归；产品路径在 DASH 目录/音频/总字节失败时自动回退并记录原因。

## 4. 关键决定与解释

1. **先取 DASH 目录再起播**：不再像 T8.9 把目录放首帧后。代价是首帧多一个 API RTT（322–369ms 仍远低于 OP1 5s）；收益是一次拿到档位/音频/总字节，并避免“先 durl 再切 DASH”的双下载。
2. **不 remux**：两个 `GrowingSource` + 两个 `AVFormatContext`；音频独立 seek，共享音频主时钟。spike 证明 fMP4 双容器可直接解码。
3. **音频缓存独立条目**：`audio-<id>` 目录 + meta `kind/audio_id`；不塞 qn/codecid。旧 durl 缓存完全兼容；清空/清理/配额同时保护当前 bvid+cid 的音频。
4. **DASH 缓存命中用双 GrowingSource（完整文件全量 Publish）**：复用同一条双输入路径，不新增 `OpenLocalDual`；0 网络、45–46ms、仍受 `GrowingComplete` 保护。
5. **修 fMP4 seek 落前一 GOP**：这是双输入暴露出的核心 bug；`SeekToKeyframePts` + PTS 校验。没有它，20 次 seek 的帧号“看起来对”，PTS 实际早 5s，音画/标记/截图都会错。
6. **M1 回归分两条**：`--force-durl` 28/0 证明单文件路径不变；DASH 25/0 证明双输入下既有 UI/索引/标记/截图仍工作（未缓存专项因下载完成跳过，不是掩盖失败）。
7. **OB-2 fps 双记录**：API 29.412 用于报告；帧号数学用容器 30fps（索引 2867 帧/95.566s）。T8.12 必须定“实际 fps”口径，不能拿 API 值算总帧数。

## 5. 已知缺口

1. **T8.11 未做**：索引仍是“缓存增长后重扫”，波形仍是 T8.6 渐进；60s 测试下载太快，未覆盖慢网/边下边索引的极端。
2. **缓存条目级 LRU 可能拆散视频/音频**：命中时缺音频只报错让用户清空重下，不自动补下（T8.13）。
3. **多音轨/Dolby/FLAC 未做**：只选一条 `BestAudio()` AAC。
4. **无音轨 DASH-only 样本未验**：无音频时回退 durl；两者都没有则失败。
5. **备份 URL 的总字节/故障切换未逐条测**：主 URL 3/3；备份只在代码路径。
6. **音画偏差是应用内时钟**：非外部同步仪；p95/max 已记录，不外推。
7. **默认 AppData/Medium 未在 T8.10 重跑**：测试根在工作区；T8.16 安装版再验。
8. **大会员 60/4K 未验**：T8.15。
9. **`--online-m2-test` 仅 GUI**：无 headless 版本。
10. **5s GOP 点尾 seek ~260ms**：不属于 P9 ≤2s 口径；T8.11/T8.13 若要做“任意位置 200ms”需另立指标。
