## 2. 接口（给 T8.4 / T8.5 / T8.7）

```cpp
namespace lapian::online {

struct CacheKey { QString bvid; qint64 cid = 0; int qn = 0; int codecid = 0; };
bool IsValidCacheKey(const CacheKey&);   // bvid=BV+10 位；cid/qn/codecid 正整数
QString CacheKeyLabel(const CacheKey&);  // BV1BMnv6jE5S/123456/64-7（只用于日志/证据）

struct CacheMetadata {  // playurl 成功后由 T8.5 写入
  QString title, owner, source_fps_hint;
  qint64 duration_ms = 0; int width = 0, height = 0; double fps = 0.0;
};

struct CacheEntry {
  CacheKey key; QString title, owner; qint64 duration_ms; int width, height;
  double fps; QString source_fps_hint;
  qint64 total_bytes, downloaded_bytes; bool complete;
  QDateTime created_at, last_access_at;
  // 派生：dir/data_path/data_bytes/meta_bytes/usage_bytes/meta_present/
  //       broken/broken_reason/evict_pending/meta_dirty
};

class CacheStore {
 public:
  explicit CacheStore(QString root = QString(), qint64 quota_bytes = 0);  // 构造不碰磁盘
  static QString DefaultRoot();                 // %LOCALAPPDATA%\拉片软件\cache
  static QString DefaultRootFor(const QString& local_app_data);  // 纯函数，单测用
  static qint64 DefaultQuotaBytes();            // 20 GiB
  static qint64 FreeDiskBytes(const QString& path, QString* error = nullptr);
  static QString FormatBytes(qint64 bytes);

  bool SetRoot(const QString&, QString* error);      // 建目录 + 可写探测；不迁移旧缓存
  bool SetQuotaBytes(qint64, QString* error);        // >= 1MiB；产品 1–100GB 由设置层 clamp

  qint64 UsageBytes() const;                          // data.part+data.mp4+meta.json
  bool Reserve(const CacheKey&, qint64 expected_bytes, QString* error); // 空间+配额/淘汰+建 meta/空 .part
  bool OpenPart(const CacheKey&, QString* part_path, qint64* existing_bytes, QString* error);
  bool UpdateProgress(const CacheKey&, qint64 downloaded_bytes, bool force);
  bool MarkComplete(const CacheKey&, QString* error); // 调用方须先关闭写句柄
  bool OpenComplete(const CacheKey&, QString* mp4_path, QString* error); // T8.7 缓存命中

  std::optional<CacheEntry> Load(const CacheKey&, QString* error = nullptr);
  bool Scan(QVector<CacheEntry>* out, QVector<CacheEntry>* broken, QString* error = nullptr);
  bool EvictToQuota(const CacheKey& current, QString* error);
  bool Rebuild(const CacheKey&, QString* error);
  bool ClearAll(QString* error, qint64* removed_bytes = nullptr);
  bool CleanupOrphans(const CacheKey& current, QString* error,
                      CleanupOptions options = {}, qint64* removed_bytes = nullptr);
  bool Touch(const CacheKey&, QString* error);
  bool SetMetadata(const CacheKey&, const CacheMetadata&, QString* error);
  QString EntryDir/PartPath/Mp4Path(const CacheKey&) const;
};

// 设置（settings.json，schema 仍是 1）
AppSettings { int volume; bool waveform_visible; QString cache_root; int cache_quota_gb; };
AppSettings MergeVolumeWaveform(const AppSettings& base, int volume, bool waveform_visible);
}
```

约定与错误语义：

- **线程**：`CacheStore` 内部 `QMutex`，可被下载线程 + UI 线程共享；但它**不创建线程、不做阻塞读**（T8.4 负责）。
- **`Reserve`**：先 `GetDiskFreeSpaceExW` 检查 `expected + 512MB`，再按配额淘汰，最后建目录/空 `.part`/meta；已完整缓存直接 `true`（缓存命中不重新预检）；`total_bytes` 变化要求先 `Rebuild`。
- **`OpenPart`**：返回 `.part` 绝对路径与**文件实际长度**；meta `downloaded_bytes` 以文件长度为准回写。**不请求网络**——Range 起点由 T8.5 决定。
- **`MarkComplete`**：校验 `.part` 长度 == total → 改名 → `complete=true`；失败保留 `.part`；幂等。
- **`Load`/`Scan`**：不存在 → `nullopt`；存在但坏 → 返回 `broken=true` 的条目并填 `*error`（不抛异常、不中断扫描）。崩溃在改名后、meta 落盘前会自动修正。
- **`EvictToQuota(current)`**：`current` 永不淘汰；文件仍被读取时标 `evict_pending` 并返回可读错误；`CleanupOrphans` 下一轮删除。
- **`ClearAll`/`Rebuild`/`CleanupOrphans`**：只动缓存根内本工具布局（`bvid/cid/qn-codecid`）的 `data.part/data.mp4/meta.json`；不碰在线记录/截图/用户源视频；不删除缓存根本身。

## 4. 关键决定与解释

1. **`meta.json` schema 是字符串 `lapian-cache-1`**（不是整数）：未知 schema 直接 broken，避免未来字段被 v1 静默读；字段名按 delta §4.1，额外只加可选 `evict_pending`。
2. **`total_bytes`/`complete`/键字段是硬要求**；展示字段（title/owner/宽高/fps/时间）缺失回退默认——满足“损坏/缺字段不崩”，同时不把坏数据当可播放。
3. **`.part` 长度是续传唯一真相**：`Load`/`OpenPart` 以文件长度校正 meta；`UpdateProgress` 走 `correct_downloaded=false` 的读取路径，避免“每次进度都触发一次校正写盘”破坏 1s 节流。
4. **写入顺序“空 `.part` → meta”**：崩溃最多留下无 meta 的孤儿数据，由 `CleanupOrphans` 清理；不会出现“meta 说 0 字节但文件有数据”的长期不一致。
5. **`Reserve` 先空间、后配额**：与 delta §4.3“写入前预检”一致；淘汰只会让磁盘更空，所以顺序安全。已完整缓存的 `Reserve` 直接命中，不再要求 `expected + 512MB`。
6. **删除用 `CreateFileW(DELETE, share=0)` + `FileDispositionInfo`**：能识别“读句柄未共享 DELETE”的占用；带 DELETE 共享的读句柄会删成功（Windows 语义安全，空间在句柄关闭后释放）。占用删不掉时保留 meta 并标 `evict_pending`，不做“删一半”。
7. **“当前会话 key”是 `EvictToQuota`/`CleanupOrphans` 的参数**，不是全局状态：T8.6 每次调用传当前 `CacheKey`；这避免 T8.3 引入会话单例。
8. **配额 1–100GB 的 clamp 放在设置层**，`CacheStore::SetQuotaBytes` 只要求 ≥1MiB：DEC-5 要求用 300MB 小配额验收，不能让产品范围挡住测试。
9. **缓存根/配额跨会话走 v1 `SettingsStore` 新键**（`schema` 仍为 1）；`MainWindow` 用 `MergeVolumeWaveform` 保留新键，旧 `settings.json` 缺键自动默认。
10. **改根不迁移**：`SetRoot` 只切当前根；旧根文件原样保留（delta §4.1 明确）；产品若要“提示旧缓存还在旧根”，T8.6 用 `root()` 变化 + 旧根 `UsageBytes` 提示。
11. **探针在 `QApplication` 之前分流**：与 `--online-http-selfcheck` 一致，保证“无 GUI、本地启动不初始化窗口/网络”。
12. **300MB/20GB 用稀疏文件**：`FSCTL_SET_SPARSE` + `QFile::resize` 造逻辑大小；`UsageBytes` 按逻辑文件大小（不是簇），符合“记账单测、不真填满”。

## 5. 已知缺口

1. **不是真 300MB/20GB 填满**：稀疏文件按逻辑大小记账；真实下载大文件/簇占用未测；20GB 真填满留 S5（DEC-5 可选）。
2. **磁盘满只有预检证据**（2 PB 不可满足 expected，0.08–0.12ms）；下载中 `WriteFile` 失败/`ERROR_DISK_FULL` 由 T8.5 映射。
3. **没有真实 playurl 数据**：qn/codecid/total/宽高/fps 都是合成值；T8.5 接入后要重跑同组（尤其 total 一致性与 Range）。
4. **杀进程续传是“新实例 + 文件长度”模拟**，未做真实 kill/断电；T8.5 还要覆盖服务端忽略 Range（200 全量）时不拼接。
5. **读句柄检测只覆盖 Win32 独占打开**；Qt/FFmpeg 真实读者行为留给 T8.4/T8.7；杀软占用未测。
6. **长路径只验本机 NTFS + 中文**（301/312 字符）；UNC/OneDrive/压缩/加密目录未验。
7. **在线记录是 sentinel**，不是真实 `%APPDATA%\拉片软件\online`（T8.7）；路径细节留给 T8.7。
8. **没有 UI**：缓存根/配额/占用只能经 API 与 `settings.json`；T8.6 才接设置/占用展示/清空入口。
9. **`CleanupOrphans` 失败不返回错误**：按“尽力而为、下一轮再试”设计（避免启动清理阻塞）；调用方若要统计，看 `removed_bytes`。
10. **`Scan` 是 O(条目数) 的文件遍历**（每次 `UsageBytes`/淘汰都扫）；MVP 条目数很小，未做索引/缓存；T8.6 若每秒调用需加缓存。

## 6. T8.4 / T8.5 需要什么

### T8.4（可增长读层，只依赖 T8.3）

- **只读**：`OpenPart` 拿到的路径 + `existing_bytes` 是唯一合法起点；若 `complete=true` 用 `OpenComplete` 的 `mp4_path` 走本地路径。
- **不要**假设 `.part` 稀疏/可写：读层打开只读句柄，`MarkComplete` 要求写句柄已关闭。
- **总大小**：`CacheEntry::total_bytes` 必须已知（T8.5 从 playurl/`Content-Length` 填）；未知时不要进入可增长播放（plan §12.4.1）。
- **并发**：`CacheStore::UpdateProgress`/`MarkComplete` 是短临界区；读层不要持有 `CacheStore` 锁，也不要让 `CacheStore` 回调读层（锁顺序 `OnlineSession → CacheStore → GrowingSource`）。
- **淘汰与读句柄**：读层句柄若不带 `FILE_SHARE_DELETE`，`EvictToQuota` 会返回 busy + `evict_pending`；T8.4 的“当前会话 key 不淘汰”由调用方传 `current` 保证。
- **测试可复用**：`tests/online_cache_test.cpp` 的稀疏文件/独占句柄 helper 可直接搬。

### T8.5（durl 取流）

- **写入契约**：`Reserve(total)` → `OpenPart` → 写 `.part`（顺序前缀）→ 每 1–2s `UpdateProgress(n,false)`（或关键节点 `force=true`）→ 关闭写句柄 → `MarkComplete`。
- **续传**：Range 从 `existing_bytes` 开始；服务端返回 200 全量时**从头写并覆盖**（不要 append），并提示“不支持断点续传”；total 不一致时 `Rebuild` 后重下。
- **元数据**：playurl 成功后用 `SetMetadata` 写 title/owner/duration/宽高/fps/source_fps_hint；**不要把 URL/Cookie/请求头写进 meta**。
- **失败**：磁盘满/空间不足直接展示 `Reserve` 的可读错误（不开始下载）；下载中写入失败保留 `.part` + meta，下次续传。
- **缓存命中**：先 `Reserve`（完整时直接 true）或 `OpenComplete`；命中路径**不调 view/playurl**（T8.7 验收 0 请求）。
- **完成**：`MarkComplete` 失败（句柄未关/长度不足）要保留 `.part` 并给可读错误，不能把坏数据当 mp4。

### T8.6 / T8.7（后续）

- 设置入口：`cache_root`（空=默认）+ `cache_quota_gb`（1–100）写 `AppSettings` 后 `SettingsStore::Save`；改根后用 `UsageBytes` 提示旧根占用但不迁移。
- 占用可见：`Scan`（总/单条 `usage_bytes`）与 `ClearAll`；清空只删缓存条目，在线记录走 T8.7 自己的目录。
- 缓存命中打开：`OpenComplete` + `Touch`（更新 LRU）；不要每次打开都 `Scan` 全根。
