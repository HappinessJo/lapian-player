## 1. 实现内容

- `ProbeMedia()` 打开本地文件，选**第一条**视频流与第一条音频流，返回：
  时长、格式名、有理数帧率（avg/r/首选）、分辨率、pix_fmt、time_base、start_time、
  容器帧数提示、display matrix/旋转角、VFR 初判、音频编码/采样率/声道。
- 错误分类：文件不存在、无权限、不支持的容器、损坏、无视频流、流信息失败、其他打开失败；
  不抛异常、不崩溃。
- VFR 初判只采样前 300 个视频帧或 50ms；不是全片索引，T2.2 再做完整 PTS 索引与校验。
- 旋转角按 FFmpeg `av_display_rotation_get` 的逆时针角归一化到 `[0,360)`；原 matrix 保留给 T1.3。
- 只读：不写源视频；不发起网络请求。

- 全部 `OK=1`，`NB_FRAMES` 与容器提示一致（测试 4573、V9 120、proxy-V1 720、proxy-V3 1200、proxy-V4 450）。
- `测试.mp4` 是用户提供的真实 1080p H.264 30fps 素材，覆盖 V2 类（30fps）元数据；
  它不是 V1（V1 要求 24fps），也不是长 GOP。其 seek 结果见

- V4 的 59ms 主要来自 4K 文件读取 300 个包做 VFR 初判；T1.1 不改采样上限，正式打开耗时可再调。
