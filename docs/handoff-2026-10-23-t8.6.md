## 2. 接口（给 T8.7/T8.8）

```cpp
// src/app/OnlineSession.h
struct OnlineRequest { QString bvid; qint64 cid; int page; QString title, owner;
                       qint64 duration_ms; QString page_title, sessdata; };
enum class OnlineState { kIdle,kPreparing,kBuffering,kReady,kStalled,kSeekingWait,
                         kRecovering,kError,kClosed };
struct OnlineProgress { qint64 published,total; double bps; QString job_state;
                        int qn,codecid; bool complete,awaiting_finalize; QString error; };
struct OnlineReadyInfo { std::shared_ptr<GrowingSource> source; QString part_path;
                         PlayUrlData playurl; OnlineRequest request; };

class OnlineSession : public QObject {
  bool Start(const OnlineRequest&, QString* error);
  void Cancel();                 // 非阻塞；取消下载/唤醒 reader
  void Close();                  // cancel + join
  bool FinalizeAfterReadersStopped(QString* error);  // reader 全停后 MarkComplete
  bool HasPendingFinalize() const;
  OnlineState state() const; OnlineProgress progress() const;
};
```

```cpp
// src/media/MediaSession.h
bool OpenGrowing(shared_ptr<GrowingSource>, const std::string& part_path,
                 const std::string& display_name, ID3D11Device*, std::string*,
                 bool prefer_hardware = true);
bool CanDecodeAhead(std::int64_t margin_bytes) const;
void InterruptGrowingReads();
bool SeekToEstimatedPts(pts_us, target_frame, DecodedFrameInfo*, std::string*);
void InstallOnlineIndex(FrameIndex, double build_ms);
```

语义/约束：

- `OpenGrowing` 只接受已知总大小的 source；display_name 只用于 UI/记录，不打开。
- 在线首帧在 UI 线程做（实测 32–39ms），因为 0.3MB 后 `ProbeFormat` 跳过包扫描；不在 UI 等 0.3MB（等待由 OnlineSession 轮询）。
- 未缓存 seek 在独立 worker；`GrowingCursor::SetInterruptFlag` 只中断该 reader，不取消共享 source；中断后该 MediaSession 丢弃并由 worker 重建。
- 部分索引只含稳定前缀（尾部 48 帧不暴露）；目标超出索引时用 CFR 估算 PTS，解码后偏差 ≤半帧才呈现，否则报错。
- 完成前 `DownloadJob` 进入 `kAwaitingFinalize`；必须停掉音频/波形/索引/seek/MediaSession 后再 `FinalizeAfterReadersStopped`。

## 4. 关键决定与解释

1. **不把 `.part` 路径直接交给 FFmpeg**：`GrowingFormat` + `ProbeFormat` + `VideoDecoder::OpenWithFormat` 非拥有 context；`GrowingSource::Published` 之外读会阻塞/EXIT，不会把未下载区当 EOF。
2. **0.3MB 首帧在 UI 线程**：T8.5/T8.6 实测 open 32–39ms、首帧 27–30ms，远低于 200ms；等待 0.3MB 本身由 QTimer/OnlineSession 轮询，不在 UI 阻塞。若后续样本需要，可把 open 移到 worker。
3. **未缓存 seek 异步 + 单读者 interrupt**：UI 只发目标/显示“缓冲中（目标帧 N）”；worker 在 frontier 阻塞；新目标/关窗用 cursor interrupt（25ms 粒度）退出，不取消共享下载源。被中断的会话丢弃，新 worker 用同一 source 重建。
4. **部分索引只暴露稳定前缀**：B 帧/PTS 排序会让“刚扫描到的尾部”帧号漂移；末尾 48 帧不暴露，安装前比较旧前缀 PTS，避免 UI 帧号跳变。这是“不能冒充精确”的落点。
5. **未索引 CFR 目标用估算 PTS**：没有全片索引时不能用帧号直接取 PTS；用容器帧率估算，解码后与目标 PTS 偏差 ≤半帧才呈现，偏差大报错。VFR/无帧率不冒充。
6. **1MB 解码余量 + 音频失速看门狗**：一次 Tick 可能连解 32 帧，256KB 余量在慢源上仍会让 `av_read_frame` 在 UI 阻塞（buffer 专项实测）。1MB + 音频 Pump 400ms 失速判定把“缓冲耗尽”变成显式自动暂停/恢复。
7. **完成前 finalize**：`DownloadJob` 默认行为不变；T8.6 启用 `defer_finalize`，先停 reader 再 `MarkComplete`。未改 CacheStore/reader 共享语义。
8. **会话内标记/截图**：T8.6 只保证可用；`MarkStore::OpenSessionOnly` 不落盘，截图写图片目录 `snapshots/`。完整在线记录（`lapian-online-1`/`index.jsonl`）留 T8.7。
9. **降帧提示保守**：实际 fps <50 时状态栏常驻“当前流帧率；若源片 60fps，帧号不同步/约 1/2”；不声称源片一定 60fps，也不把 29.4 写成 60。
10. **关闭顺序**：暂停 → online Cancel/唤醒 → seek/index/audio/waveform join → MediaSession Close → `FinalizeAfterReadersStopped` → OnlineSession Close；实测 18–645ms。
