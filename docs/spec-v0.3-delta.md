## 1. 帧、VFR、时间轴几何（§0、§3.2）

**建议补充到 §0 帧定义**：

> 帧 = 解码器按呈现顺序（PTS 升序）输出的第 N 个可显示帧，0 基；同一 PTS 的重复输出只计一次。CFR 与 VFR 的时间轴都使用等距帧格（1 帧 1 格）；VFR 的“按实际时间戳对齐”体现在波形取样区间 `[PTS_N, PTS_{N+1})`，不改变帧格宽度。时间码：CFR 用 NDF（FF = N mod 标称帧率；23.976→24、29.97→30、59.94→60）；VFR 由 PTS 换算、仅作显示，VFR 时间码输入按“最接近该时间的帧”定位。

**理由**：原 §0/§3.2 只写了“按显示帧计数”，没有定义时间轴几何与时间码公式；F2 的“1 帧 ≥8px”与 F5 的“VFR 按实际时间戳对齐”字面上冲突，必须选定一个。

**来源**：Q1。

## 2. 拖动中的“当前帧”与点击命中（§3.2）

**建议补充到 F2 行为定义**：

> 拖动中，大号帧号显示**指针映射的目标帧**；画面显示**最近已呈现的预览帧**；两者允许暂时不一致，松手后必须收敛到目标帧（误差 0）。点击/拖动的坐标命中规则：第 N 帧占据 `[N, N+1)` 区间，`floor` 取整；高 DPI 用物理像素换算后取整。

**理由**：F2 同时要求“帧号实时更新”和“预览 ≥30fps”，但指针事件频率高于呈现帧率；不定义就会在验收时争论“帧号到了、画面没到算不算”。

**来源**：Q1（补充）。

## 3. 总帧数三态（§3.2、§3.1）

**建议补充**：

> 总帧数有三种状态：精确（容器 `nb_frames` 可信或索引完成）、估算（时长×帧率，显示 `≈N`）、扫描中（显示“扫描中”）。索引完成前，End 与越界输入以已索引/已解码末帧为准，并提示；完成后静默校正。

**理由**：F1 信息区、F2-A4 的 clamp、F3-A4 的末帧都需要总帧数；VFR/MKV 常无可靠 `nb_frames`，全量扫描又和 P2/P13 冲突。

**来源**：Q1。

## 4. VFR 的 P9 例外（§4.1）

**建议补充**：

> P9 对 CFR 维持“任意距离 ≤200ms”；对 VFR 为“索引就绪后 ≤200ms，首次远距离跳转 ≤2s”。首次远跳允许先估算、后校正，但**最终落点必须是精确帧**，不能用近似帧交付。

**理由**：VFR 的“第 N 帧”必须靠 PTS 索引；首次打开时索引尚未完成，2 小时 VFR 无法在 200ms 内精确到任意帧。这是物理约束，不是实现选择。

**来源**：Q1。

## 5. 长按步进的算术（§3.3）

**建议修改 F3-A3**：

> 按住 PgDn 2s：前进 **≥20 帧**（保留 300ms 首次延迟与 ≥12 帧/秒连发），且每一帧都被渲染（帧号连续）。

**理由**：原文“2s ≥24 帧”与“300ms 后 12 帧/秒”算术不一致（约 21.4 帧）；改为 20 帧不降低连发速率，只修正验收数字。

**来源**：Q2（M1）。

## 6. 性能测试方法与 4K 放宽清单（§4.1）

**建议在 §4.1 增加“测试方法”小节**：

- **冷启动**：重启后首次启动，且目标文件不在 OS 文件缓存（用 RAMMap 或等效方式清理）；P1 测进程启动→窗口可交互，P2 测双击→首帧呈现。
- **P5 停顿**：用呈现时间戳 + UI 心跳；画面无更新且 UI 无响应 >200ms 记一次。
- **P7/P8**：P7 = 随机距离单步（含 seek，冷/热各测）；P8 = 同方向长按（解码器已热），每帧必须呈现。
- **P10 “空闲”**：打开 V1 并暂停 60s 的进程 working set；另报“无文件空态”基线。
- **P13 片长**：10 分钟 ≤3s；更长按“≤0.3s/分钟”线性放宽（2h ≤36s）。
- **4K 放宽档**：只放宽 P4（≥20fps）、P6（≤300ms）、P7（≤150ms）；P8 仍 ≥12 帧/秒，其余指标不劣化。
- **V10**：由“可选”改为“必选”，P14 保持硬指标。

**理由**：数字已有，缺的是可复现的测量条件；P8 与 4K P7 的字面冲突只有把“随机 seek”和“顺序长按”分开才能消解。

**来源**：Q2。

## 7. 音频状态机（§3.3、§3.4、§3.5）

**建议补充**：

> 步进、拖动、点击时间轴时：音频输出静音、音频时钟暂停；不逐次 seek 音频。恢复播放时，以当前帧 PTS 为起点对音频做一次 seek，预填缓冲后出声，保证音画偏差 ≤1 帧。A=B 定帧期间不推进音频、不输出。音频设备保持打开，切换时用短淡入淡出防爆音。设备丢失时降级为静音 + 系统时钟，不阻塞视频。

**理由**：原文只写“静音”，没写恢复播放从哪开始、设备是否常开；这会直接决定时钟架构与 F4-A6 的验收。

**来源**：Q3。

## 8. 波形分辨率、对齐基准与 V9（§3.5、§8）

**建议补充**：

> 波形为峰值包络，bucket ≥200 个/秒，每 bucket 存 min/max（单声道混合，int16）。对齐以容器/解码时间戳为基准；打开时估一次全局 A/V 偏移（首包 PTS + priming/edit list），验收要求**恒定偏移 ≤1 帧且无累积漂移**；不做逐段动态对齐。V9 由用户提供；若没有，可用本地合成（不联网）生成“第 100 帧 click + 一帧白闪”，并纳入片单。

**理由**：F5-A3 的“≤1 帧”没有基准与 bucket 定义就无法复现；AAC priming/edit list 会造成几十 ms 整体偏移，必须允许一次全局校正。

**来源**：Q4。

## 9. 标记/备注持久化（§3.6、§3.8）

**建议补充**：

> 默认在视频同目录写 `<视频名>.lapian.json`（UTF-8、带 schema 版本、原子写、损坏备份）；源目录不可写时回退 `%APPDATA%\拉片软件\marks\<路径哈希>.json`，UI 显示实际位置；sidecar 与回退文件同时存在时按 mark id + updated_at 合并；没有标记/备注时不产生文件；删除最后一个标记时删除附属文件。VFR 下同时保存 frame 与 pts。

**理由**：F6 只说“与文件关联保存”，没定义位置/格式/只读回退；截图有回退，标记没有，归档素材会直接丢数据。

**来源**：Q5。

## 10. 平台最低基线与可用档判定（§4.2、§4.3）

**建议补充**：

- 平台：Windows 10 21H2+ / Windows 11 x64；保证档要求可用的 D3D11 与硬件解码。RDP/虚拟机/无 GPU 加速环境只保证“不崩溃、能播”，不保证 P1–P9；不支持 ARM64 原生；DPI 覆盖 100%–200%。
- 可用档：可打开、可播放、不崩溃；不保证逐帧精确与性能。10-bit/HDR 可尝试打开并提示，不保证颜色；未列容器/编码（含 ProRes/DNxHD/MXF）明确报错；H.265 4K60 归可用档。

**理由**：“保证档/可用档”目前只有素材矩阵，没有验收判定；不写死，QA 范围会无限膨胀。

**来源**：Q7、Q8。

## 11. 分发与文件关联（§3.1、§4.5）

**建议补充**：

> 首期交付安装包（每用户安装，注册 ProgID/文件关联，卸载清理）+ 可选便携 zip；文件关联不强制设为默认应用，由用户确认。安装/卸载不联网；运行期零网络请求。

**理由**：F1-A1 依赖“双击已关联文件”，但 spec 没定义分发形态；便携版无法可靠注册关联。

**来源**：Q6。

## 12. 已拍板（2026-10-19）：两处残留口径

### 12.1 F6-A8 与 P9 的口径

F6-A8 要求“点击标记跳转 ≤100ms”，P9 要求“输入帧号跳转 ≤200ms”。标记跳转也是任意距离帧跳转，100ms 更严且与长 GOP 风险冲突。已按推荐锁定为：

> 点击标记：UI 响应（选中/播放头/帧号更新）≤100ms；画面精确到帧按 P9（1080p ≤200ms，4K ≤300ms）。

**来源**：plan R16；不在 Q1–Q8 内；2026-10-19 用户确认“按推荐来”。

### 12.2 旋转元数据

手机竖屏/VFR 素材常带 display matrix。已按推荐锁定为：

> 画面按容器 display matrix 旋转呈现；截图保存按显示方向旋转后的源分辨率图像（例如竖屏 1080×1920），不含 UI；首期不做手动旋转。

**来源**：plan R17；V5 可能触发；2026-10-19 用户确认“按推荐来”。
