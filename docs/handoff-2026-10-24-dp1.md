## 1. 完成到哪

DP-1 让**本地拖动预览**在 ≤1080p 时借用 GfxWidget 的共享 D3D11 设备硬解，
失败自动回退软件，并给 `--drag-fast` 增加真实诊断：

- `PreviewDecoder::Configure(..., ID3D11Device*, prefer_hardware, src_w, src_h)`；
- 硬件帧不 `sws_scale`、不缓存，直接 `GfxWidget::SetVideoFrame`；
- 回退原因：`device_unavailable` / `software_requested` / `source_too_large` /
  `hardware_open_failed` / `hardware_inactive` / `hardware_decode_failed` /
  `upload_failed` / `forced_software`；
- `--drag-fast` 输出 `hw_requested/hw_active/preview_hw_fallback`、
  `target_lag_frames/ms`、`seeks`、`cache_hits`、`published`、`active_fps`、
  `total_fps`、`boundary_hit`；
- `--preview-force-software` 只强制预览软解（主播放不动），用于验证回退；
- `MainWindow::PreviewDiagnosticsForTest()` 提供 target/displayed/hw/计数快照；
- 设备丢失重建：`EnsurePreviewDecoderDevice()` 比较设备指针后重开预览；
- `End()` 在硬件路径有界等待 worker 空闲（≤100ms），避免松手精确 seek 与
  预览硬解同时使用同一 D3D11 视频上下文。

## 2. 关键实现点（不要改坏）

1. **硬件帧不能缓存**：D3D11VA 静态表面池有限。spike 实测持有 16 张硬件帧
   就会把后续解码卡住。DP-1 只保留 `latest`/publish 的 1–2 张；`CacheFrame`
   只接收软件帧。DP-2 若要做硬件帧缓存，必须先做显存/表面池预算与 LRU。
2. **硬件帧不能 `sws_scale`**：`ScalePreviewFrame` 对 `AV_PIX_FMT_D3D11` /
   `hw_frames_ctx` 直接 `av_frame_clone`，全分辨率交给渲染器。
3. **固定目标切片**：硬件 `Process` 只服务进入时的目标，到目标就返回 worker。
   不允许“边解边追最新目标”，否则 +60 时永远补旧帧、Present 变稀。
4. **D3D11 全局锁仍保留**：硬件解码、`SetVideoFrame`、Present、截图回读共用
   `D3D11ContextMutex`。预览切片短 + `End()` 等待，1080p 空档 ≤46ms；如果
   改成更长的解码切片，要重新测 UI 阻塞。
5. **4K 不走硬解**：源 >1920×1088 时 `PreviewDecoder` 直接软件路径并记录
   `source_too_large`。4K 硬解 + 每步 seek 实测 8.4fps/空档 372ms，不能提交。
6. **设备生命周期**：`PreviewDecoder` 只借用 `ID3D11Device*`；`Close()` join
   线程并释放帧后才返回；MainWindow `preview_` 先于 GfxWidget 子窗口析构。
7. **探针计时**：快速/P4 用 `QTimer::singleShot(10, Qt::PreciseTimer, ...)`。
   本机 15.6ms 定时器粒度下，旧 16ms 实测约 31ms；改 10ms 后约 15.6ms。
   `fps` 是目标移动阶段的 headline，`total_fps` 是整个 2s；目标撞文件边界后
   不再产生新帧，是正常的。

| `ctest` | **36/36** |

DP-2 再做反向缓存/预取/远跳粗帧。

## 4. 环境/复现注意

- 从 DSH 工作区跑 ctest 时，Qt `QTemporaryDir` 对默认短路径 `TEMP` 失败
  （11 个测试报“无法创建临时目录”）；把 `TEMP/TMP` 指到
  `build\tmp-ctest` 后 36/36。这是环境问题，不是产品回归。
- 探针 argv 中文路径可能打不开；用 `build\dp1-test.mp4` 临时 hardlink，
  不要提交。
- 4K/HEVC 只记录，不设通过线；不要写 4K 通过，也不要因 4K 改 1080p 门。
