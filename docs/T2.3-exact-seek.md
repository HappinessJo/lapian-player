- **范围**：按帧号精确 seek；不接时间轴拖动、不做预览降质、不做音频。

## 1. 实现

- `VideoDecoder`：
  - `DecodedFrameInfo` 增加 `pts_us`/`duration_us`（AV_TIME_BASE 微秒）。
  - `SeekToPts(pts_us)`：转换到流 time_base，`av_seek_frame(..., AVSEEK_FLAG_BACKWARD)` + flush + 重置 EOF/packet 状态。
- `SeekEngine`：
  - 索引可靠：`FrameIndex::KeyframeAtOrBefore(target_pts)` 取前关键帧 → `SeekToPts` → 从关键帧开始解码，按显示帧计数到目标帧。
  - 索引不可靠/seek 落点异常：`DecodeCountFallback` 从首帧解码计数到目标帧（慢但帧号精确）。
  - `generation_` 自增 + `Cancel()` 原子取消；单次 seek 解码超时 2s。
  - 目标帧 PTS 来自索引；不拿关键帧或近似帧冒充目标帧。
- 与 T2.2 的关系：索引负责“目标帧的 PTS/关键帧”；seek 引擎负责“解码到该帧”。索引不可靠时 T2.2 的 `ValidateDecodedPts` 可继续标记降级。

## 2. 验证

`lapian_seek_engine_test`（硬解，RTX 4060；非基线机）：

| 素材 | 固定帧 PTS | 20 随机帧 | 最大耗时 |
|---|---|---|---|
| V9 120 帧 24fps | 0/1/24/59/100/119 全部精确 | 20/20 误差 0 | 30.10ms |
| proxy-V1 720 帧 24fps（长 GOP） | 0/1/24/100/359/719 全部精确 | 20/20 误差 0 | 263.85ms |
| 真实 `测试.mp4` 4573 帧 30fps（GOP 30） | 0/1/100/1000/3000/4572 全部精确 | 20/20 误差 0 | **29.95ms** |
| V9 索引强制不可靠后 | 帧 24 PTS 精确 | — | 14.26ms（降级计数） |

- 真实 1s GOP 的 20 随机帧最大 **29.95ms**，低于 P6 1080p ≤150ms（目标距前关键帧 ≤2s 条件）。
- proxy-V1 是长 GOP 样本，263.85ms 不进入 P6 的 2s 条件 p95；按方案 A 属“可用档”，但仍帧精确。
- 4K P6/P9、基线机、预览预热后 P6 仍待 T7.4/T7.7。
- H.264 在部分 seek 后会打印 `missing picture in access unit` 警告，落点 PTS 仍全部精确；测试已把 FFmpeg 日志压到 error，避免污染输出。
