## 2. 本轮做了什么

### 2.1 统一状态模型

新增 [src/media/StatusNotice.h](../src/media/StatusNotice.h)/[.cpp](../src/media/StatusNotice.cpp)，
纯 C++、不依赖 Qt/FFmpeg：

- `StatusNoticeKind`：`kNoAudio`、`kScanning`、`kOutOfGuarantee`、`kTenBit`、`kVfr`、`kError`；
- `BuildMediaStatusNotices(MediaInfo, vfr, scanning)` 生成除错误外的提示；
- `SelectPrimaryNotice()` 选唯一横幅；`SecondaryNoticeSummary()` /
  `SecondaryNoticeTooltip()` 生成状态栏摘要与 tooltip；
- `ParseStatusNoticeKind` / `MakeStatusNotice` 供单测和 `--banner-test` 合成全量场景。

优先级（高 → 低）：

```text
错误 > VFR > 10-bit > 超出保证范围 > 总帧扫描中 > 无音频
```

**顺序不是随手排的**：

- 错误是唯一“当前文件没打开/没换成”的状态，必须最醒目；
- VFR 改变帧号语义，spec F2-A7 要求打开时提示；手机 4K VFR 很常见，若让
  “超出保证范围”压过 VFR，VFR 提示只剩状态栏小字，F2-A7 的主路径不成立；
- 10-bit 影响颜色正确性，比性能提示更具体；
- 扫描中影响总帧数/导航，无音频只影响波形，所以扫描中高于无音频。

要改顺序只改 `StatusNoticePriority()` 一处；不要在 InfoBar 里再写分支。

### 2.2 InfoBar 唯一横幅

[src/app/InfoBar.h](../src/app/InfoBar.h)/[.cpp](../src/app/InfoBar.cpp)：

- 删除原来 `SetTotal()` 里“VFR else 扫描中”的二选一逻辑，统一走 `UpdateNotices()`；
- 仍只有一个 `banner_label_`（`objectName=infoBanner`），所以结构上不可能叠 banner；
- 横幅在 InfoBar 的 `QVBoxLayout` 网格下方，出现时 InfoBar 增高、时间轴/画面按布局
  让位；`setWordWrap(true)` + `Qt::PlainText`（错误文本不解析富文本）；
- 颜色分级：错误暗红、VFR/10-bit/超出保证琥珀、无音频/扫描中蓝灰；
- tooltip 放完整 `detail`；错误横幅只取消息首行，完整消息在 tooltip；
- `SetError()` / `ClearError()`；成功 `SetMedia()` 或 `Clear()` 自动清错误。

### 2.3 其余进状态栏

[src/app/MainWindow.cpp](../src/app/MainWindow.cpp)：

- 新增 `notice_label_`（`objectName=noticeInfo`）常驻状态栏，位于音频标签左侧；
- 文本如“其他提示：VFR、10-bit 等 5 条”，最大 240px、右侧省略，tooltip 列全部；
- 连接 `InfoBar::noticesChanged`，由 `UpdateStatusNotices()` 统一刷新；不用
  `statusBar()->showMessage()`，避免被“已打开/截图已保存”等临时消息冲掉；
- `ShowOpenError()` 现在同时 `info_bar_->SetError(message)`，错误横幅在模态框关闭后
  仍保留，直到下一次成功打开；
- `LayoutStateForTest()` / `LayoutProblemsForTest()` 增加横幅与 `noticeInfo`：
  `banner-clipped`、`banner-text-clipped`、`banner-overlaps-frame`、
  `banner-overlaps-timeline`、`banner-overlaps-status`、状态栏重叠/越界。

### 2.4 10-bit 来源

[src/media/MediaInfo.h](../src/media/MediaInfo.h) 的 `VideoStreamInfo` 新增
`int bit_depth = 8`；[MediaProbe.cpp](../src/media/MediaProbe.cpp) 打开时读取
`bits_per_raw_sample`，缺失则从像素格式描述推导（`yuv420p10le` → 10）。
这样不用等首帧解码就能出 10-bit 提示，也不会把“10-bit”误塞进“超出保证”重复报。

## 4. 决策与口径

1. **优先级按“语义影响 > 颜色 > 性能 > 过渡态 > 波形”**，不按任务列表顺序；
   见 §2.1 理由。VFR 放在 10-bit/超出保证之前是刻意的，不是笔误。
2. **超出保证范围判定**：像素数 > 1920×1080、fps > 60 + 1e-6、编码不是 h264/hevc；
   10-bit 单独成条；竖屏 1080×1920 不误报。
3. **容器不单独判定**：FFmpeg 的 demuxer 名把 MP4/MOV、MKV/WebM 合并；VP9/AV1
   WebM 已被编码条件覆盖。8-bit HDR、4:2:2/4:4:4 不细分。
4. **错误横幅只接打开失败**：运行期跳帧/音频设备/图形错误仍是状态栏/QMessageBox；
   常驻“音频不可用”会把 VFR/10-bit 等更有用的提示挤掉。
5. **扫描中当前不是真实异步状态**：`MediaSession::Open` 同步建索引；CFR 不出现，
   VFR 强制扫描态但作为 VFR 的 secondary。横幅路径由单测/合成覆盖，等 T7.2 后再
   接真实后台索引。
6. **其余提示不用 `showMessage`**：临时消息会覆盖，所以用常驻 `noticeInfo` 标签；
   这是对“其余进状态栏”的解释。
7. **测试合成入口保留**：`SetBannerNoticesForTest` 只在 `--banner-test`/自动化使用，
   不改变真实媒体路径；真实路径仍由 `SetMedia`/`SetTotal`/`SetError` 驱动。

## 5. 缺口 / 不宣称

1. **不是真实显示缩放**：100%/200% 用 `QT_SCALE_FACTOR`；没有改 Windows 显示设置、
   没有 4K 显示器/多显示器/每屏 DPI。
2. **不是正式 VFR 验收**：`vfr.mp4` 是 320×240 合成 VFR；没有 4K VFR/手机录屏，
   F2-A7 正式片单仍待 T7.7。
3. **10-bit 只验证提示与可打开**：fixture 是 320×240 H.264 10-bit；没有 HDR 元数据/
   广色域，也没有颜色正确性比对（spec 不保证）。
4. **超出保证规则有边界**：容器/8-bit HDR/色度采样/8K 未细分；正式 V4/V5 仍需手测。
5. **错误/扫描路径有范围**：错误只覆盖打开失败；扫描态没有真实异步索引。
6. **截图视频区黑**：D3D11 原生 HWND 的 `grab()` 限制，只证明 InfoBar/状态栏布局。
7. **不是基线机/P1–P14**：74 项与 0.037ms 是开发机（RTX 4060）数字；正式性能、
   2h soak、4K 路径归 T7。
8. **不宣称** F2-A7/F1-A4 正式片单通过、真实 10-bit/HDR 颜色、真实 200% 显示缩放、
   多显示器、IME/AltGr、F1-A6 真人、F8-A1 真实 `%APPDATA%`、F4-A2 长 GOP、
   正式 V1–V10/基线机。
