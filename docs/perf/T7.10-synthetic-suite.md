## 3. 生成方法

### 3.1 工具

- `C:\Program Files\Red Giant\Trapcode Suite\Tools\ffmpeg.exe`
  （ffmpeg 2.1.4，2014 版；只用于本地 stream copy/重封装，不随产品分发）
- Python 3（V5 改 `stts`；V8 WAV）
- 未联网；没有安装新工具

### 3.2 V1/V6/V7

```powershell
# V1：6:01，1080p24，AAC
ffmpeg -ss 60 -t 300 -i media\测试2.mp4 -c copy -avoid_negative_ts make_zero media\synthetic-suite\V1.mp4

# V6：12:00，1080p24，AAC
ffmpeg -ss 0 -t 720 -i media\测试2.mp4 -c copy -avoid_negative_ts make_zero media\synthetic-suite\V6.mp4

# V7：152s，1080p30，无音频
ffmpeg -ss 0 -t 152 -i media\测试.mp4 -c copy -an -avoid_negative_ts make_zero media\synthetic-suite\V7.mp4
```

> `-ss` 前的 stream copy 会从最近关键帧起，V1 实际 361s；在 3–10min 内。

### 3.3 V5：改 `stts` 造 VFR

1. 先做 30s 视频-only 基片：
   `ffmpeg -ss 0 -t 30 -i media\测试.mp4 -an -c copy build\v5-base.mp4`
2. 用 Python 改写 MP4 `moov/trak/mdia/minf/stbl/stts`：
   - 900 帧；首帧 delta=0；其余每 5 帧 `4×1000 + 1×3000`（timescale 30000）；
   - 去掉 `edts/elst`；更新 `mdhd` duration=1,257,000、`mvhd` duration=41,900；
   - `moov` 在 `mdat` 之后，`stco` 不需要改。
3. 探测结果：`DURATION_US=41900000`、`FPS=21.48`、`VFR_SUSPECT=1`、
   `VFR_DEVIATION_RATIO=0.198`、`HAS_AUDIO=0`。

脚本在 `build/make_v5.py`（gitignore；不随仓库）。如果 build 被清掉，按上面规则重写。

## 4. V10 2h soak（已收口）

命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\soak-bench.ps1 `
  -File media\synthetic-suite\V10.mp4 `
  -Seconds 7200 -Interval 30 -Tag v10-synth -NoLoop
```

- 启动：2026-10-22 19:30:18；结束：21:30:27（duration_s=7200.0）
- 日志：`build/soak/v10-synth-20261022-193018.log`
- 最终 summary（逐字）：

```text
T7.3 soak_summary mode=soak tag=v10-synth soak_loop=0 display=1920x1080
duration_s=7200.0 samples=242 steady=240 warmup_s=60 limit_mb=1200 pass=1
ws_start_mb=162.4 ws_final_mb=164.8 ws_max_mb=166.1 growth_mb=2.4
slope_mb_per_h=-0.01 baseline_blocks=24 baseline_growth_mb=2.4
baseline_slope_mb_per_h=0.16 private_max_mb=247.0 handles=691/675/712
threads=56/50/61 audio_underruns=0 loop_jumps=0 cache_max=0
frame_stall_events=0 playback_stopped_events=0 ui_gap_max_ms=212 flags=none
```

采样（每 30s 一次，取整点）：

| t_s | WS MB | private MB | handles | threads | frame | playing | underrun | ui_gap |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 166.1 | 247.0 | 712 | 61 | 0 | 1 | 0 | 0 |
| 1800 | 165.0 | 215.6 | 687 | 52 | 43156 | 1 | 0 | 207 |
| 3600 | 165.1 | 215.7 | 677 | 50 | 86313 | 1 | 0 | 206 |
| 5400 | 164.7 | 215.6 | 675 | 50 | 129469 | 1 | 0 | 212 |
| 7200 | 164.8 | 215.7 | 675 | 50 | 172626 | 1 | 0 | 207 |

判定：

- `pass=1`、`flags=none`；WS 峰值 166.1MB（P14 上限 1200MB），首末 +2.4MB；
  下包络 24 块、斜率 0.16MB/h（`memory_growth` 阈值 16MB/h），**无持续增长**。
- handles 691→675（峰值 712），threads 56→50（峰值 61），都在稳态回落后持平；
  `frame_stall_events=0`、`playback_stopped_events=0`、`audio_underruns=0`、
  `cache_max=0`；`ui_gap_max_ms=212`，远低于 2000ms 的浸泡 UI 冻结阈值。
- 启动时只有一条 `[h264] missing picture in access unit with size 692`（拼接
  边界），之后播放到末帧 172626，无其他解码/卡顿/设备错误。
- **结论：合成 V10 替身 P14 稳定性通过。** 不写“正式 V10 片单通过”/“P14
  正式通过”；V10 是重复内容拼接，内容多样性不等同正式片单。
