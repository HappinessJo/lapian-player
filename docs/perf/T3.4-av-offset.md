## 1. 估算口径

`MediaProbe` 在 VFR 采样时顺带记录第一条视频包和第一条音频包的 PTS，以及音频首包的 `AV_PKT_DATA_SKIP_SAMPLES`：

```
av_offset_us = audio_first_pts_us + priming_us - video_first_pts_us
priming_us   = skip_samples * 1e6 / sample_rate
```

- 只估一次，写入 `MediaInfo.av_offset_us`（`av_offset_estimated` 标记是否可用）。
- `AudioEngine` 起播时把视频目标时间加上该 offset 再 seek 音频，保证音频内容与视频目标同锚点。
- 波形（T3.5/T3.6）后续用同一个 offset 把 bucket 时间映射到帧格，不再重复估。

## 2. V9

`ffprobe` 原始数据：

- 视频首包 PTS `0.000000`；
- 音频首包 PTS `-0.021333`，首包带 `Skip Samples, 1024`；
- priming = 1024 / 48000 = 21.333ms；
- `av_offset_us = -21333 + 21333 - 0 = 0`。

`lapian_media_probe`：

```
HAS_AUDIO=1
AUDIO_RATE=48000
AV_OFFSET_US=0
AV_OFFSET_ESTIMATED=1
```

V9 click 校验（`lapian_audio_test` 解码 V9，找第 100 帧 ±1 帧窗口内峰值）：

- 峰值位于 **4.169s**；
- 第 100 帧时间 = 100 / 24 = **4.1667s**；
- 偏差 **2.3ms**，约 0.055 帧，≤1 帧。

代理样本 `proxy-V1` 的 offset 也是 0。

## 3. 非零 offset 的探测

用 FFmpeg 生成一个音频相对视频后移 100ms 的本地测试片（只在 `build/`，不入库）：

```powershell
ffmpeg -i media\V9.mp4 -itsoffset 0.1 -i media\V9.mp4 `
  -map 0:v:0 -map 1:a:0 -c copy -t 4.8 build\offset100.mp4
```

`lapian_media_probe` 输出 `AV_OFFSET_US=78000`（+78ms）。没有达到名义 100ms，是容器 copy/edit list 对首包时间戳的再量化；重要的是非零偏移被识别并会用于音频起播，而不是被当成 0。

## 5. 未完成 / 不宣称

1. **波形映射尚未实现**：T3.5/T3.6 才会把 offset 用于 bucket→frame 的绘制；当前只有数据钩子。
2. **正式 V1 未就位**：V9 是合成验收片，V1 真素材仍缺。
3. **offset 只来自首包/首个 skip samples**：不是完整 edit list 重建；复杂 MP4/MKV 的容器 delay 仍可能差几十 ms。
4. **动态偏移未做**：只估一次，运行中不补偿；符合 spec。
5. **10min/基线机未测**。
6. **synthetic 100ms 片实测 78ms**：只证明非零 offset 可被识别，不作为精度指标。
