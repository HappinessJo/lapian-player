# T5.4 截图测量记录

- **日期**：2026-10-20
- **范围**：`S` 当前帧 PNG、3 连拍不覆盖、播放中按键、90° display matrix、目录回退、焦点隔离、4K 路径与工作集
- **机器**：开发机 Windows 11 x64 / RTX 4060；**不是** 4C/8G/集显基线机
- **代码**：T5.4 代码提交 `01ad8dc`
- **自动化入口**：`--snapshot-test`（可配 `--file A --file-b B --snapshot-pictures <dir>`）
- **分发**：`dist` 32.21MB / 25 文件（P12 上限内）
- **单测**：`ctest` 17/17；`lapian_snapshot_naming_test` 覆盖命名/时间码/目录/旋转

## 1. 测试素材

| 素材 | 规格 | 用途 |
|---|---|---|
| `build\t5.4-snap\A.mp4` | `media\V9.mp4` 副本，1920×1080 H.264 24fps，120 帧/5s，AAC 48kHz | F6-A3/A4/A5、S 键、焦点、回退 |
| `build\t5.4-snap\B.mp4` | 同上，`ffmpeg -display_rotation 90 -i A -c copy`，存储 1920×1080 + display matrix 90 | 显示方向 1080×1920 |
| `build\t5.4-4k\K.mp4` | V9 放大到 3840×2160，H.264 24fps，120 帧（libx264 ultrafast） | 4K 回读/编码/播放不中断/P11 观察 |
| `build\t5.4-rotcheck\quad_rot.mp4` | 320×180 四色象限 + display matrix 90 | 旋转方向断言 |

V9 是 T0.2 的合成测试片（第 100 帧白闪），不是 spec §8 的正式 V9；B/K/quad 都是本地合成，**不是 V5/V4 正式素材**。素材只在 `build/` 与 `media/`，不入库。下面命令里的 `ffmpeg` 指仓库自带的 `third_party\tools\ffmpeg-gpl\bin\ffmpeg.exe`（也可用 PATH 中的等价版本）。

生成命令：

```powershell
# B：90° display matrix（不是物理旋转）
ffmpeg -y -display_rotation 90 -i .\media\V9.mp4 -c copy build\t5.4-snap\B.mp4

# K：4K 合成
ffmpeg -y -i .\media\V9.mp4 -vf "scale=3840:2160:flags=neighbor" `
  -c:v libx264 -preset ultrafast -crf 28 -pix_fmt yuv420p -c:a copy build\t5.4-4k\K.mp4

# quad：Pillow 画四色象限后用 ffmpeg 编码 5s/24fps，再加 display matrix 90
```

## 2. 自动化命令

```powershell
# 1080p + 90° B
$dir = Join-Path $PWD 'build\t5.4-snap'
New-Item -ItemType Directory -Path $dir -Force | Out-Null
Copy-Item '.\media\V9.mp4' (Join-Path $dir 'A.mp4')
ffmpeg -y -display_rotation 90 -i .\media\V9.mp4 -c copy (Join-Path $dir 'B.mp4')
$p = Start-Process -FilePath (Join-Path $PWD 'dist\lapian.exe') `
  -ArgumentList @('--file',(Join-Path $dir 'A.mp4'),'--file-b',(Join-Path $dir 'B.mp4'),'--snapshot-test') `
  -Wait -PassThru -RedirectStandardError (Join-Path $PWD 'build\t5.4-snapshot.log')
Write-Host "exit=$($p.ExitCode)"

# 4K
$p = Start-Process -FilePath (Join-Path $PWD 'dist\lapian.exe') `
  -ArgumentList @('--file',(Join-Path $PWD 'build\t5.4-4k\K.mp4'),'--snapshot-test') `
  -Wait -PassThru -RedirectStandardError (Join-Path $PWD 'build\t5.4-snapshot-4k.log')
Write-Host "exit=$($p.ExitCode)"
```

日志是 UTF-8；控制台 GBK 时用
`[System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes(path))` 读。

### 3.3 90° display matrix 与方向

`B_f100` 输出 1080×1920；四色象限样本输出 180×320，取样：

```text
top-left (0,255,0)      # 原右上绿
top-right (253,254,0)   # 原右下黄
bottom-left (252,0,0)   # 原左上红
bottom-right (0,0,253)  # 原左下蓝
```

这对应“源图逆时针旋转 90°”。证据图：[T5.4-rotated-90.png](T5.4-rotated-90.png)。

### 3.4 内容核对（V9 第 100 帧）

V9 第 100 帧是白闪；用 ffmpeg 单独抽出第 100 帧作参考：

```text
ref (1920, 1080) A (1920, 1080) B (1080, 1920)
A mean_abs_diff 2.0, extrema (253,253,253)
B mean_abs_diff 2.0, extrema (253,253,253)
```

- 截图内容与参考帧一致（纯白），差异来自 YUV→RGB/范围转换，不是 UI 或错帧。
- 由于该帧是纯白，不能用它区分构图/方向；方向由 §3.3 的四色象限样本单独验证。
- “无 UI”由源分辨率 + 直接 AVFrame 路径保证；没有用 `QWidget::grab()`（它抓不到 D3D11 原生 HWND）。

## 4. 口径与不宣称

1. **不是正式 V4/V5**：4K 与竖屏素材都是本地合成；没有真实 4K 参考片、VFR 手机录屏或基线机。
2. **不是真人验收**：F6-A3/A4/A5/A7 全部是自动化；`S` 是 `QKeyEvent`，不是物理键盘；播放连续性只断言“未暂停 + 保存帧号正确”，没有统计丢帧/音频 underrun。
3. **F6-A7 只跑同名文件阻塞**：验证了“主目录不可写 → 回退图片目录 → 提示 → 标记仍在”的逻辑；没有在 T5.4 重跑 ACL 只读目录，也没有写真实用户图片目录（自动化注入 `build/t5.4-snapshot-pictures`）。
4. **P11 不是正式数字**：工作集/峰值来自开发机 `GetProcessMemoryInfo`；没有 10min/2h soak。
5. **软解/10-bit 未测**：样本走 D3D11VA 硬解（`hardware=1`）；软件帧路径与 P010 10-bit 截图没有端到端证据。
6. **VFR 文件名时间码未单独验收**：按标称帧率生成 NDF 时间码；帧号仍是主键。
7. **拖动中按 S 不截图**：预览帧是降采样且可能不是目标帧，当前提示“松开后再截图”；这是实现边界，不是 spec 正式验收项。
8. **长 GOP F4-A2 未改善**：仍是 148–157ms，T7 处理。
