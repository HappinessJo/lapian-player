# T7.2.1 热修记录：B=末帧循环与 PgUp 画幅跳变（2026-10-20）

> 代码提交：`fe01648`。修复 F4-A1/A2 的末端循环失败，以及 T7.2 帧缓存命中后
> 硬解/软件帧画幅不一致。验收口径：spec §3.4 F4-A1/A2、§4.1 P7；这不是 V1/V10
> 正式验收，也没有替代用户物理鼠标/人眼复测。

## 1. 结论

- **B 在文件末帧时循环不再停住**：V9（B=119）5 秒内 **5 次** B→A；
  152s 1080p（B=4572）**6 次**；4K proxy（B=449）**6 次**。修复前 V9 只出现
  1 次 `loop_jump`，随后停在 B。
- **PgUp 画幅跳变根因确认**：1080p D3D11VA 纹理分配为 **1920×1088**，显示尺寸是
  **1920×1080**；旧渲染器用纹理尺寸做 fit，而 T7.2 缓存命中返回 1920×1080 的软件帧，
  于是 PgUp 时画幅比例变化。现在硬解帧只拷贝/使用 1920×1080 有效区域，缓存回拷前后
  渲染尺寸一致。
- `ctest` **20/20**（14.93s）；`dist` **32.49MB / 25 文件**。
- 自动化只证明尺寸/循环次数；**人眼画幅观感仍待用户复测**，不提前写成“用户验收通过”。

## 2. Bug 1：B=末帧不回 A

### 2.1 复现

`--loop-test` 在 V9 上会把 B=160 clamp 到 119（最后一帧）：

```powershell
dist\lapian.exe --file media\V9.mp4 --loop-test `
  --settings-path build\t7.2.1-loop-settings
```

修复前（T7.2 代码）：

- 10.3s 的 `after-3-loops` 仍是 `frame=119 playing=1 loop=1 a=100 b=119`；
- 整个 ~9s 播放只打印 **1 次** `loop_jump`；
- 时序日志在 B 附近出现 `pending B` 等 target、target 不再推进的停滞。

### 2.2 根因

B 不是末帧时，解码器还能吐出 B+1，`pending_frame_ > loop_out_` 会触发回 A。
B 是末帧时没有 B+1，只能等 `DecodeNextFrame` 返回 EOF；而 EOF 分支要求
`current_frame_ >= loop_out_`。如果音频时钟在 B 的 PTS 之前停住（音频先 EOF/
IAudioClock 停在音频末尾）：

1. `pending_pts_seconds_ > target` 让 Tick 每 5ms 直接 return，B 永远不“到点”；
2. `current_frame_` 不会更新到 B，EOF 分支也进不去；
3. 结果停在 B 附近，或者 `Finish()` 后看起来“播到终点就停了”。

### 2.3 修复

`src/app/PlaybackController.*`：

- 新增 `loop_out_reached_`：只要 `pending_frame_ >= loop_out_` 或 B 被 emit，
  就记录“B 已解到”；EOF 分支用 `loop_out_reached_ || current_frame_ >= B ||
  last_decoded_frame_ >= B`，不再要求 `current_frame_` 正好等于 B。
- 新增“一帧墙钟 + 余量”的 B 等待上限：
  `hold_ms = max(100, frame_duration / rate * 1.25 + 30)`。
  B 已解码但 target 不推进时，超过上限就先把 B 放进 `best_frame` 呈现，然后回 A。
  这样 0.25x 不会在 B 真正到点前提前跳走。
- 循环跳转失败不再直接 `Finish()`：最多重试 3 次；失败日志 `loop_jump_failed`。
- 新增 `LoopJumpCountForTest()`，用于回归确认“确实回了 A”，而不是停在 B。
- 新增 `--loop-end-test`：A=last-20、B=last，播放 5s 后断言
  `loop_jumps >= 3`、`playing=1`、`loop=1`、当前帧在范围内。

### 2.4 数字（最终 build，dist）

| 素材 | A / B | 5s 内 jumps | 最终状态 |
|---|---:|---:|---|
| V9 120 帧 | 99 / 119（末帧） | **5** | frame=106, playing=1, loop=1 |
| 1080p 152s | 4552 / 4572（末帧） | **6** | frame=4565, playing=1, loop=1 |
| 4K proxy 450 帧 | 429 / 449（末帧） | **6** | frame=436, playing=1, loop=1 |

- 现有 `--loop-test`（B=160，非末帧）：~9s 内 4 次 `loop_jump`，0 次
  `loop_end_hold`、0 次 `loop_jump_failed`；A=B 定帧 5s 保持仍通过。
- `LoopJumpCount` 是成功跳转计数；`loop_end_hold` 只在音频时钟停住时出现。

## 3. Bug 2：PgUp 画幅变大一点点

### 3.1 根因

`VideoRenderer::UploadHardwareFrame` 旧代码：

```cpp
source->GetDesc(&source_desc);
CreateTexture(source_desc.Width, source_desc.Height, ...);
video_width_ = source_desc.Width;   // 1920
video_height_ = source_desc.Height; // 1088
```

而软件帧路径用 `AVFrame.width/height`（1920×1080）。1080p H.264 的 D3D11VA
纹理按 16 对齐分配为 1920×1088；T7.2 后退步进命中缓存时返回 1920×1080 的软件帧，
fit 从 1920×1088 切到 1920×1080，所以看起来“画幅变大一点点”。4K 2160 能被 16
整除，通常不复现。

### 3.2 修复

- `UploadHardwareFrame` 用 `frame->width/height` 的**显示尺寸**创建目标纹理，
  并用 `D3D11_BOX{0,0,0,display_width,display_height,1}` 只拷贝有效区域；
  `video_width_/height_` 也用显示尺寸。
- 新增 `VideoRenderer::video_width()/video_height()` 回归 getter。
- `lapian_video_renderer_test`：
  - 断言渲染尺寸 == `AVFrame` 显示尺寸（不是纹理分配尺寸）；
  - 把同一帧写入 `FrameCache` 再取回、上传，断言缓存回拷前后渲染尺寸一致；
  - 新增 1080p 硬解素材和 4K/10-bit 回归。
- `lapian_frame_cache_test`：1080p 硬件帧回拷后 `hit->width/height` 必须是
  1920×1080，不是 1088。

### 3.3 证据

`lapian_video_renderer_test` 输出（开发机）：

```text
proxy-V1 硬解 frame=1920x1080 texture=1920x1088 renderer=1920x1080
1080p 硬解  frame=1920x1080 texture=1920x1088 renderer=1920x1080
proxy-V4 4K 硬解 frame=3840x2160 texture=3840x2160 renderer=3840x2160
10-bit 软解 frame=320x240 texture=0x0 renderer=320x240
[ OK ] ... 缓存回拷前后渲染尺寸一致
```

修复前的旧逻辑会得到 `renderer=1920x1088`，与软件帧 1920×1080 不一致。

## 5. 缺口 / 不宣称

1. **不是正式 V1/V10/V4**：V9、152s 1080p、450 帧 4K proxy；没有真实片单。
2. **没有用户物理复测**：自动化证明循环次数和渲染尺寸；PgUp 的画幅观感、
   真实 4K/VFR/HDR 仍要用户/ T7.7 复测。
3. **没有 0.25x 的 B=末帧长跑**：hold 公式按 `frame_duration/rate` 缩放，
   但本次只跑 1x 的 5s 回归；0.25x 的循环边界留 T7.4/T7.7 复测。
4. **没有 2h soak**：T7.3。
5. `loop_end_hold` 是“时钟停住”的兜底；如果 SeekToFrame 连续失败 3 次会
   `Finish()` 并走 `reachedEnd`，不会无限重试。真实损坏文件/设备丢失归 T7.5。
6. 不把本文写成 F4-A1/A2 正式验收、P7 通过、用户画幅验收或基线机结论。
