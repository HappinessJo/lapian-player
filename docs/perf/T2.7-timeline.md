# T2.7 时间轴渲染测量（2026-10-20）

- **状态**：开发机初步测量，**不是基线机验收**；正式 P 指标仍待 T7。
- **范围**：T2.7 时间轴渲染：帧刻度/标签、缩放、横向滚动、播放头、只画可见区。
- **代码**：`lapian_timeline`（`src/core/TimelineModel.*`、`src/app/TimelineWidget.*`）。
- **测试**：`build\release\Release\lapian_timeline_test.exe`（`ctest` 名称 `lapian_timeline_test`）。

## 1. 环境

| 项 | 值 |
|---|---|
| OS | Windows 11 x64 10.0.26200 |
| CPU/GPU | 开发机（RTX 4060，D3D11 FL 11_1）；**不是** 4C/8G/集显基线机 |
| 编译器 | VS2022 / MSVC 14.44 |
| Qt | 6.8.3 msvc2022_64 |
| CMake | 3.31.6 便携版 |

本机所有数字只用于开发期回归，不代替 `spec.md` §4.1 的 P1–P14 验收。

## 2. 方法

- 时间轴控件尺寸 **1920×72**，总帧数 **432000**（2 小时 @ 60fps）。
- 离屏 `QWidget::render` 到 `QImage`，包含背景、刻度、标签、播放头与横向滚动条。
- 预热 10 次后采样 200 次；取 p50/p95。
- 两个场景：
  1. **fit**：全片适配，当前帧 216000；
  2. **8px/帧 + scroll**：最大缩放，逐次切换当前帧触发播放头跟随与滚动重绘。
- 运行三次，表中给范围；单次 p95 受调度影响，但均远低于 16ms 门槛。

## 3. 结果

| 场景 | p50 | p95 | 16ms 门槛 |
|---|---:|---:|---|
| fit 432k | 0.155–0.164ms | 0.167–0.205ms | 通过 |
| 8px/帧 + scroll | 0.168–0.176ms | 0.214–0.227ms | 通过 |

代表性单次：

```text
[perf] fit 432k p50=0.160ms p95=0.168ms
[perf] 8px/frame + scroll p50=0.172ms p95=0.196ms
```

## 4. 视觉与交互检查

用 `media\proxy\proxy-V1.mp4`（720 帧）在真实窗口检查：

- fit：标签为帧号 `0, 50, 100, … 700`，播放头在第 600 帧；窗口信息栏仍显示 `帧 600`。
- 最大缩放：标签步进 10 帧，1 帧 = 8 逻辑像素；横向滚动条出现。
- 滚轮缩放锚点跟随鼠标；`+` / `-` 以播放头为锚点；播放中播放头跟随并保持在可见区。
- 点击滚动条空白区可翻页（260–410 → 420–570），当前帧与画面不变。
- `F2-A1` 的“任意单帧可点选”需要 T2.8 的点击命中，本次只验证帧号标签、8px/帧和可见区刻度。
- `F2-A8`：在帧 600 缩放/滚动后，信息栏仍为 600，画面不变。

## 5. 判读与限制

1. **时间轴重绘本身远低于 16ms**：43.2 万帧 fit 与最大缩放下 p95 均 <0.25ms，说明“只画可见区”的刻度生成没有退化为全片遍历。
2. 这是离屏 `QPainter` 数字，不含 Windows 窗口合成、真实字体光栅化和 DPI 缩放；真实窗口目视正常，但**不能当作基线机 P 指标**。
3. 未覆盖 200% DPI、4K 屏、真实 2 小时片单；这些留给 T6.4/T7.7。
4. T2.7 不解决同步索引打开耗时（T2.2 worker 缺口）和帧缓存（T2.4 缺口）。
