### 2.2 命令

```powershell
# 全量（约 195s）：20 次 P1/P2 + 40 样本 1080p 拖动 + 20 样本 4K 拖动
# + 40 步 × 2 + 60s 内存 + T7.5 + P12

# 快速调试（样本数不是 spec 口径，不能作为验收证据）
powershell -ExecutionPolicy Bypass -File scripts\bench-regression.ps1 -Quick -SkipBaseline

# 只跑部分套件
powershell -ExecutionPolicy Bypass -File scripts\bench-regression.ps1 `
  -Suites startup,drag1080,step1080,memory,robust,package

# 重新记录基线（只应在全量、干净负载下做）
powershell -ExecutionPolicy Bypass -File scripts\bench-regression.ps1 `
  -UpdateBaseline -BaselineLabel dev-2026-10-22

# 可选：只读 ACL（会 icacls /deny 再恢复）
powershell -ExecutionPolicy Bypass -File scripts\bench-regression.ps1 -IncludeReadonly

# 可选：软解诊断（exit 4，不冒充保证档）
powershell -ExecutionPolicy Bypass -File scripts\bench-regression.ps1 `
  -Suites drag1080 -AllowSoftwareDecode
```

输出：

- `build\bench\results\bench-<stamp>.json`（当次完整结果）
- `build\bench\results\bench-latest.json`（最新；注意跑过一次软解诊断会覆盖它）
- `build\bench\logs\<stamp>\<suite>.err.log`（产品 stderr，UTF-8）

退出码：`0` 通过；`1` spec 阈值失败；`2` 基础设施失败（超时/缺日志/进程异常）；
`3` 同机基线漂移超容差；`4` 仅诊断（软解/非保证档）。

## 3. 阈值与基线设计

### 3.1 阈值只来自 spec

`thresholds.json` 的每个小节都带 `spec` 字段：

| 小节 | 阈值 |
|---|---|
| startup | P1 ≤1500ms、P2 ≤2500ms；`pass_fraction=0.95`（20 次至少 19 次） |
| drag 1080p | P4 ≥30fps、P6 ≤150ms、P7 ≤80ms、P8 ≥12fps、P9 ≤200ms |
| drag 4K | P4 ≥20fps、P6 ≤300ms、P7 ≤150ms、P8 ≥12fps、P9 ≤300ms |
| step | P7 1080p ≤80ms、4K ≤150ms（后退/前进各 40 步 p95） |
| memory | P10 ≤250MB、P11 1080p ≤800MB、P11 4K ≤1536MB |
| robust | ≥75 项检查、0 失败、≤1 跳过、≤90s |
| package | P12 每个分发形态 ≤100MB（dist/setup/zip/stage 各自判断，不相加） |

`P6/P9` 的 2s 前提由 `--drag-test` 检查：`p9_prefix_max_frames` 必须 ≤
`ceil(2 × fps)`（proxy-V1 24fps → 48，实测 47；proxy-V4 30fps → 60，实测 53）。
`hw=1` 是保证档前提；`hw=0` 默认判失败，只有显式 `-AllowSoftwareDecode` 才降为诊断。

### 3.2 采样数与基线比较

- **P1/P2**：20 次；p95 用第 19 个排序样本（20 次至少 19 次达标）。
- **拖动**：1080p 用 40 样本（两倍于 spec 的 20，p95 更稳）；4K 用 20 样本
  （每次拖动成本更高，20 样本 p95 已稳定）。spec 的 20 样本口径仍由
  T7.4/T7.7 报告覆盖；40 样本只会更严格。
- **步进**：后退/前进各 40 步，p95 按 40 样本。
- **内存**：空态 5s、暂停 60s、1080p 播放 60s、4K 播放 15s（素材全长）。
- **基线漂移**：同一 `machine.id` 才比较；默认 `pct=10%`，每个指标另有
  `abs` 噪声下限（5ms/10MB/1fps 等）。`P9` 与步进用 **p50** 做漂移，
  因为 20/40 个随机目标的 p95 尾部在亚毫秒或 1080p 代理上会抖动；
  spec 门槛仍用 p95 硬判。`P6 1080p` 的 p95 在 50–59ms 间波动，
  基线比较给 10ms 下限。
- 基线 JSON 包含：机器 id、OS/CPU/RAM/GPU、exe SHA-256、素材 SHA-256、
  HEAD、`cache_state=hot`、73 个数值。换机时只做 spec 阈值检查，
  跳过漂移判定（会在结果里写 `machine_match=false`）。

## 7. 已知缺口 / 不宣称

1. **不是 T7.7 正式验收**：V1–V10、F1–F8、100–200% DPI、p95 20 次的正式
   片单报告仍待；本文只覆盖 1080p/4K 代理与 P1–P12 的一部分。
2. **不是冷缓存**：P1/P2 是热缓存；没有重启、RAMMap 或等效清理，
   不能写成 F1-A1 通过。
3. **不是基线机**：6C/12T + RTX 4060 + 31.6GB，强于 spec 的 4C/8GB/集显。
4. **素材是代理**：proxy-V1/proxy-V4，不是正式 V1/V4；4K 的 60fps/P6/P9
   不能外推到真实复杂内容。
5. **seek 后 PgUp 单样本（T7.9 已更正/修复）**：1080p **372.49ms** 是
   proxy-V1 10s GOP 的关键帧边界（目标 250 正好是关键帧），不属 2s GOP
   的 80ms 口径；4K **205.71ms** 是 2s GOP 的正常 seek 后单步，已由 T7.9
   seek handoff 修到 **0.06ms**。普通 seek 后单步与“目标为关键帧”的跨 GOP
   边界专项必须分开记录；详见 [T7.9](T7.9-p7-seek-handoff.md)。
6. **4K P7 尖峰仍在**：40 步后退 max 418–427ms（缓存重填/硬件回拷），
   p95 2.3–2.9ms 通过；不写成“4K 后退无卡顿”。
7. **P7 后退 p95 的基线漂移**用了 5ms 绝对下限：0.76→0.95ms、
   2.33→2.93ms 的相对差 25%，但绝对差 0.19/0.60ms；这是测量噪声，
   spec 的 80/150ms 门槛仍独立判定。
8. **T7.5 的缺口不变**：可达 SMB、物理设备丢失、真实 V8 未验；
   `-IncludeReadonly` 只做了 17/17 单独烟测，未计入本次 54 项。
9. **安装器缺口不变**：UI 英文、未签名、无图标；E: 需复制到 C: 才能装。
10. **不跑 V10 2h**：P14 仍用 `scripts\soak-bench.ps1 -File <V10> 
    -Seconds 7200 -NoLoop`；本脚本明确不把 90min/短时探针写成 P14。

### 8.2 维护规则

- **不要为了让回归变绿改阈值**；阈值只来自 spec。若 spec 版本记录改了口径，
  先改 `spec.md`，再同步 `thresholds.json`。
- 有意的性能改动（例如 T7.4 的缓存窗口）完成后，才用
  `-UpdateBaseline` 重写基线；更新前先确认全量 54 项通过、机器空闲。
- 换机时基线会自动跳过（`machine_match=false`），只做 spec 阈值检查；
