- **日期**：2026-10-20

## 1. 策略落点

| 行为 | 实现 |
|---|---|
| 步进/点击/拖动开始 | `TimelineWidget`/`GoToFrame` 先 `playback_->Pause()`；`OnPlaybackStateChanged(false)` 调 `audio_->Pause()` |
| 音频时钟 | `AudioEngine::Pause` 停流、失效 `clock_valid`，不推进媒体时钟 |
| 不在每步 seek 音频 | 步进只做视频 seek；音频保持暂停，直到恢复播放 |
| 恢复播放 | `PlaybackController::Play` 发一次 `stateChanged(true)`；MainWindow 调一次 `AudioEngine::PlayFrom(CurrentMediaSeconds())` |
| 防爆音 | `AudioEngine` 起播 5ms 淡入、暂停/切换 5ms 淡出（T3.3） |
| A=B 定帧 | **未实现**；A/B 本体在 T4.2，T3.7 不越界造循环 |

## 2. 自动化步进/恢复

`--step-test`：打开 V9、播放；1.2s 后步进一帧，1.8s 后恢复播放。

```powershell
$env:LAPIAN_TIMING_LOG='1'
$env:LAPIAN_AUDIO_LOG='1'
.\dist\lapian.exe .\media\V9.mp4 --play --step-test
```

日志关键段：

```
audio state=3 message=已暂停
audio start: target=1.167s rate=1.00x clock=wait
audio state=2 message=播放中
```

- 步进前最后一帧 `frame=27 target=1.1269`；
- 步进后音频 `已暂停`；
- 恢复时只有 **一次** `audio start`，target **1.167s**；
- 第 28 帧 PTS = 28 / 24 = **1.1667s**；target 偏差 **0.33ms**，≤1 帧；
- 恢复后 `sync_ms` 仍在 -0.33 ～ -9.33ms 范围，回到 `clock=audio`。

没有出现每一步一次 `audio start`，符合“不逐次 seek 音频”。

## 3. 拖动路径

代码路径：

- `OnScrubStarted` → `playback_->Pause()` → 音频暂停；
- `OnScrubTargetChanged` 只更新预览解码器，不碰音频；
- `OnScrubFinished` → `GoToFrame` 精确视频 seek，音频仍暂停；
- 用户再按 Space → `Play` → 一次 `PlayFrom(current)`。

**未做拖动过程的自动化音频日志**；本记录只验证步进路径。拖动与步进共用 `Pause`/`GoToFrame`，风险低但没有单独数字。
