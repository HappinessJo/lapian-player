# T3.3 变速与变调测量记录

- **日期**：2026-10-20
- **范围**：0.25–2x 变速、音高随速度、时钟速率、起播/切换淡入淡出
- **机器**：开发机 Windows 11 x64 / RTX 4060 / Realtek 默认输出；**不是** spec 的 4C/8G/集显基线机
- **代码**：T3.3 提交 `ecaeada`；构建 `scripts\build-release.ps1` 通过

## 1. 实现方式

- 音频重采样输出率 = `device_rate / rate`：
  - 1.0x → 48000 Hz
  - 2.0x → 24000 Hz（设备仍 48k 播放 → 时长减半、音高升高）
  - 0.5x → 96000 Hz
  - 0.25x → 192000 Hz
- 设备输出仍是 WASAPI shared mode 48k/2ch/float32；`IAudioClock` 位置按 `GetFrequency()`（本机 384000）换算墙上时间，再乘 rate 得到媒体时间。
- 变速时保持解码器/文件打开，只重建 swresample 输出格式，seek 到当前媒体位置后续播；切换前后各有 5ms 淡入/淡出，降低截断爆音。
- 视频继续按媒体时钟选帧；变速不 seek、不改帧号/时间码/当前帧。

## 2. 音频链路探针

命令：

```powershell
$env:LAPIAN_AUDIO_LOG='1'
.\build\release\bin\lapian_audio_probe.exe .\media\proxy\proxy-V1.mp4 3 --rate 2
.\build\release\bin\lapian_audio_probe.exe .\media\proxy\proxy-V1.mp4 3 --rate 0.5
.\build\release\bin\lapian_audio_probe.exe .\media\V9.mp4 2 --rate 0.25
```

| 场景 | 实际耗时 | 结束媒体位置 | 解码输出率 | underrun |
|---|---:|---:|---:|---:|
| proxy-V1 2x | 3.1s | 6.06s | 24 kHz | 0 |
| proxy-V1 0.5x | 3.1s | 1.52s | 96 kHz | 0 |
| V9 0.25x | 2.0s | 0.51s | 192 kHz | 0 |

- 2x 的实际媒体推进约为墙上时间的 2 倍；0.5x/0.25x 对应减半/四分之一。
- 三种倍率均无 underrun、无解码错误。

## 3. 1x / 2x 同步

`LAPIAN_TIMING_LOG=1`，`sync_ms = 呈现帧 PTS - 音频时钟`；测试片 `build/sync60.mp4`（24fps，60s）。

| 场景 | 墙上时长 | 帧数 | max | p95 | mean |
|---|---:|---:|---:|---:|---:|
| 1x | 60s | 1439 | 9.33ms | 4.68ms | 2.13ms |
| 2x | 约 32s | 1439 | **11.93ms** | **9.51ms** | 4.71ms |
| 0.5x（V9 5s） | 9s | 104 | 2.32ms | 2.31ms | — |

- 24fps 一帧 41.67ms；2x max 11.93ms ≈ 0.29 帧，p95 9.51ms。
- 2x 的最后一帧因音频先结束回退 `clock=qpc`，属预期；全程主体为 `clock=audio`。
- 0.5x 的 max/p95 都低于 3.3ms。
- 2x 60s 媒体在约 32s 内播完，帧号 0–1439 连续，未出现时间轴失真。

## 4. 实时切换

用 `[` / `]` 在播放中切换（`{]}` 经 WScript 发送）：

```
audio rate=1.00x
audio start: target=0.000s rate=1.00x
audio rate=1.25x
audio start: target=0.600s rate=1.25x
audio rate=1.50x
audio start: target=1.475s rate=1.50x
```

- 切换后从当前媒体位置续播，不回到开头；
- 切换期间视频短暂走 QPC，音频时钟恢复后切回；
- 60 个采样内 `sync max=16.67ms`，无解码/设备错误；
- 5ms 淡入/淡出已接；**未做人耳听感验收**。
