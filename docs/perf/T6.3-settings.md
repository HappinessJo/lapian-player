# T6.3 设置持久化测量记录

- **日期**：2026-10-20
- **范围**：spec §3.8 — 音量/波形跨会话、循环/速度仅会话、缺失/非法/损坏/无权限静默回退；F8-A1
- **机器**：开发机 Windows 11 x64 / RTX 4060 / 1920×1080 @100%；**不是** 4C/8G/集显基线机
- **代码**：T6.3 代码提交 `105dbcf`
- **单测**：`ctest` **18/18**（约 10.35s；新增 `lapian_app_settings_test`）
- **分发**：`dist` **32.31MB / 25 文件**（P12 上限内）
- **自动化入口**：`--settings-test`、`--settings-expect <volume> <waveform>`、`--settings-path <dir>`

## 1. 配置位置与格式

默认路径（`SettingsStore::DefaultRootDir()`，与 sidecar 回退的 AppData 父目录一致）：

```text
C:\Users\HappinessJo\AppData\Roaming\拉片软件\settings.json
```

- 不写注册表；实际路径由 `--settings-test` 的 `T6.3 settings_default_root` 日志确认。
- 格式为 UTF-8 JSON，带 `schema`；未知键忽略；未来 schema 整份回退默认：

```json
{"schema":1,"volume":55,"waveform":false}
```

- 文件大小 42 字节；原子写使用 `QSaveFile`（同目录临时文件 + 替换），失败保留旧文件。
- 只存 `volume` 与 `waveform`。`loop`、播放速度、静音、窗口几何、最近文件都不写入。

## 2. 读取与保存延迟

开发机、单次文件、`--settings-test` 内 20 次保存：

```text
T6.3 settings_load   load_ms=0.020–0.582（多次；最终重载 0.150）
T6.3 settings_save_perf n=20 p50=0.853ms p95=1.042ms max=1.042ms load_ms=0.023
```

- 读取在 UI 构造完成后、首个文件打开前同步执行；文件上限 64 KiB，超过按损坏回退，不读入内存。
- 保存去抖 250ms；关窗 `closeEvent` 与析构各 flush 一次，不进入 `SnapshotService::Drain` 的等待链。
- 这些是开发机数字，不是 P1/P2 冷启动验收；冷启动仍由 T7.1 测。

## 3. F8-A1 两进程验证

为覆盖“退出→重开”而不是同进程重载，把 `APPDATA` 重定向到工作区，使默认根落在
`build\t6.3-appdata-final\拉片软件`，再用两个独立进程：

```powershell
$appdata = Join-Path $PWD 'build\t6.3-appdata-final'
$env:APPDATA = $appdata
$root = Join-Path $appdata '拉片软件'
Start-Process dist\lapian.exe -ArgumentList @('--file',(Join-Path $PWD 'media\V9.mp4'),
  '--settings-test','--settings-path',$root) -Wait -PassThru
Start-Process dist\lapian.exe -ArgumentList @('--file',(Join-Path $PWD 'media\V9.mp4'),
  '--settings-expect','55','0','--settings-path',$root) -Wait -PassThru
```

结果：

```text

T6.3 settings_check final-reload-status ok=1
```

phase 1 的 `--settings-test` 还覆盖：

- 初始默认 100 / 波形开；未改设置时不产生文件；
- 改音量 37、关波形 → 保存 → 文件 JSON 字段正确；
- 只改音量 55 后走真实 `QCloseEvent`，关窗保存生效；
- `{not json` 损坏 → 默认值、状态 `corrupt`、不崩溃、不覆盖原文件；
- `volume=999` / `waveform="no"` / 未知键 → clamp 100 / 默认 true / 未知键忽略；
- `schema=2` → `unsupported_schema` 默认值；
- `settings.json` 被目录占用 → 读回退 `unreadable`，写返回 false、dirty 保留、不崩溃；
- 循环开 + 速度 1.5x 后保存，phase 2 仍是 `loop=0`、`speed=1`，证明循环/速度只本次会话。

phase 1 日志里有一次 `settings_save ok=0` 是“路径被目录占用”的预期失败用例，不是 F8-A1 失败；
其余保存均 `ok=1`。

## 4. 真实 `%APPDATA%` 路径

默认根解析为 `C:\Users\HappinessJo\AppData\Roaming\拉片软件`，读取已在真实用户目录验证：

```powershell
# PowerShell 写入 42/关波形（Medium IL）
$root = Join-Path $env:APPDATA '拉片软件'
# 应用读取默认根
dist\lapian.exe --file media\V9.mp4 --settings-expect 42 0 --settings-path $root
```

```text
T6.3 settings_load path=C:/Users/HappinessJo/AppData/Roaming/拉片软件/settings.json
  status=loaded volume=42 waveform=0
T6.3 settings_expect status=loaded volume=42 waveform=0 expected_volume=42 expected_waveform=0
exit=0
```

**真实 `%APPDATA%` 的写入未在本会话完成**：本会话直接启动的 `lapian.exe` / Qt 控制台测试进程是
Low 完整性级别（`S-1-16-4096`），`%APPDATA%` 为 Medium IL 保护目录；`CreateFileW` 返回 5、
`CreateDirectoryW` 返回 2。用 Medium IL 计划任务再测时，`cmd` 能写 `%APPDATA%`，但
`lapian.exe` 与 Qt 控制台测试仍被拒（同一任务、同一路径）。这说明是本会话执行环境对非系统
进程写用户配置目录的拦截，不是设置代码路径；F8-A1 的跨进程写入/恢复用上面的重定向
`APPDATA` 验证（默认根解析走同一 `qEnvironmentVariable("APPDATA")` 路径）。正式 F8-A1 仍需
在普通用户 shell/安装版手测一次。

## 6. 结论与不宣称

1. **F8-A1 的跨进程写入/恢复在重定向 `APPDATA` 下通过**；缺省、非法、损坏、未知键、未来
   schema、路径被占用与无权限（保存失败）都回退默认且不崩溃、不弹错误。
2. **只持久化音量/波形**：循环、速度、静音、窗口几何、最近文件都没有写入；phase 2 有断言。
3. **不是真实用户配置目录的写入验收**：本会话执行环境拒绝非系统进程写 `%APPDATA%`；真实默认
   路径的读取已通过，写入需普通用户 shell/安装版手测。
4. **不是冷启动/P1/P2 验收**：读配置 <1ms、上限 64 KiB；P1/P2 仍由 T7.1 在基线机测。
5. 设置文件损坏时不做 `.bak` 备份（MarkStore 的 sidecar 才做）；下次保存会覆盖，符合
   “损坏回退默认、不阻塞”的本任务口径，不在 spec 之外新增用户可见行为。
