60s 素材生成命令（**不是** spec V1/V4/V5）：

```powershell
ffmpeg -y -stream_loop 11 -i .\media\V9.mp4 -t 60 `
  -c:v libx264 -preset ultrafast -crf 28 -g 24 -keyint_min 24 -sc_threshold 0 `
  -pix_fmt yuv420p -c:a aac -b:a 64k build\t6.2-key\A.mp4
```

选 60s 是因为 V9（120 帧）的 fit 缩放已经超过 8px/帧上限，`+`/`-` 会被 clamp 成 no-op；120 帧无法验证缩放键。

### 3.2 焦点矩阵

同一套 `PgDn/→/Home` 在四个焦点位置都生效：

```text
focus-video-step ok=1
focus-tree ok=1
focus-tree-step ok=1
focus-tree-home ok=1
focus-slider ok=1
focus-slider-step ok=1
focus-none-step ok=1
```

- 视频（GfxWidget）、侧栏标记树、音量滑块、无焦点（`ClearFocusForTest`）都走 MainWindow 的事件过滤器。
- **取舍**：标记树的 Home/End/↑/↓/PgUp/PgDn 键盘导航让位给全局帧键（spec §3.7 只豁免文本框）。鼠标选择标记不受影响；`Delete` 仍是 MarkPanel 的 WidgetWithChildrenShortcut。若要恢复列表键盘导航，需要另立任务并改 spec 的焦点口径。

### 3.3 缩放键（避免 clamp 与双触发）

```text
T6.2 key_zoom ppf0=0.685 ppf1=0.856 ppf2=0.685 ppf3=0.856
```

- `Shift+Plus`：0.685→0.856（×1.25，单次触发）
- `-`：0.856→0.685（×0.8，单次触发）
- numpad `+`（无 Shift）：0.685→0.856
- 比例是单个缩放步长，说明事件过滤器与 QAction 没有双触发；`+`/`-` 的 QAction 快捷键已移除，统一走过滤器（兼容 `Key_Plus`、`Key_Equal+Shift`、numpad）。

### 3.4 长按与按键重复

```text
T6.2 key_hold start=50 after=53 autorepeat=53
T6.2 key_hold_2s steps=27
```

- 按下 450ms 后从 50 到 53（首次立即 + 300ms 后连发）；发送两次 `autoRepeat=true` 的 KeyPress，帧保持 53，不额外走帧。
- 继续按住 2s：50→77，共 27 帧，满足 T2.5/F3-A3 的“2s ≥20 帧”。
- 松手后定时器停止；再次发送 idle 自动重复也不走帧。
- 焦点切到音量滑块时连发停止（`focus-hold-stopped`），帧保持不变。

## 4. 结论与不宣称

1. **spec §3.7 的全表在自动化范围内通过**（除 Ctrl+O 原生文件对话框只验证映射）；文本框与模态对话框让位、OS 重复忽略、长按 2s 27 帧。
2. **不是真人键盘验收**：所有键都是程序化 `QKeyEvent`；中文输入法、AltGr、不同键盘布局/IME 抢占没有真人测试。`Ctrl+O` 的原生文件对话框也没有自动化。
3. **标记树键盘导航让位是明确取舍**：Home/End/方向键/PgUp/PgDn 全局帧键优先，鼠标选择与 Delete 仍可用。若用户要求列表键盘导航，需要重新定义焦点矩阵。
4. **不是基线机/DPI 验收**：开发机 1920×1080 @100%；150%/200% 与多显示器留给 T6.4。
5. **F7 没有编号 F7-A 条款**：验收就是 §3.7 表 + “文本框只留 Esc/Enter”两条行为定义；正式 F7 手测矩阵仍需按 tasks.md 做一次真人走查。
