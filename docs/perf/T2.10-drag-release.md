# T2.10 拖动集成与松手精确测量（2026-10-20）

- **状态**：开发机单样本 + 10s 合成拖动，**不是** T7.7 的 20 样本 p95 正式验收。
- **范围**：T2.10 拖动集成：预览取消、精确请求优先、松手落目标帧、保持暂停、10s 拖动 UI 停顿检查。
- **代码**：`MainWindow` 的 `OnScrubStarted/OnScrubTargetChanged/OnScrubFinished/OnPreviewTick`。
- **探针**：`LAPIAN_TIMING_LOG=1` 时，`OnScrubFinished` 输出 `release_exact_ms`；`OnPreviewTick` 超过 200ms 输出 `preview_tick_ms`。

## 1. 环境与素材

| 项 | 值 |
|---|---|
| OS | Windows 11 x64 10.0.26200 |
| CPU/GPU | 开发机（RTX 4060）；**不是** 4C/8G/集显基线机 |
| 1080p 短 GOP | `media\测试.mp4`，1920×1080，30fps，1s GOP，target 500 |
| 1080p 长 GOP | `media\proxy\proxy-V1.mp4`，1920×1080，24fps，长 GOP，target 499 |
| 4K | `media\proxy\proxy-V4.mp4`，3840×2160，30fps，2s GOP，target 299 |

## 2. 方法

- 用 `PostMessage` 向时间轴发送鼠标按下、若干移动、松开，模拟真实拖动。
- `release_exact_ms` 从松开事件进入 `OnScrubFinished` 开始，到 `GoToFrame` 返回（包含停止预览、精确 seek、`GfxWidget::SetVideoFrame` 上传）。
- 这是单次拖动样本，不等于 spec §4.1 的“20 次 p95”。
- P5：在 proxy-V1 上发送 10s 连续来回拖动（330 次目标更新），检查 `preview_tick_ms` 是否有 >200ms 记录。

## 3. 结果

| 场景 | 目标帧 | release_exact_ms | 口径 |
|---|---:|---:|---|
| 1080p 1s GOP | 500 | **17ms** | P6 1080p ≤150ms，单样本通过 |
| 4K 2s GOP | 299 | **257ms** | P6 4K ≤300ms，单样本通过 |
| 1080p 长 GOP（proxy-V1） | 499 | 351ms | 目标距前关键帧 >2s，按可用档，不计入 P6 保证档 |

10s 拖动（proxy-V1）：

- 330 次目标更新，10.0s；
- `preview_tick_ms` 无 >200ms 记录；
- 松手 sample：`release_exact_ms=10 frame=1`（最后目标回到首帧附近）。

## 4. 判读与限制

1. 1080p 1s GOP 与 4K 2s GOP 的单样本 P6 在开发机上通过；**正式 p95 仍需 V1/V4 + 基线机 20 样本**（T7.7）。
2. 长 GOP 的 351ms 是可用档样本，不能拿来宣称 P6 达标；与 spec 的方案 A 口径一致。
3. 10s 拖动没有记录到 >200ms 的预览 tick 停顿；这是 UI 线程探针，不是专业帧时间戳/ETW 测量，P5 正式验收仍待 T7。
4. 拖动预览使用 1280 长边降采样帧；松手后无条件走精确 `GoToFrame`，因此不会把预览帧当成落点。
5. **音频静音尚未接入**：当前没有音频引擎，T2.10 的“拖动/步进静音”由 T3.7 实现；不能声称 F3-A6/F5 静音已完成。
6. 高 DPI 150%/200%、4K 显示缩放、网络盘/只读素材未覆盖。
