# T3.1 音频解码与 WASAPI 测量记录

- **日期**：2026-10-20
- **范围**：第一条音轨解码、WASAPI shared mode 输出、音量/静音、无音轨与设备不可用降级
- **机器**：开发机 Windows 11 x64 / RTX 4060 / Realtek 默认输出；**不是** spec 的 4C/8G/集显基线机
- **代码**：T3.1 工作区；构建 `scripts\build-release.ps1` 通过

## 1. 设备与格式

`LAPIAN_AUDIO_LOG=1` 时，`lapian_audio_probe.exe` 输出：

```
audio device: 48000 Hz 2 ch float32 buffer=1056
audio decoder: aac 48000 Hz 1 ch
```

- WASAPI shared mode，默认 render endpoint；
- 设备混合格式 48 kHz / 2 ch / float32；
- `IAudioClient` 缓冲 1056 帧（约 22ms）；
- 解码输出统一为交错 float32，由 `swresample` 完成采样率/声道转换；
- 环形缓冲目标 80ms、上限 150ms。

## 2. 连续播放

命令：

```powershell
$env:LAPIAN_AUDIO_LOG='1'
.\build\release\bin\lapian_audio_probe.exe .\media\proxy\proxy-V1.mp4 10
```

结果：

| 场景 | 时长 | 结束位置 | underrun |
|---|---:|---:|---:|
| V9（5s，AAC 48k 单声道） | 4s | 4.05s | 0 |
| proxy-V1（30s，AAC 48k 单声道） | 10s | 10.12s | 0 |
| 测试片截取（2s，AAC 48k 立体声） | 2s | 2.00s（音频结束） | 0 |
| proxy-V1 `--seek 5` | 2s | 7.02s | 0 |

- 位置每 500ms 轮询一次，随播放时间推进；
- 10 秒连续播放无 underrun 日志，无 decoder 错误；
- 未把该表当作 P 指标；T3.1 没有音画同步验收。

## 3. 音量 / 静音 / 暂停 / 步进

开发机无法由 agent 听音，以下用 `LAPIAN_AUDIO_LOG=1` 的行为日志验证：

- 启动 `--play` 后按 `M`：`audio mute=1`；再按 `M`：`audio mute=0`；
- 启动后按 `Space`：`audio state=3 已暂停`；再按 `Space`：`audio start: target=0.708s`；
- 播放中按两次 `PgDn` 再按 `Space`：`audio state=3 已暂停` → `audio start: target=0.792s`；
- 静音 + 音量 25 运行 2s：无错误、0 underrun（音量曲线本身见单测）；
- 暂停/步进恢复播放时重新 seek 到当前帧 PTS，符合 T3.1 的“停止后重新起播”范围。

## 4. 无音轨 / 错误路径

用构建期 FFmpeg 工具从 V9 生成无音轨测试片（只在本机 `build/`，不入库、不分发）：

```powershell
ffmpeg -y -i media\V9.mp4 -an -c copy build\noaudio-V7.mp4
```

- `lapian_media_probe`：`HAS_AUDIO=0`；
- 应用打开该文件时不创建音频引擎，音频标签为“无音频”，视频正常播放；
- `lapian_audio_probe` 对该文件返回 `文件没有音频流`（探针直接打开音频引擎，属预期错误路径）；
- 不支持的音频编码会走“音频不可用”，视频仍可播放。
