# T7.3 长时稳定性（浸泡监测）测量记录（2026-10-21）

> 验收口径：[spec.md](../../spec.md) §4.1 P14（2h 1080p 连续播放，内存 ≤1.2GB、无持续增长、不崩溃/卡死）、
> §4.4；任务：[tasks.md](../../tasks.md) T7.3。
> 本文是**开发机、暖文件缓存**的短时探针：152s 1080p 代理整片 A/B 循环，
> 以及 1h34m 1080p 代理的单文件连续播放（90min）。
> **不是 V10 2h 素材、不是 P14 正式验收、不是基线机结论**。
> 正式结论留 T7.7；有 V10 后必须重跑 7200s。
>
> 原始日志（build 不入库，重跑即可再生）：`build\soak\probe1800-20261021-123534.log`、
> `build\soak\noaudio600-20261021-130917.log`、`build\soak\probe3600-*.log`、
> `build\soak\v10-1p5h-20261022-124648.log`。

## 1. 结论

- **90 分钟单文件连续播放 `pass=1`（关键新证据）**：`v10-1p5h`，1h34m
  1080p 素材、`--memory-no-loop`、播到 5400s：WS **150.9 → 153.1MB**（+2.1），
  最大 **155.7MB**，斜率 **1.22MB/h**；下包络 18 块 +4.1MB/1.91MB·h⁻¹；
  `loop_jumps=0`、cache 0、underrun 0、无帧停顿/UI 卡死。
- **对比：152s 短文件循环**在 30min/1h 出现 +18.2/+20.8MB 的失败；同样
  90 分钟、单文件连续播放只涨 +2.1MB。这强烈提示慢漂移主要来自**反复
  B→A seek/音频重启的循环路径**，不是“单文件连续播放”的通用泄漏。
- **但 1.5h 不是 V10 2h**：仍不能判 P14 通过；A/B 循环是产品核心场景
  （S2），循环路径的慢漂移仍是真实稳定性问题，需要单独收口。
- **循环路径历史数据（供对照）**：30min WS 107.8→126.1MB（+18.2，斜率
  30.49MB/h）、1h 105.6→126.4MB（+20.8，21.42MB/h）；下包络仍失败
  （30min +15.3/27.12MB·h⁻¹、1h +19.2/21.19MB·h⁻¹）。1h 的 t=2460
  （第 16 次 B→A）有持续 +7MB 台阶。
- **循环复测的差异**：30min audio +3.0、noaudio +7.4、35min +4.8 都 pass；
  但另一次 30min +18.2、1h +20.8 fail。音频 30min 全程 `playing`、无
  device lost/重连，说明不是每次音频循环必现。
- **不是崩溃/卡死/缓存泄漏**：所有长跑 `cache_entries=0`、
  `audio_underruns=0`、`frame_stall_events=0`、`playback_stopped=0`；
  句柄/线程稳定；UI 心跳最大 298ms。
- **回归**：`ctest 21/21`（17.23s）；`--key-test` 77 项 0 失败（2s 长按 27 帧）；
  `--loop-end-test` V9/1080p/4K 分别 5/6/6 次 B→A、`playing=1`；
  `--index-test` 12 项 0 失败；`--memory-test pause/play` 87.8 / 105.4MB。
  `dist` **32.52MB / 25 文件**。
- **不宣称**：不是 V10、不是 2h、不是 P14 通过、不是基线机/冷缓存。
  T7.3 的 P14 正式验收仍未做；当前只能写“90min 单文件连续播放有界，
  循环路径有慢漂移待收口”。

## 3. 方法

### 3.1 `--memory-mode soak`

```powershell
powershell -ExecutionPolicy Bypass -File scripts\soak-bench.ps1 `
  -File build\t7.2-media\test1080.mp4 -Seconds 1800 -Interval 30 -Tag probe1800
```

- 打开文件 → 等异步索引就绪 → A=0、B=last → 开循环 → 从 0 播放。
- 每 30s 采样：WS/private/peak/handles/线程数/帧号/playing/循环跳数/
  audio underrun/波形状态/帧缓存条目/UI 心跳间隔。
- 产品路径不变：异步索引、T7.2 缓存策略、T7.2.1 B 到达/显示尺寸都未改。
- **整片 A/B 循环**是为了让 152s 有限素材能持续播放；它不是“2h 单文件连续
  播放”，报告必须区分。
- **`--memory-no-loop`**：V10/1.5h 单文件用；不设 A/B，直接从头播放到
  `--memory-seconds`，summary 里 `soak_loop=0`、`loop_jumps=0`。

### 3.2 判定阈值

[`src/app/SoakStats.cpp`](../../src/app/SoakStats.cpp)：

| 项 | 口径 |
|---|---|
| 稳态窗口 | 2h 去前 60s；短时探针取 10%（最小 5s、最大 60s） |
| 内存上限 | 1080p 1200MB（P14 1.2GB）；4K 诊断用 1536MB |
| 持续增长 | 稳态样本按 **5 分钟分块取 WS 最小值**（下包络），对包络做最小二乘；包络斜率 >16MB/h **且** 首末包络增量 ≥12MB |
| 原始曲线 | 全窗口首末增量/斜率仍写入 summary（`growth_mb`/`slope_mb_per_h`），只做对照，不单独判失败 |
| 句柄/线程 | 末值 > 首值 +64 / +2 |
| 帧缓存 | 纯播放路径任何采样 `cache_entries > 0` |
| 播放中断 | 稳态采样 `playing=0` |
| 帧停顿 | 连续 ≥2 个采样窗口帧号不变且没有 B→A 回绕 |
| UI 卡死 | 心跳间隔 >2000ms；看门狗 10s 记录、30s `_Exit(6)` |

- 下包络的作用是忽略循环边界的瞬时分配尖峰；如果包络本身持续抬升，仍判增长。
- 斜率/增量门槛是“持续增长”的自动化口径，不是 P14 的替代；短时探针通过
  也不等于 2h 无增长。
- 音频 underrun 只记录，不判失败（设备恢复/拔出归 T7.5/T7.7）。

## 5. 慢漂移分析

1. **单文件连续播放 90min 基本平**：WS 150.9→153.1（+2.1），下包络
   +4.1/1.91MB·h⁻¹；没有 B→A，句柄/线程稳定，cache 0、underrun 0。
2. **循环版明显更差**：152s 短文件循环 30min/1h 出现 +18.2/+20.8MB，
   下包络 27/21MB·h⁻¹；而 90min 单文件只 +2.1MB。最合理的解释是——
   **慢漂移主要来自反复 B→A 的 seek/解码器 flush/音频重启路径**。
3. **但不是每循环必现**：循环复测里 30min audio +3.0、noaudio +7.4、
   35min +4.8 都 pass；一次 30min +18.2、1h +20.8 fail。运行间差异大，
   更像“某些 seek/驱动状态下抬升”，而不是固定每次漏一个对象。
4. **音频不是唯一原因**：`audio1800` 全程 `playing`、无 device lost/重连；
   无音频循环也涨。循环路径的其它环节（D3D11 解码表面池/堆）也要查。
5. **P14 结论**：单文件连续播放有界是好消息，但 1.5h ≠ V10 2h；正式 P14
   仍需 V10 7200s。循环路径的慢漂移是独立的产品稳定性问题（S2 循环拉片），
   不能因为 P14 单文件通过就忽略。
6. **下一步**：
   - 有 V10：跑 7200s `--memory-no-loop`，确认 2h 单文件平台化；
   - 循环路径：用同一 1.5h 文件只循环前 152s（需要 A/B 子区间选项）做对照，
     或加 D3D11 表面池/句柄计数，定位每次 B→A 的分配；
   - 不要在 T7.3 里用阈值掩盖循环路径的问题。

## 8. 缺口 / 不宣称

1. **没有 V10 2h 素材**：最长只有 1h34m 的 `测试2.mp4`；90min 单文件探针
   不是完整 2h。
2. **不是 P14**：90min 单文件 `pass=1`，但 1.5h ≠ 2h；循环版仍有慢漂移，
   P14 正式验收未做。
3. **不是基线机/冷缓存**：开发机 6C/12T + RTX 4060 + 32GB，暖文件缓存。
4. **没有 GPU 显存统计**：WS/private 只覆盖进程内存，D3D11 表面池未单独量化。
5. **没有设备恢复/拔出**：音频 underrun 0 只代表本轮设备正常。
6. **没有真实 V1/V4/V10、4K 长跑、0.25x 长跑**；归 T7.4/T7.7。
7. 不把本文写成 P14/V10/基线机/正式 P10/P11 通过。

## 9. 复现注意

- 用 `scripts\soak-bench.ps1`，不要直接 `Start-Process` 传中文路径；脚本会建
  ASCII 硬链接并做外部超时。
- 日志 UTF-8；Windows PowerShell 5.1 读日志用
  `[IO.File]::ReadAllBytes + [Text.Encoding]::UTF8.GetString`。
- 浸泡期间不要并行跑其他 GUI 回归，避免内存/线程/帧号采样被干扰。
- 30min/1h 的 `pass` 只代表自动阈值；`flags` 和 WS 曲线要一起看。
- 没有 V10 时，报告必须写“短时探针”，不能写 P14 通过。
