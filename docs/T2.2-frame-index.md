# T2.2 VFR 检测与 PTS 索引验证记录

- **日期**：2026-10-19
- **任务**：[tasks.md](../tasks.md) M2 / T2.2
- **状态**：PTS 索引核心、重复 PTS、关键帧索引、三态总帧数、解码校验/降级完成；后台 worker 与真实 V5 手机录屏待 T2.3/素材。
- **范围**：只 demux、不解码；包级 PTS + parser 计数校验；索引不可靠时只给“估算”，不冒充精确。

## 1. 实现

- `FrameIndex`（`src/media/FrameIndex.h/.cpp`）：
  - 每帧记录 `pts_us`（AV_TIME_BASE）与关键帧标志；按 PTS 升序排序；同一 PTS 只保留一帧（关键帧标志 OR）。
  - `PtsOfFrame` / `FrameOfPts`（最近帧）/ `FindExactPts` / `KeyframeAtOrBefore` 二分查找。
  - `Total()`：`Ready+Reliable` → 精确 `N`；不可靠 → `≈N`；未构建 → `—`。
  - `BuildFromFile`：打开容器、只读视频包、PTS 缺失计数；H.264/HEVC parser 计数（不保存 parser PTS）；`parsed_frames > packet_count` 时标记包内多帧、索引不可靠。
  - `BuildFromEntries`：单测/降级用；重复 PTS 去重。
  - `ValidateDecodedPts`：偏差 >1 帧计一次，连续 3 次标记不可靠并写 warning；T2.3 会调用。
- 关键取舍：**包级索引在包内多帧/缺 PTS 时不可靠，T2.3 必须降级为解码计数**；不拿近似帧冒充精确帧。
- 尚未接后台线程：`BuildFromFile` 是同步核心，T2.3/MediaSession 负责放 worker，避免阻塞首帧。

## 2. 验证

`lapian_frame_index_test`：

- 纯索引：乱序 + 重复 PTS 排序去重；`FrameOfPts(120)=2`、`FrameOfPts(150)` 取较近帧；精确/最近查找；`KeyframeAtOrBefore(150)=0`、`(200)=3`。
- 连续 3 次解码 PTS 偏差 → `IsReliable=false`，总帧数降级 `≈N`。
- V9：120 帧、索引可靠、总帧数精确、首帧关键帧、首/末帧 PTS 往返。
- proxy-V1：720 帧、索引可靠、总帧数精确。
- 合成 VFR（`build/test-media/vfr.mp4`，30→15fps 变化）：索引可靠、总帧数精确、帧间隔确实变化。
