```cpp
// 凭据（只存 SESSDATA，DPAPI 当前用户）

// nav / 会话状态
lapian::online::CheckNav(sessdata, IHttpClient*, cancel, timeout_ms = 2000)
    -> AuthResult { state, is_login, api_code, http_status, vip_status, elapsed_ms,
                    error, message, detail, request_cookie_sent }
lapian::online::BiliAuthSession session;
session.SetCredentialPresent(bool);  // true -> not_checked；false -> anonymous
session.BeginCheck();                // not_checked -> checking（只一次）
session.CompleteCheck(result);       // 成功 logged_in / 失败 login_unavailable（本会话缓存）
session.CancelCheck();               // checking -> not_checked（可重试）

// 显式 Cookie（T8.5 仍必须遵守）
HttpRequest request;
request.url = ...;                  // 只允许 https://api.bilibili.com:443

response.request_cookie_sent;       // 诊断，不含值
```

## 3. 关键决定与解释

1. **产品栈 = WinHTTP（T8.2 门）**：S2 的 `.NET HttpClient -101` 不适用于 WinHTTP；同一 SESSDATA 下 WinHTTP nav 通过。libcurl 未构建，T8.2 不引入 DLL/许可/体积；T8.16 再决定是否换栈。
2. **DEC-3 时机按“首次提交”实现**：用户打开对话框、保存/清除凭据、非法输入、本地模式都不发 nav；只有合法 BV/URL 首次提交时 `BeginCheck()` 一次，与 view 并行；失败/超时不阻塞 view（`nav` ≤2s，view 仍按 6s 上限）。会话缓存 `logged_in`/`login_unavailable`；取消中的检查回 `not_checked` 可重试；清除立即 `anonymous`。
3. **Cookie 只发 API**：`HttpRequest::sessdata` 只能由 nav 设置；客户端对非 `https://api.bilibili.com:443` 直接拒绝；不跟随重定向；禁用 cookie jar；view 不带 Cookie（`--online-auth-test` 断言）。
4. **隐私说明**：在线对话框显示（可隐藏），内容含联网时机/Cookie 用途/DPAPI 路径/清除方式/本地模式不联网；本地打开路径不创建该对话框。未把“首次”持久化到设置（每次应用会话首次打开在线对话框会显示，可手动隐藏）；若产品要求“一辈子只显示一次”，T8.16 再接到设置。
5. **环境陷阱**：默认 DSH 沙箱拒绝 Schannel 写 `%APPDATA%\Microsoft\Crypto`，导致 `SEC_E_NO_CREDENTIALS`；自检在 `danger-full-access` 下完成。普通桌面进程无此限制。不要把这个错误误判为 TLS 校验失败。

## 4. 已知缺口

1. **libcurl 未构建**：只有 WinHTTP 产品栈证据；`--http-stack=libcurl` 是 `not_built`。
2. **没有抓包/代理日志**：Cookie 只去 API 由客户端白名单 + 单测 + `cookie_sent=1` 证明；T8.5 取流阶段必须补抓包，证明 CDN 不带 Cookie。
3. **真实 nav 取消未测**：真实 nav 161–202ms；取消用 fake 阻塞 + 本地慢服务器覆盖（≤100ms）。
4. **412/429 只做 fixture**：未真实触发风控/限频。
5. **DPAPI 只验当前用户**：未做跨用户/漫游配置；内存明文只“尽力清零”，不是密码学擦除。
6. **隐私说明“首次”未持久化**：每个应用会话首次打开在线对话框显示；可隐藏。
7. **未改 ADR-007 评审记录**：T8.2 条件已满足，但 ADR 要求 T8.2 + T8.4 都通过后回填；T8.4 未完成，故保持“附条件接受”。
8. **T8.1 探针**：仍用 fake 的取消/关窗时序；真实 nav 由 `--online-http-selfcheck` 覆盖。

## 5. T8.3 / T8.5 需要什么

### T8.3（缓存）

- 缓存根/`meta.json`/`.part`→`.mp4` 不要持久化 SESSDATA、Cookie、签名 URL；`meta.json` 只放 bvid/cid/标题/UP/时长/qn/codecid/宽高/fps/字节/时间。
- 复用 `CredentialStore` 的“损坏按无凭据”模式；缓存损坏/磁盘满的错误文案不要带 Cookie。
- 日志仍走 host/path/status/elapsed；缓存路径/文件名不要带 SESSDATA。

### T8.5（取流）

- `playurl` 请求可以带 SESSDATA（仍只发 `api.bilibili.com`）；**CDN GET 必须不带 Cookie**，需要抓包/代理证据。
- 复用 `HttpRequest::sessdata` 的 host 白名单/重定向禁用；如果下载器另走 WinHTTP，必须复制同样的约束，不能把 Cookie 加到 CDN 请求。
- URL 过期/403 重试时不要打印签名 URL；日志只留 host/path/status/elapsed。
- 真实取消/超时要覆盖；nav 自检失败不能阻塞取流（当前已继续匿名）。
- `--online-http-selfcheck` 的 `stack=winhttp` 结果可作为 M1 的 HTTP 栈证据；若 T8.16 换 libcurl，必须重跑本门。
