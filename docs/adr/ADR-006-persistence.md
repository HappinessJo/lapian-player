# ADR-006 标记与备注持久化

- **状态**：已接受（2026-10-19 按推荐确认；实现中若证据变化，按“重新考虑条件”修订）
- **日期**：2026-10-19
- **决策范围**：标记/备注存哪里、什么格式、只读目录与多实例怎么办
- **相关**：`plan.md` §3.6、§7 R11；`spec.md` §3.6、§3.8

## 背景

spec 要求：标记与备注“和视频文件关联保存”，重开同一文件恢复；没有标记/备注的文件不产生附属文件；视频移动/重命名后不保证恢复；截图有 `snapshots/` 与图片目录回退，但标记没有回退；零项目、零联网、不修改源视频。归档素材、网络盘、只读目录很常见，必须定义写失败行为，否则 F6/F8 无法验收。

## 决策

1. **默认 sidecar**：视频同目录 `<视频名>.lapian.json`，UTF-8，带 `schema` 版本；内容含视频标识（规范化路径、大小、时长）、marks 数组（id、frame、pts、label、note、created_at、updated_at）。
2. **原子写**：写同目录临时文件 → flush → `ReplaceFile`/rename；失败不破坏旧文件；损坏 JSON 备份为 `.bak` 并提示，不阻塞打开。
3. **只读回退**：源目录不可写时写 `%APPDATA%\拉片软件\marks\<规范化路径哈希>.json`；UI 显示实际存储位置；下次若源目录可写，迁移回 sidecar。
4. **合并**：打开时若 sidecar 与 AppData 同时存在，按 mark `id` 合并，冲突取 `updated_at` 较新者；保存到当前规范位置。
5. **空文件清理**：最后一个标记删除后删除 sidecar/AppData 文件，满足 F6-A6。
6. **VFR 双键**：存 `frame` 与 `pts`；重开优先按 frame，PTS 校验不一致时提示“帧号可能变化”，按 PTS 校正。
7. **不做**：不写视频元数据、不建 SQLite/媒体库、不做最近文件、不做跨进程锁（首期）、不做导出。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 统一 `%APPDATA%` 数据库 | 否 | 用户换机/移动素材带不走；不符合“附属数据”直觉；首期过重 |
| 写入视频文件元数据 | 否 | 违反只读；容器/编码差异大；风险高 |
| 仅 sidecar，无回退 | 否 | 只读/网络盘直接丢标记；F6-A7 类场景无解 |
| 仅 AppData，无 sidecar | 否 | 用户无法随素材带走；路径哈希在移动后失效 |
| sidecar + AppData 回退（本决策） | 是 | 便携 + 只读兜底；格式简单可审 |

## 为什么这样选

- **符合产品语义**：标记是“这条片子的附属数据”，不是工程；sidecar 最直观，复制/备份素材时能一起带走。
- **不修改源视频**：独立文件，满足只读。
- **只读场景可活**：AppData 回退保证归档盘/网络盘也能记录；UI 明确告知位置，避免“以为存了”。
- **可恢复**：原子写 + 损坏备份 + 按 id 合并，比“直接覆盖”安全。

## 后果

- 正面：F6-A1/A2/A6、F8-A2/A3 可实现；用户可读可迁移；零数据库。
- 负面：视频目录会多出 `.lapian.json`（用户可能不喜欢）；只读回退后换机不同步；多实例可能分叉（合并缓解，但不完全）。
- 风险：路径大小写/短路径/UNC 规范化不一致导致哈希不同；网络盘延迟导致保存慢；中文/长路径写入失败。

## 重新考虑的条件

- 用户明确反对在素材目录产生 sidecar，要求统一 AppData/数据库。
- 首期之后做多文件/媒体库/标记导出，需要索引与批量迁移。
- 多实例写冲突变成真实问题，需要文件锁或单实例。
- 需要跨设备同步（会引入账号/网络，属于候选池，需另立 ADR）。
