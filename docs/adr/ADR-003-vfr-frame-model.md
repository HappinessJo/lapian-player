# ADR-003 VFR 帧模型与索引

- **状态**：已接受（2026-10-19 按推荐确认；实现中若证据变化，按“重新考虑条件”修订）
- **日期**：2026-10-19
- **决策范围**：帧的定义、VFR 帧号↔时间戳、时间轴几何、总帧数、时间码
- **相关**：`plan.md` §5；`docs/spec-v0.3-delta.md`

## 背景

spec 已拍板：0 基“显示帧序号”；CFR 精确；VFR 按显示帧计数并提示；时间码辅助。但没有定义 VFR 下帧号如何映射到 PTS、时间轴是否等距、总帧数未知时怎么办、`HH:MM:SS:FF` 在 23.976/VFR 下怎么算。手机录屏（V5）是典型 VFR，且可能带旋转元数据；如果按“平均帧率”处理，帧号会漂移，违反“帧准确不可妥协”。

## 决策

1. **帧号 = 解码器按呈现顺序输出的第 N 个可显示帧**；同一 PTS 的重复输出只计一次。
2. **时间轴在 CFR 与 VFR 下都用等距帧格**（1 帧 1 格）；VFR 的“按实际时间戳对齐”落在波形取样区间 `[PTS_N, PTS_{N+1})`，不让帧格宽度变化。
3. **VFR 用后台 PTS 索引**：只 demux、不解码，记录每帧 PTS 与关键帧标志；按 PTS 升序排序、同一 PTS 只保留一帧；`FrameOf/PtsOf` 二分查找；包内多帧用 parser 拆分。
4. **总帧数三态**：精确（`nb_frames`/索引完成）、估算（时长×帧率）、扫描中；UI 分别显示 `N`、`≈N`、`扫描中`；End/越界 clamp 以当前最可靠值为准，索引完成后校正。
5. **时间码**：CFR 用 NDF（FF = N mod 标称帧率；23.976→24、29.97→30、59.94→60）；VFR 由 PTS 换算、仅显示；VFR 输入时间码按“最接近该时间的帧”定位。
6. **VFR 首次远跳**允许先按平均帧率估算再校正，但最终必须落到精确帧；P9 对 VFR 改为“索引就绪后 ≤200ms、首次远跳 ≤2s”，CFR 维持 200ms。
7. **索引校验**：解码 PTS 与索引连续 3 次偏差 >1 帧 → 标记不可靠，后台重建；重建期降级“解码计数”模式（慢但精确），UI 提示。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 时间比例轴（帧格宽度 = 实际时长） | 否 | “1 帧 ≥8px”在长短帧上含义不同；点击命中/缩放/虚拟化都变复杂；长片最大缩放不可行 |
| 只按解码顺序逐帧数，不建索引 | 否 | 任意帧 N 要解 N 帧，2h/P9 不可能；无法显示总帧数 |
| 按平均帧率把 VFR 当 CFR | 否 | 帧号会漂移，违反帧准确；V5 直接失败 |
| 拒绝 VFR / 只提示不支持 | 否 | spec F2-A7 要求可逐帧；V5 是验收片 |
| 等距帧格 + PTS 索引（本决策） | 是 | 保住帧号/8px/输入定位；VFR 只在波形取样上体现真实时间 |

## 为什么这样选

- 产品的差异化是“帧号可直接读、直接输入”，不是“时间轴比例精确”。等距帧格让帧号、点击、缩放、8px 下限都简单可验收。
- VFR 的“真实时间”仍然保留在 PTS 索引与波形 bucket 里，卡点对齐不受影响。
- 索引只 demux，成本远低于全片解码；首次远跳的 2s 例外是诚实的物理约束，不牺牲落点精度。

## 后果

- 正面：F2-A2/A5/A6/A7 可写死；VFR 可精确步进；时间轴虚拟化简单。
- 负面：VFR 时间轴不是“真实时间比例”，用户可能误以为格子等时；需要 UI 标注“VFR / 时间码辅助”；首次远跳可能等待。
- 风险：包数 ≠ 帧数时索引不可靠，需要校验与降级；降级模式远跳会慢；旋转元数据未定义（见 plan §10）。

## 重新考虑的条件

- 真实 VFR 素材（V5 及更多手机录屏）索引校验频繁失败，说明 packet-PTS 索引不可行，需要改为解码建索引（会影响 P2/P9）。
- 用户明确要求 VFR 时间比例轴，且接受 1 帧 <8px/点击语义变化——这是产品决策，不是实现细节。
- 出现需要 drop-frame 时间码或 24 小时以上素材的需求。
- 首期之后要做多轨/多文件，帧索引需要跨文件抽象。
