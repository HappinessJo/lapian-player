# ADR-004 依赖、许可与分发

- **状态**：已接受（2026-10-19 按推荐确认；实现中若证据变化，按“重新考虑条件”修订）
- **日期**：2026-10-19
- **2026-10-27 修订**：项目**自身**许可证由 GPL-3.0 改为 **MIT**（第三方组件仍按各自许可；
  已发布的 v0.1.0 及更早版本为 GPL-3.0，授权无法撤回）。本 ADR 其余依赖/许可红线不变。
- **决策范围**：技术栈、第三方依赖、许可红线、安装/便携形态
- **相关**：`plan.md` §2.1、§4.4；`ADR-001`

## 背景

首期硬约束同时包括：Windows 10/11 x64、分发 ≤100MB、空闲 ≤250MB、冷启动 ≤1.5s、运行期零网络、双击已关联文件可打开、H.264/H.265 8-bit SDR 为保证档。技术栈必须同时满足体积、启动、内存、帧级控制与许可合规；任一项选错，后面用优化补不回来。

## 决策

1. **语言/构建**：C++20 + CMake + MSVC 2022（v143），x64 Release。
2. **UI**：Qt 6 Widgets，只链接 Core/Gui/Widgets；不用 QML、Qt Quick、Qt Multimedia、WebEngine。
3. **解码**：FFmpeg 7.x，**LGPL 2.1+、动态链接、最小构建**；只保留 file 协议、解封装、H.264/H.265/VP9/AV1 解码、AAC/MP3/Opus/PCM 解码、swscale、swresample；禁用网络、编码器、非必要滤镜/设备。
4. **平台 API**：D3D11/DXGI/D3D11VA、WASAPI、WIC 全部来自 Windows SDK；不引入额外渲染/音频库。
5. **许可红线**：不引入 GPL/AGPL 组件；不静态链接 LGPL 库；随包附 FFmpeg/Qt 许可文本与源码获取说明；HEVC/H.264 专利许可按“随包分发、不额外付费”处理，并在发布说明中记录风险。
6. **分发**：Inno Setup 安装包（每用户安装，注册 ProgID/文件关联，卸载清理）+ 可选便携 zip；运行期不联网、不检查更新。
7. **构建期**允许联网拉依赖；**运行期零请求**，T0.1 用 ProcMon 验证。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| C#/.NET 8 + WPF | 否 | 自包含体积接近/超过 100MB；启动与内存不如 C++；D3D11 互操作开销 |
| Electron + WebCodecs | 否 | 包体/内存/冷启动三项同时超标；VFR 与精确 seek 控制弱 |
| Rust + egui/winit | 否 | 可行但 UI 成熟度/中文输入/高 DPI/文件对话框成本高；首期时间不划算 |
| Media Foundation 单栈 | 否 | HEVC 系统扩展不确定；VFR/索引/精确 PTS 控制不足 |
| Qt + FFmpeg 静态链接 | 否 | LGPL 合规复杂；体积未必更小；更新困难 |
| 纯 Win32 + D3D11（无 Qt） | 否 | 体积最优，但时间轴/文本编辑/焦点/高 DPI 开发量过大 |

## 为什么这样选

- **P12/P1/P10**：Qt Widgets + 最小 FFmpeg 是少数能同时压到 100MB 内、启动 <1.5s、空闲 <250MB 的组合；Electron/.NET 自包含都更危险。
- **帧控制**：FFmpeg 提供 PTS/关键帧/硬件帧，Qt 只做 UI，不与播放引擎争控制权。
- **许可**：LGPL 动态链接 + 自有代码闭源可分；GPL 会污染整个分发。
- **交付**：Inno Setup 足够小，能注册关联与卸载；便携 zip 满足不想安装的用户。

## 后果

- 正面：体积/启动/内存可控；帧级能力完整；许可边界清晰。
- 负面：需要维护 FFmpeg 最小构建脚本与许可清单；Qt LGPL 动态链接需要随包 DLL 与许可；HEVC 专利风险仍在。
- 风险：FFmpeg 最小构建若漏了某编码/容器，V3/V4/V5 可能失败；Qt 插件裁剪过度会影响高 DPI/文件对话框；安装器关联需要用户确认默认应用。

## 重新考虑的条件

- 实测 P12 仍 >100MB，且裁剪无法解决——需要重新评估 Qt 或 FFmpeg 构建。
- HEVC/H.264 专利许可要求改变分发方式（例如必须由系统解码）。
- Qt 许可条款/商业授权变化，或团队决定闭源静态链接。
- 首期之后要做 macOS/Linux（当前架构不为跨平台抽象买单）。
