### 0.2 明确不写进 MVP 验收的档位

以下档位**不得成为 M1/M2 的通过条件，也不得写成 MVP 验收**；但按 **B（2026-10-23 拍板）** 可作为独立的“大会员可用档”条件验收（O11，非 MVP 门）：

- **1080P60 / 720P60**：普通用户（非大会员）不可得；S2 已实测 1080P60 不可得。大会员若可达，按 O11 条件验收。
- **4K（qn=120）**：普通用户不可得；只存在于大会员侧，未实测。即使凭据可达，也只按 v0.3 §4.2 的“可用档”处理：能播则播，不保证性能与颜色。
- **HDR / 10-bit 颜色正确**：沿用 v0.3 的不保证口径；4K HDR 也不因 B 变成承诺。
- **付费 / DRM / 地区限制内容**：不做、不测“如何拿到”；只测“如何给出可读拒绝”。

**允许**出现 60fps 的验收项有两条：**O6 降帧提示必须可见**（验收“提示正确”，不是“拿到 60fps”）与 **O11 大会员 1080P60 条件验收**（只有真 60fps、有大会员账号时才执行；无账号则标“未验证”，不宣称通过）。

### 0.3 与 v0.3 的关系

- v0.3 的 F1–F8、P1–P14、§4.2 支持范围、§4.4 稳定性、§4.5 轻量化对**本地模式**继续有效。
- 本文件新增的 O/OP 条款只对**在线模式**有效；同一交互（如 PgUp/PgDn）在两种模式下语义相同，但性能承诺不同（在线只看已缓存区）。
- 本轮**不动 `spec.md` §9**。v0.3 中“首期零网络 / 不做 B 站”的表述，按 §7 做“模式限定”的解释记录；等 v2 验收稳定、用户决定合并 v1.0 时，再统一写 `spec.md` §9 版本记录。这是对 [spec-versioning.md](spec-versioning.md) §2 规则 2 的**有意暂缓**：S3 已拍板但尚未合并 v1.0，提前改 §9 会让 v0.3 看起来已经接受 v1.0。

## 1. 模式、术语与不变量

### 1.1 两种模式

| 项 | 本地模式（v1） | 在线模式（v2） |
|---|---|---|
| 输入 | `Ctrl+O` / 拖拽 / 文件关联 | BV 号 / B 站视频 URL（用户主动提交） |
| 数据 | 本地文件，随机可读 | 网络边下边缓存；已缓存区随机可读 |
| 网络 | **运行期零网络请求** | 仅在用户提交 BV 后联网；无后台预取其他视频 |
| 帧精确 | 全片 | **仅已缓存区间**；未缓存区等待，不承诺 80ms |
| 波形 | 全片后台生成 | 随音频缓存渐进生成 |
| 记录 | 源文件旁 sidecar | `%APPDATA%` 在线记录（按 bvid+cid） |
| 验收依据 | `spec.md` v0.3 | 本文件 |

### 1.2 在线会话

“在线会话”指从用户提交 BV/URL 到关闭该视频（或打开另一个视频）的整个过程。包含：

1. 解析（view）→ 用户确认标题/时长/分P；
2. 取流（playurl）→ 选档；
3. 缓存记录建立 → 下载；
4. 达到起播阈值 → 首帧呈现；
5. 播放 / 已缓存区操作 / 未缓存区等待；
6. 关闭（保留 `.part` 以便续传）或缓存完成（`.part` → `.mp4`）。

**缓存命中**时跳过 1–4 的联网部分，直接按本地文件路径打开（仍显示在线来源信息）。

### 1.3 不变量（在线模式不得破坏）

1. **本地模式零网络、能力不退化**：F1–F8 全量保留，P1/P2/P7/P10/P11 不退化（O9）。
2. **在线只在用户主动提交 BV/URL 后联网**；启动、本地打开、设置、标记、截图、关闭都不联网；不做后台预取其他视频、不做遥测/更新检查。
3. **不修改源视频；缓存只在本地**；不提供导出/分享/把缓存当视频文件另作他用的入口。
4. **帧号仍是“显示帧序号”，0 基**。在线帧号只对**当前流**（bvid + cid + qn + codecid + 实际 fps）成立；换档位/换编码后帧号不保证一致，必须提示（O6）。
5. **P7/P9 只承诺已缓存区间**；未缓存区只承诺“显示缓冲状态、可取消、取到后落点误差 0”，不承诺毫秒数。
6. **不绕过**：无凭据不取付费内容；不做地区伪装/代理骗地域；不做账号轮换/共享；不批量抓取；不再分发。
7. **不做账号体系**：只支持用户自带的 SESSDATA（可选），不做扫码/多账号/云同步。
8. **4K / 1080P60 不是 MVP 验收项**（§0.2）；B 另做 O11 条件验收，不进 M1/M2 门。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 缓存记录 | 一条在线视频在本地的元数据 + 数据文件；键为 `bvid + cid + qn + codecid` |
| 已缓存区间 | 从文件起点到“已下载字节”的连续前缀（MVP 顺序下载，无空洞） |
| 缓存边界 | 已缓存区间的末尾字节/时间位置 |
| 缓冲中 | 读层阻塞在未缓存字节上，UI 明确显示的状态；不是“卡死” |
| 档位 | `qn`（清晰度）+ `codecid`（编码）的组合；同一 qn 可能有 AVC/HEVC/AV1 |
| 实际流帧率 | playurl 返回/容器实测的当前流 fps（如 29.412）；不是标题宣称的源帧率 |
| 源帧率 | 源片标称帧率（如 60fps）；在线模式**可能拿不到**，只能提示“可能降帧” |
| 降帧副本 | 60fps 源在无 60fps 权限时拿到的约 29.4fps 流；S2 一条样本实测精确 2:1 |
| 缓存命中 | 该 bvid+cid+档位已完整缓存，打开时零网络 |
| 在线记录 | 在线模式的标记/备注/截图清单，存 `%APPDATA%` / 图片目录，不随缓存清空而丢失 |

### 1.5 在线状态机（UI 必须能区分）

| 状态 | 触发 | UI | 可执行操作 |
|---|---|---|---|
| `Idle` | 未输入 | 空态 + BV 输入框 | 输入、粘贴 |
| `Resolving` | 提交 BV/URL | “解析中…” | 取消 |
| `Confirming` | view 成功 | 标题/UP/时长/分P/清晰度候选 + “开始” | 确认、换分P、取消 |
| `Preparing` | playurl 成功，建缓存 | “准备缓存…” | 取消 |
| `Buffering` | 未达起播阈值 | “缓冲中 x%（约 y s）” | 取消 |
| `Ready` | 首帧已呈现 | 正常播放器 UI；离线来源标识 | v1 全部操作 |
| `Stalled` | 播放中缓冲区耗尽 | 自动暂停 + “缓冲中”；画面保持 | 取消、重试 |
| `SeekingWait` | seek 到未缓存区 | “缓冲中（目标帧 N）”；已缓存画面保持 | 取消、改 seek |
| `Recovering` | 断网/URL 过期/重试 | “网络中断，重试中…” | 重试、继续看已缓存 |
| `Error` | 不可恢复 | 可读原因 + 下一步 | 重试、换 BV、清缓存 |
| `Closed` | 关窗/换片 | 保存记录、停止下载、保留 `.part` | — |

> 任何状态下 UI 线程不得等待网络/解码；状态切换 ≤100ms 可见（DEC-2 已拍板）。

## 2. 在线功能验收

### 2.1 O1 输入与解析

**行为定义**

- 接受：`BV` 开头的 12 位 BV 号；`https://www.bilibili.com/video/BV...`（可带 `?p=`）。不接受搜索词、短链、`av` 号（未验证，不做承诺）。
- **本地先校验**：长度/字符集不合法不发请求；错误在 100ms 内显示。
- `view` 取：标题、UP 主、时长、分P 列表（cid/标题/时长）。封面不要求。
- **必须回显标题/时长/UP 主让用户确认后再取流**：BV 校验位有效可能命中另一条视频（S2 实测末位改动即命中别的视频）。
- 多P：默认 P1；必须可切换；切P后 cid/时长/清晰度候选随之更新。
- 未登录仍可解析；提示“未登录，清晰度受限”。
- 失败码映射见 §5；不静默重试到成功、不猜测用户意图。

**验收标准**

- **O1-A1** 输入有效公开 BV：5s 内显示标题、UP 主、时长、分P；**不自动取流、不自动播放**。
- **O1-A2** 输入 `BV1`、少一位、含非法字符、空串：≤100ms 本地可读错误；**本操作 0 网络请求**（抓包/日志证明；DEC-3 已拍板为“首次在线打开自检”，只计本操作新增请求）。
- **O1-A3** 输入带 `?p=2` 的 URL：默认选中 P2；cid、时长与 view 一致；可直接确认。
- **O1-A4** 输入 S2 的“末位改动”样本：显示**实际标题/时长**；用户必须确认；不得只凭输入就播放。
- **O1-A5** `-400` / `-404` / `62002`：5s 内可读原因与下一步；进程不退出、不冻结。
- **O1-A6** 未配置 Cookie：解析成功，并显示“未登录，清晰度受限”提示。
- **O1-A7** 解析中取消/关窗：≤100ms 放弃；无残留请求/线程（DEC-2 已拍板）。

### 2.2 O2 起播与缓冲

**行为定义**

- 起播阈值以 S2 实测为准：**约 0.16–0.3MB** 可让 `avformat` 完成 probe 并出首帧；实际值随容器/码率变化，不写死。
- 首帧呈现前，UI 必须显示解析/准备/缓冲状态；超过 1s 必须有可见进度，不得白屏。
- **“起播”定义**：从用户确认到**首帧呈现且 UI 可交互**。默认仍停在第 0 帧、不自动播放（沿用 v1 F1-A2；见 §9 规格假设 A1）。
- 播放中缓冲区耗尽：自动暂停、画面保持、显示“缓冲中”；数据恢复到起播阈值后自动继续。
- 取消：停止下载、保留 `.part`、回到空态/上一个会话；不得挂住进程。
- 不伪造进度：百分比按“已下载字节 / 已知总字节”；总字节未知时显示字节数，不显示假百分比。

**验收标准**

- **O2-A1** 3 条 `OB` 样本（M1 为 720p、M2 为 1080P30）：每条 20 次冷缓存（清该条缓存）确认→首帧；每条 p95 ≤5s（19/20）DEC-2 已拍板；记录 p50、实际下行速率。
- **O2-A2** 首帧前若等待 >1s：1s 内出现“缓冲中”与进度；无白屏、无“未响应”。
- **O2-A3** 缓冲中取消：≤100ms 回到可交互；`.part` 保留；再次打开可续传DEC-2 已拍板。
- **O2-A4** 播放中耗尽缓冲区：自动暂停 + 缓冲提示；恢复后从当前帧继续；不黑屏、不跳帧、帧号不漂移。
- **O2-A5** 首帧呈现后默认暂停；`Space` 播放/暂停状态变化 ≤100ms（【继承】F1-A3）。

### 2.3 O3 已缓存区间

**行为定义**

- 已缓存区间内，v1 的全部操作**原样可用**：点击/拖动时间轴、`Ctrl+G`、PgUp/PgDn、长按、A/B、0.25–2x、波形、标记/备注、截图、全屏、设置。
- 落点误差必须为 **0 帧**；不允许用关键帧/近似帧替代。
- 帧号、时间码、总帧数三态沿用 v1；索引未覆盖目标时显示“扫描中”，不得假装精确。
- 波形与帧刻度恒定偏移 ≤1 帧；生成中可逐步填充。
- 截图分辨率 = **当前流分辨率**（不是源片）；文件名与清单记录 fps/qn（O6/O10）。
- 在线会话内的标记/截图不因缓存淘汰而丢失（O10）。

**验收标准**

- **O3-A1** 已缓存区连续 20 次 PgUp/PgDn（测试点距缓存边界 ≥2s、解码器热）：帧号严格 ±1、落点误差 0；每条 BV 的 p95 ≤80ms（19/20）（DEC-2 已拍板）。
- **O3-A2** 已缓存区 20 个随机 seek（目标距前关键帧 ≤2s；长 GOP 单列）：索引已覆盖时落点误差 0、p95 ≤200ms（【继承】P9 口径）；索引未覆盖时显示“扫描中”并等待，不冒充。
- **O3-A3** 波形：已生成区间与帧刻度恒定偏移 ≤1 帧；生成中不阻塞步进/拖动。
- **O3-A4** `Ctrl+M` 在已缓存帧添加标记/备注；关窗重开同一 BV：标记与备注仍在、位置一致。
- **O3-A5** `S` 截当前显示帧：PNG 尺寸 = 当前流分辨率、无 UI、文件名含 bvid 与帧号；清单记录 fps/qn。
- **O3-A6** A/B 循环、0.25–2x、全屏、音量/静音在已缓存区与 v1 行为一致。
- **O3-A7** 100 个在线标记：列表/时间轴可操作；点击标记的 UI 响应 ≤100ms（【继承】F6-A8），画面按 P9。

### 2.4 O4 未缓存区间

**行为定义**

- 未缓存区 seek/步进：读层阻塞，UI 进入 `SeekingWait`；**已呈现画面保持**，不黑屏、不显示错误帧。
- 缓冲提示必须包含：目标帧号、已缓存/需要的字节（或百分比）、按“剩余字节 ÷ 实测速率”估算的等待（速率未知时只显示字节）。
- **不承诺 P6/P7/P9 数字**；不允许把等待伪装成“瞬移”。
- 用户改 seek/关窗：取消旧等待（`AVERROR_EXIT` 路径），丢弃过期结果；不得用旧目标帧覆盖新目标。
- 帧号更新时机：目标帧**呈现后**才更新当前帧号；等待中显示“目标帧 N”，当前帧号保持原值。
- 达到目标后：落点误差 0；若索引/解码失败，保留原画面并给可读错误，不冒充目标帧。
- 网络超时/断网：显示可读错误；已缓存区间仍可播放；可重试。

**验收标准**

- **O4-A1** 从未缓存区 seek：≤100ms 显示“缓冲中（目标帧 N）”；画面保持；无错误帧DEC-2 已拍板。
- **O4-A2** 等待中进度/估算至少 1 次/秒更新；公式为“剩余字节 ÷ 实测速率”；速率未知时显示字节；不显示无依据的倒计时。
- **O4-A3** 数据到达后：目标帧精确呈现（误差 0），帧号随即更新；中间不呈现错误帧。
- **O4-A4** 等待中改 seek：旧等待 ≤100ms 被取消；新目标生效；旧目标不覆盖新帧DEC-2 已拍板。
- **O4-A5** 等待中关窗：进程 ≤1s 退出；无死锁/挂起。
- **O4-A6** 缓存边界处按 PgUp/PgDn：进入等待；取到后帧号严格 ±1；不崩溃。
- **O4-A7** 等待中断网：≤5s 可读错误；已缓存区仍可播放；可重试。
- **O4-A8** 未缓存区 20 次 seek：记录实际等待 p50/p95；**只记录，不作为通过/失败门槛**；落点误差必须 0。

### 2.5 O5 缓存与配额

**行为定义**

- 缓存根默认 `%LOCALAPPDATA%\拉片软件\cache`，可在设置中修改；路径与占用对用户可见。
- 结构：`<缓存根>\<bvid>\<cid>\<qn>-<codecid>\`，内含 `data.part`（下载中）/ `data.mp4`（完成）/ `meta.json`。
- `meta.json` 记录：bvid、cid、标题、UP、时长、qn、codecid、宽高、fps、总字节、完成标记、最近访问时间。**不持久化 Cookie，不持久化带签名的播放 URL**（过期后重新解析）。
- 下载中写 `.part`；完成后原子改名为 `.mp4`；MVP 顺序下载，`.part` 是连续前缀，崩溃后按文件长度续传（Range）。
- 配额默认 **20GB**（vision 已拍板），可配置；LRU 淘汰；**当前正在播放的条目永不淘汰**。
- 占用可见（总占用、单条占用）；可手动清空；清空缓存**不删除**在线记录/截图。
- 开播前检查磁盘空间；不足时先提示，不静默失败。
- 缓存损坏（meta/大小不符/无法打开）：检测并给出“重建缓存”，不得把坏数据当成功。
- 不提供导出/分享/另作他用入口。

**验收标准**

- **O5-A1** 默认缓存根/占用可见；修改路径与配额后重启仍生效。
- **O5-A2** 缓存命中：**断网（或网络禁用）**打开同一 BV：0 网络请求；首帧 ≤2.5sDEC-2 已拍板；标题/时长/标记可用。
- **O5-A3** LRU：用小配额（如 300MB）触发淘汰；被淘汰的是最久未用条目；当前播放条目不淘汰；淘汰后总占用 ≤ 配额DEC-5 已拍板。
- **O5-A4** 手动清空：缓存文件删除；在线标记/备注/截图保留；再次打开重新下载。
- **O5-A5** 磁盘不足：开播前或写入失败时 ≤5s 可读错误；已缓存区仍可播放；不崩溃。
- **O5-A6** 下载中杀进程：重开同一 BV 从已下载长度续传（Range）；无重复字节/花屏；`.part` 可继续增长。
- **O5-A7** 缓存损坏（截断/改 meta/改大小）：检测到并提示重建；不用坏数据冒充可播放。
- **O5-A8** 缓存目录不在源视频目录；无“导出/分享”入口；安装/卸载行为见 T8.16（非 MVP 门）。

### 2.6 O6 清晰度、帧率与提示

**行为定义**

- **默认只选 H.264（AVC）且 ≤1080p**；自动顺序（保帧率优先）：
  `1080P60 → 720P60 → 1080P30 → 720P30 → 480P30`。
  普通用户（非大会员）实际只能落到 1080P30 / 720P30 / 480P30（S2）。
- **大会员档按 O11**：1080P60 若 AVC 可用则可自动；若只有 HEVC/AV1，则只进手动菜单、标“60fps / HEVC（手动）”，不自动、不静默降帧；4K 始终只手动。
- **4K 只允许手动选择**，标“可用档：性能/颜色不保证”；允许该档的 HEVC/AV1；**不是 MVP 验收项**。
- 手动切档：重新取流、重建索引/波形；标记按 bvid+cid 保留；切换后必须重新确认“帧号可能变化”。
- **实际流帧率始终可见**（信息栏/角标）；不得把 29.412 显示成 60。
- 当实际流帧率明显低于源片标称（例如 60fps 源只拿到约 29.4fps）：
  - 起播前必须提示“帧率已降，帧号与源片不同步/约为 1/2”；
  - 学习过程中必须有一个**持续可见**的提示（形态见 DEC-4）；
  - 标记与截图清单记录实际 fps/qn/codecid。
- 档位判断只信 `dash.video[]` / `durl` 实际返回，不信 `quality` 字段（S2：请求 qn=116 返回 quality=64，但 dash 无 64 档）。
- 未登录/清晰度受限时明确说明“能拿到什么”，不只说“清晰度受限”。

**验收标准**

- **O6-A1** 3 条 `OB` 样本：显示的档位/编码/fps 与 playurl 实际返回一致；不出现“请求 1080P60 成功”的假象。
- **O6-A2** `OB-2`（60fps 源）在普通用户下：实际 fps ≈29.4；起播前出现降帧提示；学习过程中持续可见（按 DEC-4 形态）；提示文案明确“帧号与源片不同步”。
- **O6-A3** 手动从 1080P30 切到 720P30：重新取流成功；帧号/索引重建；标记仍在；切换提示可见。
- **O6-A4** 4K 档（若凭据可达）：只出现在手动菜单，标“可用档”；默认不选；不进入 M1/M2 验收。
- **O6-A5** 同一 BV 切换档位后，若 fps 不同：按 PTS 映射标记并提示；不得静默声称帧号一致。
- **O6-A6** 在线截图：清单记录 bvid/cid/qn/codecid/fps/frame/pts/路径/时间；缓存清空后清单仍可读。
- **O6-A7** 未登录：显示“未登录，最高约 480P30（以实际返回为准）”；不承诺 720p/1080p。

### 2.7 O7 错误、断网与恢复

**行为定义**

- 所有用户可触发的失败在 **5s 内**给可读原因与下一步；不崩溃、不冻结（【继承】F1-A5/§4.4 的时限）。
- 断网：停止下载、保留已缓存数据；已缓存区可继续播放；显示“网络中断”；可重试；重试从已下载长度继续。
- URL 过期（S2：120 分钟）：到期前或遇 403 时刷新 playurl；刷新成功继续；失败则保留缓存并提示。
- 每个流有 3 个备份 URL（S2）：主 URL 失败按备份重试；全失败再刷新。
- 缓存损坏/磁盘满：按 O5/O7 处理，不丢标记。
- 错误提示不包含 Cookie、签名 URL、完整查询串；日志同样脱敏。
- 具体错误码矩阵见 §5。

**验收标准**

- **O7-A1** 下载中断网：正在播放的已缓存区继续；下载暂停；提示出现；恢复网络后从断点续传。
- **O7-A2** seek 到未缓存区时断网：≤5s 可读错误；已缓存区仍可播放；可重试。
- **O7-A3** 模拟 URL 过期（短 deadline 或注入 403）：自动刷新 playurl 后继续；刷新失败则已缓存可播 + 可读提示。
- **O7-A4** 主 CDN URL 失败：自动切备份 URL；不重复下载已缓存字节；最终成功或给可读错误。
- **O7-A5** 缓存损坏：检测/重建；重试成功；不显示错误帧。
- **O7-A6** 磁盘满：≤5s 提示；不崩溃；标记不丢。
- **O7-A7** API 失败（-400/-404/62002/-101/超时）：5s 内可读；进程不退出。
- **O7-A8** 下载中杀进程后重开：`.part` 可续；在线记录不丢。
- **O7-A9** 所有 O7 场景中，UI 线程停顿 >200ms 的次数 = 0（【继承】P5 口径）。

### 2.8 O8 凭据与隐私

**行为定义**

- Cookie 可选：只接受用户粘贴的 **SESSDATA**；不做扫码/账号密码/多账号。
- 存储：`%APPDATA%\拉片软件\credentials.dat`，用 Windows DPAPI（当前用户）加密；落盘无明文；提供“清除凭据”。
- 自检：用产品实际 HTTP 栈请求 `x/web-interface/nav`，带 SESSDATA 判断 `isLogin`；**放启动还是首次在线打开，DEC-3 已拍板：首次在线打开**。
- 失败：`-101` 映射为“登录不可用/凭据失效”，明确说明“将按未登录清晰度播放”；**不静默降级**。
- 日志/错误/崩溃信息**不得**包含 SESSDATA 或完整 Cookie；不得把 Cookie 发给 CDN 主机（只发 `api.bilibili.com`）。
- 首次在线使用显示隐私说明：会联网、会缓存到哪、Cookie 用途、如何清除；本地模式不显示、不联网。
- 不做遥测/崩溃上报/更新检查。

**验收标准**

- **O8-A1** 保存凭据后：磁盘上无明文 SESSDATA（字符串扫描 `credentials.dat` 与日志）；DPAPI 解密后可完成 nav 自检。
- **O8-A2** 清除凭据：文件删除/失效；后续请求按未登录处理；界面状态同步。
- **O8-A3** 日志与错误对话框：用哨兵 Cookie 测试，任何日志/弹窗/崩溃文本中不出现该值；URL 查询串脱敏。
- **O8-A4** 只有用户提交 BV/URL 后才联网；启动、本地打开、设置、标记、截图、关闭 0 请求（O9）。
- **O8-A5** 首次在线使用出现隐私说明；可关闭；本地模式不出现。
- **O8-A6** 自检失败（-101/超时）：明确“登录不可用”，继续匿名；不假装已登录。
- **O8-A7** Cookie 只发往 `api.bilibili.com`；CDN 请求不带 Cookie（抓包/代理日志证明）。

### 2.9 O9 本地模式零网络不退化

**行为定义**

- v1 的“运行期零网络请求”对本地模式**原样保留**；在线模块必须懒加载：不输入 BV 不初始化网络栈。
- 本地打开路径不经过在线解析/缓存层；代码路径可审计。
- v1 的 F1–F8、P1–P14、键位、焦点、sidecar、截图目录、安装/卸载不联网全部不变。
- 网络审计方法沿用 T7.6：ProcMon/ETW 轮询 TCP/UDP。

**验收标准**

- **O9-A1** 冷启动→打开本地文件→播放→步进→标记→截图→关闭：**0 TCP/UDP**（安装/卸载另测亦 0）。
- **O9-A2** 未输入 BV 时：无 DNS/TLS 请求；网络模块未初始化（线程/DLL 可观测）。
- **O9-A3** P1 ≤1.5s、P2 ≤2.5s、P7 ≤80ms（1080p，热解码器 + 缓存）不退化（【继承】v0.3 §4.1）。
- **O9-A4** F1–F8 回归全过；本地 sidecar/截图/键位/DPI 行为不变。
- **O9-A5** 安装/卸载仍不联网；文件关联与本地双击打开路径不变（【继承】T7.6）。
- **O9-A6** 本地文件打开不产生缓存记录、不写入在线目录（代码/磁盘审计）。

### 2.10 O10 在线记录（标记/备注/截图）

**行为定义**

- 在线标记/备注存 `%APPDATA%\拉片软件\online\<bvid>-<cid>.lapian.json`，schema `lapian-online-1`；**不复用/不修改** v1 的 sidecar schema。
- 字段至少：mark id、frame、pts、fps、qn、codecid、label、note、created_at、updated_at；原子写、损坏备份、无记录不产生文件。
- 截图目录：`%USERPROFILE%\Pictures\拉片软件\<bvid>\`；不可写时回退 `%APPDATA%\拉片软件\online\snapshots\<bvid>\`。
- 截图命名：`<bvid>_f<frame>_<HH-MM-SS-FF>.png`；重名加序号，不覆盖。
- 清单：截图目录内 `index.jsonl` 追加记录（bvid/cid/qn/codecid/fps/frame/pts/path/saved_at）；编码失败不写半条。
- **清空缓存不删除**在线记录与截图；卸载默认保留（用户数据），缓存目录可另行清理。
- 重开同一 BV：标记/备注先于下载可见；点击标记触发 seek（可能进入 `SeekingWait`）。
- 档位切换：标记按 bvid+cid 保留；fps 不同则按 PTS 映射并提示，不静默复用帧号。

**验收标准**

- **O10-A1** 在帧 100 添加标记+备注，关窗重开同一 BV：标记在 100、备注一致；点击跳转并暂停（可先缓冲）。
- **O10-A2** 删除标记并确认：重开后仍不存在；空记录文件被删除。
- **O10-A3** 截图：尺寸 = 当前流、无 UI、文件名含 bvid/f100；`index.jsonl` 记录 fps/qn。
- **O10-A4** 清空缓存后：标记/备注/截图仍在；重开需重新下载，但记录不丢。
- **O10-A5** 1080P30 → 720P30 切档：标记保留；若 fps 相同帧号一致；fps 不同则按 PTS 映射并提示。
- **O10-A6** 损坏的在线记录：备份并回退空记录，不阻塞播放；不丢源文件/缓存。

### 2.11 O11 大会员可用档（B，条件验收，非 MVP 门）

**行为定义**

- **触发条件**：用户凭据为大会员，且 `playurl` 实际返回 1080P60（qn=116）/ 720P60（qn=74）/ 4K（qn=120）。没有大会员账号、或该条视频不返回这些档位 → 本条**不执行**，报告写“未验证”，不得用普通账号冒充。
- **范围**：只覆盖 1080P60 / 720P60 + 4K SDR；720P60 与 1080P60 同口径（P7 同按 1080p ≤80ms 条件，不另设档）；**HDR / 杜比 / 10-bit 颜色正确不在承诺内**；4K HDR 只标“颜色不保证”。
- **1080P60**：
  - AVC 可用时，自动选档可包含 1080P60（`116`）；
  - 只有 HEVC/AV1 时，**不自动选**，只进手动菜单并标“60fps / HEVC（手动）”；不得静默降到 30fps 而不提示；
  - 实际流帧率必须显示；真 60fps 时**不显示**“降帧”横幅；
  - 已缓存区帧精确、步进/seek 走 v1；P7 条件 ≤80ms（硬解、热解码器、距缓存边界 ≥2s）；不达标则标“可用档”，不阻塞 MVP。
- **4K**：
  - **只手动**，菜单标“4K（可用档：性能/颜色不保证）”；默认不选；
  - 允许该档的 HEVC/AV1；4K HDR 颜色不保证；
  - **不承诺 P7/P9**；只要求能打开、能播放、已缓存区能逐帧、不崩。
- **记录**：标记/截图记录 qn/codecid/fps；换档按 bvid+cid 保留，fps 不同按 PTS 映射并提示。
- **报告**：结果单独出 `docs/perf/v2-online-vip.md`；有账号写“通过/部分通过/不通过”，无账号写“未验证”；**不得写成 MVP 通过**，也不进 M1/M2 门。

**验收标准**

- **O11-A1** 有大会员凭据：`playurl` 返回 116/74/120 时，档位菜单可见并标注 fps/codec/“可用档”；无大会员账号时，报告明确“未验证”，不伪造通过。
- **O11-A2** 1080P60/720P60 AVC 可用：自动选 116/74；实际 fps ≥59.5；不显示降帧横幅；已缓存区 20 次 PgUp/PgDn 帧号严格 ±1、p95 ≤80ms（硬解/热；不达标降“可用档”，不阻塞 MVP）。
- **O11-A3** 1080P60/720P60 只有 HEVC/AV1：不自动选；手动菜单可选并标编码/60fps；选择后实际 fps 正确；未选时提示“有更高帧率档，可手动切换”，不静默降帧。
- **O11-A4** 4K：只手动；能打开、播放、已缓存区逐帧不崩；不承诺 P7/P9；HDR 标“颜色不保证”。
- **O11-A5** 4K 或 1080P60/720P60 切回 1080P30：缓存/在线记录不丢；标记按 bvid+cid 保留；fps 不同按 PTS 映射并提示。
- **O11-A6** 报告：有账号时写“通过/部分通过/不通过”；无账号写“未验证”；不得写成 MVP 通过。
- **O11-A7** M1/M2 门不因 O11 失败而失败；O11 也不因 MVP 通过而自动通过。

### 3.2 测量规则

1. **同机、同网、同时间段**；记录机器、网络、实际下行、DNS/TTFB；不跨时段拼数字。
2. p95 口径沿用 v1：同一操作 20 次，≥19 次达标；OP1 每条 BV 单独算 p95，3 条都达标才算通过。
3. OP1 的“冷缓存”指清空该 BV 的缓存，不是清 OS 文件缓存；首次解析（DNS/TLS 冷）与再次解析分开记录。
4. OP2/OP4/OP5 只在**已缓存**状态测；缓存边界外不计入 OP2。
5. **4K / 1080P60 不进入 MVP 门**；OP9 是大会员 1080P60 条件项，OP10 只记录 4K 可用性；T8.15 执行，无大会员账号则“未验证”，不得写成通过。
6. 在线性能证据放 `docs/perf/v2-online-*.md`，必须包含失败样本与未达标项，不得只报达标值。

## 4. 缓存与配额规范（O5 的细节）

### 4.1 目录与文件

```text
<缓存根>\
  <bvid>\
    <cid>\
      <qn>-<codecid>\
        meta.json
        data.part        # 下载中；连续前缀
        data.mp4         # 完成后原子改名
```

- 缓存根默认 `%LOCALAPPDATA%\拉片软件\cache`；设置可改；路径变化不迁移旧缓存（提示用户）。
- `meta.json` 字段：`schema`、`bvid`、`cid`、`title`、`owner`、`duration_ms`、`qn`、`codecid`、`width`、`height`、`fps`、`total_bytes`、`downloaded_bytes`、`complete`、`created_at`、`last_access_at`、`source_fps_hint`（可空）。
- **不存**：SESSDATA、Cookie、带签名的播放 URL、请求头。
- 文件权限：当前用户；不共享给其他用户。

### 4.2 生命周期

1. `view` 确认后建立 `meta.json`（`complete=false`）与 `data.part`。
2. 顺序下载；每写一块更新 `downloaded_bytes`（可 1–2s 节流写盘）。
3. 达到 `total_bytes`：关闭写句柄 → 原子改名 `data.mp4` → `complete=true`。
4. 打开：`complete=true` 且文件大小匹配 → 走本地路径；否则以 `.part` 走可增长读层。
5. 关闭会话：停止下载线程；保留 `.part` 与 meta；记录 `last_access_at`。
6. 启动清理：无 meta 的孤儿 `.part`、超过 24h 未访问的 `complete=false` 条目可清理（可配置/可关闭）。
7. 缓存损坏：meta 缺失/大小不符/无法 probe → 标 `broken`，提示重建；重建先删该条目数据，不删在线记录。

### 4.3 配额与 LRU

- 默认 20GB；可配置（建议 1–100GB，步进 1GB）；设置持久化走 v1 `SettingsStore`（新增键，不改 v1 schema 语义）。
- 计算口径：`data.mp4` + `data.part` + `meta.json` 的实际字节；不含在线记录/截图。
- 淘汰顺序：`last_access_at` 最旧优先；`complete=true` 与 `complete=false` 都参与；**当前会话的 bvid+cid+qn+codecid 不淘汰**；淘汰前确认无读句柄（或标记待淘汰，会话结束后执行）。
- 写入前预检：`可用空间 ≥ 预计总字节 + 512MB`；不足则提示“磁盘空间不足”，不开始下载；已有缓存仍可播。
- 淘汰/清理不得删除在线记录/截图；不得删除用户源视频。

### 4.4 续传

- MVP 顺序下载，`.part` 是连续前缀；重启后以文件实际长度作为已下载字节，Range 从该长度继续。
- 服务端不支持 Range（返回 200 全量）：从头下载并覆盖；UI 提示“服务器不支持断点续传”，不产生双份文件。
- 续传后必须校验 `total_bytes` 一致；不一致（源变了/CDN 返回不同文件）则废弃重建，不拼接。

### 4.5 缓存命中零网络

- 打开顺序：先查 `meta.json` + `data.mp4` 完整性；命中直接按本地文件打开，**不调用 view/playurl**。
- 标题/UP/时长/档位/fps 从 meta 读取；标记/截图从在线记录读取。
- 若用户手动“刷新信息”才允许联网（MVP 可不做刷新入口；不做自动刷新）。

## 5. 错误码与提示矩阵

> 未实测的码只做“通用可读提示”，不编造具体含义；不绕过、不重试到成功。

| 情况 | 检测/码 | 用户提示（要点） | 行为 | 验收 |
|---|---|---|---|---|
| BV/URL 格式非法 | 本地校验 | “BV 号格式不对，应为 BV 开头的 12 位” | 不发请求 | O1-A2 |
| 参数错误 | `-400` | “请求参数错误” | 不重试 | O1-A5 |
| 不存在 | `-404 啥都木有` | “稿件不存在或已删除” | 不重试 | O1-A5 |
| 不可见 | `62002 稿件不可见` | “稿件不可见（私密/审核/删除）” | 不重试 | O1-A5 |
| 未登录/凭据失效 | `-101` | “登录不可用/凭据失效；将按未登录清晰度播放” | 转匿名；不静默 | O8-A6 |
| 风控/限频（未实测） | 非 0 / HTTP 412/429 | “请求被拒绝，请稍后重试” | 退避；不循环 | O7-A7 |
| 付费/大会员/地区限制（未实测具体码） | 非 0 + message | “该内容当前不可用（付费/地区/权限），本工具不绕过” | 停止；不建议绕行 | O7-A7 |
| DRM/加密 | 无法解 | “不支持 DRM/加密内容” | 停止 | O7-A7 |
| DNS/TLS/连接失败 | 客户端错误 | “网络连接失败，检查网络后重试” | 保留缓存；可重试 | O7-A1/A2 |
| 读超时 | 客户端超时 | “网络无响应，重试中…” | 有限重试；保留缓存 | O7-A2 |
| CDN 403/404/5xx | HTTP 状态 | “取流失败，正在切换线路…” | 备份 URL → 刷新 playurl → 错误 | O7-A3/A4 |
| URL 过期 | deadline / 403 | “播放地址已过期，正在刷新…” | 刷新；失败保留缓存 | O7-A3 |
| 磁盘不足 | 预检/WriteFile | “磁盘空间不足，无法继续缓存” | 停止下载；已缓存可播 | O5-A5 |
| 缓存损坏 | meta/大小/probe | “缓存损坏，需要重建” | 标 broken；重建；不删记录 | O5-A7 |
| HTTP 栈自检失败 | nav 非 0 | “当前网络客户端被 B 站拒绝，登录不可用” | 匿名；提示；不假装登录 | O8-A6 |
| 下载被取消 | 用户 | 不弹错误 | 保留 `.part`；回空态 | O2-A3 |
| 解析/取流取消 | 用户 | 不弹错误 | 丢弃结果 | O1-A7 |

**通用要求**：所有用户可触发失败 ≤5s 可读；进程不退出、不冻结；提示不含 Cookie/签名 URL；重试有上限与退避，不无限循环。

## 6. 隐私、合规与网络边界

### 6.1 网络请求白名单

| 目的 | 主机 | 方法 | 携带 Cookie | 备注 |
|---|---|---|---|---|
| 元数据 | `api.bilibili.com`（`x/web-interface/view`） | GET | 可选 SESSDATA | 只在用户提交后 |
| 取流 | `api.bilibili.com`（`x/player/playurl`） | GET | 可选 SESSDATA | 只在确认后 |
| 登录自检 | `api.bilibili.com`（`x/web-interface/nav`） | GET | 可选 SESSDATA | 时机DEC-3 已拍板：首次在线打开 |
| 媒体数据 | playurl 返回的 CDN 主机 | GET/Range | **不带** | 只取当前会话的流；不预取其他视频 |

- 只允许 HTTPS；校验证书；不忽略 TLS 错误。
- 不使用系统代理做地域伪装；用户系统代理照常生效（不额外改）。
- 不请求搜索/推荐/评论/弹幕/收藏夹；不批量；不后台预取。
- 请求频率：单用户、低频、仅用户动作触发；失败退避。

### 6.2 凭据

- 只收 SESSDATA；不收集其他 Cookie；不提供账号密码/扫码。
- DPAPI 当前用户加密；明文只在内存中短暂存在；不做“记住密码”式回显。
- 日志、错误、崩溃文本、缓存 meta 均不得含凭据。
- 一键清除；清除后按匿名处理。

### 6.3 缓存与合规

- 缓存仅本地个人研究使用；不提供导出/分享/再分发入口；不做“下载器”功能（无批量、无收藏夹、无后台队列）。
- 不做付费/DRM/地区限制绕过；失败给可读拒绝，不给绕行建议。
- 发布前做一次合规/ToS 评审（S5/S6），发布说明写明“仅个人研究、公开免费内容、不绕过限制、不再分发”。
- 本地模式零网络是硬承诺（O9）；在线模块不得在启动路径初始化网络。

| 选项 | 内容 | 优点 | 代价/风险 |
|---|---|---|---|
| **A（拍板）** | **首次在线打开（有凭据时）自检一次，会话内缓存结果** | 本地模式仍零网络、P1 不受影响；用户提交 BV 时才知道登录态，语义自然 | 首次在线打开多 0.2–0.5s（nav 60–142ms + 握手） |
| B | 启动时自检 | 打开 BV 前就知道登录态 | **本地模式启动联网，违反 O9/vision“本地零网络”**；P1 风险；未登录用户也被联网 |
| C | 只在设置里提供“测试登录”按钮 | 最保守；零隐式网络 | 用户不点就不知道失效；打开 BV 时才失败，体验差 |

**拍板 A**：仅当存在凭据时、在第一次在线解析前做一次 nav；结果缓存到会话结束；失败明确提示并转匿名。启动、本地打开绝不联网。
**未选 B 的原因**：必须改 O9-A1/A2 与 vision“本地零网络”的承诺，并把 P1 预算重新分配；不建议。

### DEC-4（已拍板 A：起播横幅 + 帧号旁常驻角标）

| 选项 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A（拍板）** | 起播前 InfoBar 横幅（可关闭）+ 帧号旁常驻角标“29.41fps / 降帧” | 起播时不会漏；学习过程中一直可见；与“帧号是核心”一致 | 占空间；角标可能被认为噪音 |
| B | 只在帧号旁常驻角标 | 不打断；持续可见 | 起播时容易漏；用户可能直接开始逐帧 |
| C | 只在详情/信息栏显示 | 最安静 | 学习时看不到；不满足“写在脸上” |
| D | 每次打开弹确认框 | 最强提示 | 每次都弹，打断工作流；可能被无脑确认 |

**拍板 A**，并明确文案：“实际 29.41fps（源约 60fps）：帧号约为源片 1/2，不保证逐帧对应；截图/标记记录实际 fps。” 判定依据：以 playurl/容器实际 fps 为准；若只能从标题/`accept_quality` 推测源 60fps，文案用“可能降帧”，不写死 2:1（S2 只验了一条 2:1）。
**执行细则**：角标在帧号右侧；横幅可关闭，角标不可关。

### DEC-5（已拍板 A：300MB 自动 + 20GB 记账单测 + 可选真填满）

| 选项 | 方法 | 优点 | 代价 |
|---|---|---|---|
| **A（拍板）** | 配额做成可配置；自动化用 **300MB 小配额** 验 LRU/淘汰/占用/磁盘满；再补一次 **20GB 边界** 的记账/淘汰单测（不真填满） | 快、可重复、覆盖算法；配额可配置本身是产品需求 | 不是“真 20GB 填满”的端到端证据 |
| B | 真填满 20GB 再淘汰 | 最真实 | 1080p 约 5.6–6.8 小时；2 周内不现实；网络/磁盘成本高 |
| C | 只手工清空/手工看占用 | 最省事 | 无法证明 LRU/配额上限；发布风险 |

**拍板 A**：因为 vision 已要求“配额可改可清空”，小配额测试不是测试后门，而是产品路径；20GB 只验记账边界（把配额设为 20GB，用合成大文件/占位文件模拟占用，或单测 LRU 计算）。真 20GB 填满留作可选长测（S5），不作为 M1/M2 门。
**执行细则**：接受“300MB 自动 + 20GB 记账单测 + 可选真填满”作为正式验收。

### 规格假设（B/DEC 之外；默认沿用 v1）

- **A1 在线打开仍停在第 0 帧、不自动播放**；“起播”只指首帧呈现且可交互（沿用 v1 F1-A2）。若产品要“确认后自动播放”，需要改 O2 与 F1-A2 的在线语义。
- **A2 在线记录键为 bvid+cid**；标记存 `%APPDATA%`，截图存图片目录；清缓存不丢记录。
- **A3 自动选档只选 AVC 且 ≤1080p**；1080P60/720P60 若 AVC 可用可自动；HEVC/AV1-only 的 1080P60/720P60 与 4K 只手动、标可用档（B 口径）。
- **A4 MVP 顺序下载，不做稀疏 Range 跳取**；未缓存远跳按“剩余字节 ÷ 速率”等待；跳取优化留候选池。
- **A5 在线请求只在用户提交/确认后发生**；不做后台预取其他视频。
- **A6 HTTP 客户端选型不在 S3 定**：由 T8.2 用产品实际栈自检后定（WinHTTP 优先、libcurl 备选），结果补进 ADR-007 评审记录；S3 不预设结论。
- **B1 无大会员账号时**：O11/T8.15 只能写“未验证”，不得用普通账号冒充大会员档；不影响 MVP。
- **B2 4K 只做 SDR 可用档**；HDR/杜比 Vision/10-bit 颜色正确不在 B 的验收范围；若 4K 流是 HDR，只提示“颜色不保证”。
