## 2. 接口给 T8.2 / T8.5

```cpp
// 解析层
lapian::online::BiliInput NormalizeInput(const QString& text);
lapian::online::BiliResolveError ParseViewJson(const QByteArray& json, BiliVideo* out);
lapian::online::BiliResolveResult BiliResolveClient::Resolve(
    const QString& input, const HttpCancelToken& cancel);

// HTTP 抽象（T8.2 可替换实现）
class IHttpClient {
  virtual HttpResponse Get(const HttpRequest&, const HttpCancelToken&) = 0;
};

// UI 确认（T8.5 接这里）
OnlineResolveDialog::confirmed(QString bvid, qint64 cid, int page);
```

- `BiliVideo`：`bvid/aid/title/owner/duration_seconds/pages[]/selected_index`；`pages[]` 有 `page/cid/title/duration_seconds`。
- `BiliResolveError`：`kind`（invalid-input/api/http/network/timeout/cancelled/parse）+ `api_code`/`http_status`/`message`/`detail`。
- `BiliResolveClient` 每次 `Resolve` 只发一次 `view` GET；非法输入 0 请求。
- `IHttpClient` 目前没有 Cookie 头/请求头字段；T8.2 加 SESSDATA 时需要扩展（建议 `HttpRequest::headers` 或专用凭据参数），不要把 Cookie 塞进 URL。

## 4. 已知缺口 / 需要 T8.2 注意

1. **WinHTTP 是 T8.1 的可替换最小实现，不是产品栈决定**。T8.2 必须用产品实际栈做带 SESSDATA 的 `nav` 自检（WinHTTP 优先、libcurl 备选）；两种都 `-101` 就停线重决策（ADR-007 附条件接受）。
2. **动态加载是 dist 的硬约束**：v1 `scripts\check-imports.ps1` 明确禁止 `WINHTTP.DLL` 导入；当前用 `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)` 动态加载，所以 dist 通过。T8.2 若改为静态链接 WinHTTP/libcurl，必须同步 T8.16 的打包/白名单/体积/许可，别静默破坏“本地模式零网络”。
3. **没有 Cookie 路径**：`HttpRequest` 没有 headers 字段，T8.1 只发匿名 GET。T8.2 加 SESSDATA 时：
   - 只发 `api.bilibili.com`，不发 CDN；
   - 不写日志/错误/meta；
   - DPAPI 存储/清除；
   - `-101` 明确“按未登录”，不静默降级。
4. **没有 nav/登录自检**：本任务没有 `nav` 请求，也没有未登录提示之外的账号状态。
5. **没有真实 B 站请求中取消**：真实 WinHTTP 取消在本机慢服务器验证；B 站 view 正常 65–230ms，未注入延迟。T8.2 有凭据/代理后可补“真实请求取消”。
6. **没有 playurl/档位**：`quality` 字段不可信、durl 1080p 1/3、DASH/AAC 等全部留 T8.5/T8.9；未登录提示刻意不写具体档位。
7. **多P live 样本只有一条**；分P 语义有 fixture 单测。OB-5 的 `-400` 用 `BV0000000000` 替代（`BV1`/少一位按 O1-A2 本地拒绝，不发请求）。
8. **真人手测未单独做**：`--online-resolve-test` 驱动产品对话框/按钮，截图供视觉核对；没有真人鼠标/IME 验收。
9. **单机单时段匿名**：网络 RTT 65–230ms，不能外推；T8.1 不测在线起播/P7/缓存命中。
10. 代理/TLS 异常、限频/风控未测；T8.2 HTTP 自检应覆盖。

## 5. T8.2 需要什么

- **账号/凭据**：一个普通用户（非大会员）B 站账号的 `SESSDATA`，放 `.secrets\bilibili_sessdata.txt`（单行、不入库、不回显）；大会员账号另备 T8.15，不进 T8.2。
- **网络**：可访问 `api.bilibili.com` 的 HTTPS；能跑 `curl.exe` 对照（S2 的 curl 通过 / .NET -101 对照）。
- **产品栈自检**：
  - `--online-http-selfcheck`（T8.2 新入口）至少一种产品实际栈 `nav code=0/isLogin=true`；
  - 记录 DNS/TLS/TTFB、`-101`/412/429/超时映射；
  - 若 WinHTTP 自检通过，确认 T8.1 的 `WinHttpClient` 可复用/扩展；若选 libcurl，评估 DLL/许可/体积（T8.16）。
- **凭据**：DPAPI 当前用户加密 `%APPDATA%\拉片软件\credentials.dat`；清除后匿名；哨兵 Cookie 日志/弹窗扫描。
- **环境**：能抓包/代理（证明 Cookie 只发 `api.bilibili.com`，CDN 不带 Cookie）；普通用户账号的 `playurl` 档位留 T8.5/T8.9。
- **回归**：`ctest`、本地 P1/P2/P7、dist 导入表；不要为了网络栈破坏本地零网络。

可直接复制给下一个 agent 的 T8.2 提示词：[docs/next-session-prompt-t8.2.md](next-session-prompt-t8.2.md)。
