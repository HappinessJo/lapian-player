## 4. 关键决定与解释

1. **命中在 playurl 之前**：先 `Scan` 缓存根，`OpenComplete` 校验；命中直接本地打开。这样断网/缓存损坏都不会先发请求，也不会创建 `.part`。
2. **缓存命中走本地 `MediaSession::Open`，不是 `OpenGrowing`**：完整 `data.mp4` 有全量索引/seek/预览；已缓存区 P7/seek 按本地口径，不会因可增长读层回退。`OnlineReadyInfo.source` 为空，`MainWindow` 分开处理。
3. **在线记录用 `MarkStore` 的在线模式**：复用现有 UI 的 AddMark/SetMarkText/RemoveMark/Save/警告链路，但文件/schema/键完全独立；不改 v1 sidecar。逐条保存 `fps/qn/codecid` 是为了换档按 PTS 映射，不静默复用帧号。
4. **记录先于索引可见**：缓存命中打开时立即 `LoadOnlineMarks`；`BeginIndexScan` 在 `online_ready_` 时不清空；索引就绪后再 `ReconcileFrames` 并按 PTS 校正/保存。
5. **截图目录与缓存文件解耦**：在线截图不按 `data.mp4` 所在目录，统一 `Pictures\拉片软件\<bvid>\`；`index.jsonl` 与 PNG 同目录；PNG 成功后才追加。
6. **对话框缓存预检**：只有 P1/无分P 输入才预检；命中时不发 view/playurl/nav，直接回显缓存元数据。多 P 的缓存 `meta.json` 没有分P 号，不猜。
7. **测试根隔离**：`--online-m1-test`/`--online-buffer-test` 用独立 records 根；默认 AppData 验收用 Medium 副本 `--offline-default-paths`，不清理用户缓存；该 BV 已有在线记录先备份为 `.t87-backup`，结束/失败时恢复。
8. **`WaitUntil` 每轮处理事件**：缓存命中的本地 seek 是同步的，predicate 可能立刻真；不处理事件会让 40 次连续 seek 占住 UI，心跳把测试循环误报为产品 UI 停顿。修正后 UI gap 111ms。

## 5. 已知缺口

1. **M1 3/3 720P blocked**（OB-2 360P）；T8.8 才能判。
2. **T8.3.1 未做**：缓存管理 UI/修改路径/配额/打开目录/清空/启动孤儿清理；本任务只接 `ClearAll` 测试语义。
3. **无清晰度选择**：命中取最新完整条目（同时间 qn 更高）；不会按用户档位偏好选，也不提示“缓存的是哪档”以外的选择。
4. **多 P 缓存命中不完整**：`OnlineResolveDialog` 仅 P1/无 `?p=` 预检；P2+ 断网仍走 view 失败。要支持需给缓存 meta 增加分P 号，属于后续任务。
5. **真实断网未做物理拔网/禁用网卡**：0 网络证据是 netstat 轮询 + 模块检查 + 注入计数客户端；T8.13 再做真实断网/403 UI 矩阵。
6. **在线记录写盘在 UI 线程**：首次写新目录可能受 Defender 扫描；E2E mark_save 1ms、UI gap 111ms。未做异步写盘。
7. **记录只读/ACL 失败**：沿用 v1 提示，关窗保存失败可能弹确认框；未改。
8. **截图清单失败不回滚 PNG**；只提示。
9. **默认 AppData 只在 Medium 副本验证**；Low 工作区结果不代表正常用户。
10. **`--online-offline-test` 的缓存键固定 qn=64/codecid=7**（OB-1 720P）；360P/其他档样本需换 key 或先 seed 对应条目。
