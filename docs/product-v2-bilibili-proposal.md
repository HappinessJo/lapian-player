# v2 产品提案：B 站 BV 拉片工作流（2026-10-22，待确认）

> **状态：提案，未拍板。** 本文把“完整品”的第一个闭环写成可执行路线；
> 不修改 `spec.md` v0.3，不写产品代码。需要用户确认边界后，才进入 spike/ADR。
>
> 背景：v1 是本地帧级拉片器（零网络、本地优先）。用户明确第一用户是
> **静止系 MAD 作者 / PV 作者**，第一工作流是：
> **在 B 站找到想研究的 MAD → 在拉片软件输入 BV 号 → 联网加载 → 逐帧观看研究。**

## 1. 产品定义

**一句话**：给 MAD/PV 作者的“B 站参考片逐帧研究工具”——输入 BV，取到本地，
用帧号、波形、循环、标记、截图把片子拆开看。

**核心工作流**：

1. 在 B 站看到想研究的 MAD/PV；
2. 复制 BV 号，粘贴进拉片软件；
3. 软件解析标题/作者/时长/清晰度，下载并缓存到本地；
4. 下载完成后自动打开，停在首帧；
5. 用现有帧级工具（PgUp/PgDn、波形、A/B、标记、截图）研究；
6. 下次打开同一 BV 直接读缓存，可离线。

**关键产品判断**：

- **不是“在线流播放”**：B 站是 DASH 音视频分离，直接流播很难保证帧精确；
  正确路径是“解析 → 下载 → 封装 → 本地播放”。用户感知是“输入 BV 后等一会儿，
  然后像本地文件一样逐帧”。
- **不是“下载器”**：下载只是入口；差异化仍是帧级时间轴、波形、循环、标记、
  截图，以及后续的分镜/节拍/导出。
- **不是“绕过限制”**：只处理用户有权访问的公开免费内容；不做付费/DRM/
  地区限制绕过，不再分发，不批量抓取。

## 2. 为什么这是 v2，而不是 v1 补丁

| 维度 | v1 | v2 |
|---|---|---|
| 网络 | 零网络请求 | 仅在用户输入 BV 后按需联网 |
| 输入 | 本地文件 | 本地文件 + BV |
| 数据 | 用户已有视频 | 新增缓存目录/配额/清理 |
| 依赖 | FFmpeg 本地解码 | 新增 HTTP/JSON/解析/下载/封装 |
| 合规 | 只读本地 | B 站 ToS、版权、Cookie/隐私 |
| 验收 | T7.7 本地片单 | 新增网络/解析/缓存/失败路径验收 |

所以需要：**产品决策记录 + ADR + spec 版本增量 + 新任务**，不能静默改 v0.3。

## 3. 范围（建议的 MVP）

**做**：

- 输入 BV 号（`BV1xx...`）或 B 站视频 URL；
- 解析公开视频的标题、作者、时长、封面、可用清晰度；
- 选择/默认 1080p H.264（硬解兼容优先），失败回退 720p；
- 下载视频+音频，FFmpeg 封装为本地 MP4；
- 缓存目录、进度、取消、失败重试、断点/残留清理；
- 下载完成自动打开；已有缓存直接打开；
- 缓存管理：大小、删除、默认配额；
- 网络状态/错误提示：BV 无效、视频不存在、需要登录、地区限制、付费/DRM、
  网络断开、磁盘不足、解析失败；
- 明确的“联网获取”用户确认与隐私说明。

**不做（MVP）**：

- 不做信息流/推荐/搜索页/排行榜；
- 不做弹幕、评论、字幕；
- 不做批量下载/整个收藏夹；
- 不做 4K/8K/HDR/杜比；
- 不做付费/大会员/DRM/地区限制绕过；
- 不做后台自动预取；
- 不做账号体系/云同步；
- 不做再分发/导出成片。

## 4. 技术路线

### 4.1 主路径：先下载，再本地播放

```text
BV 输入
  → 解析元数据（标题/作者/时长/清晰度列表）
  → 选择清晰度（默认 1080p H.264）
  → 取视频流 + 音频流（DASH，可能分离）
  → 下载到临时目录（带进度/取消/重试）
  → FFmpeg 封装为 MP4（-c copy，不改分辨率/帧率）
  → 校验（时长/流/首帧可解码）
  → 原子移动到缓存目录
  → 用现有 MediaSession 打开
```

**为什么封装成 MP4**：现有引擎、索引、seek、波形都按本地文件工作；
封装后不需要改播放核心，帧精确和性能沿用 v1 的成果。

### 4.2 解析器选型（需要 spike 决定）

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 原生 C++ 解析（HTTP+JSON+签名） | 体积小、可控、无外部进程 | B 站接口/签名会变，维护成本高 | 长期产品 |
| 内置/随包下载器（如 yt-dlp） | 开发快、格式覆盖好 | 体积/许可/更新/安全/被风控 | PoC/内部版 |
| 用户自备外部下载器 | 法律/维护压力小 | 体验割裂，不算闭环 | 过渡 |

**建议**：先用 3–5 天 spike 验证“公开 BV 能否稳定解析/下载/封装/逐帧”，
再决定长期用原生还是内置。**spike 只写脚本/工具，不进产品代码。**

### 4.3 缓存

```text
%LOCALAPPDATA%\拉片软件\cache\bilibili\<BV>\video.mp4
%LOCALAPPDATA%\拉片软件\cache\bilibili\<BV>\meta.json
```

- 默认配额（如 20GB，可设置）；LRU 或手动清理；
- 临时文件 `.part`，失败可清理；完成后原子移动；
- 不做源视频修改；缓存可删除，删除后重新下载；
- 离线时只读缓存，不发任何网络请求。

### 4.4 网络与隐私

- 只有用户输入 BV/点击“获取”才联网；启动、播放、标记、截图不联网；
- 不埋点、不上传使用数据；
- Cookie/登录（如果做）必须用户主动授权、加密存储、可退出清除；
- 日志不记录 Cookie/token/完整 URL 查询串；
- 失败重试有上限和退避，不后台无限重试。

## 5. 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| B 站接口/签名变化 | 解析突然失效 | 解析层隔离、可更新、spike 验证、错误提示 |
| 登录/清晰度限制 | 拿不到 1080p | 先支持公开可用清晰度；登录作为可选增强，需用户确认 |
| 反爬/风控/频率限制 | 请求被拒/封禁 | 单用户、低频、手动触发、退避；不做批量 |
| 版权/ToS | 法律与合规风险 | 只限个人研究、公开免费内容、不再分发；上线前评审 |
| 付费/DRM/地区限制 | 无法获取 | 明确报错，不绕过 |
| DASH 音视频不同步 | 帧/音频错位 | FFmpeg 封装 + 现有 A/V offset 逻辑；验收 V9 类素材 |
| VFR/可变帧率 | 帧号语义 | 沿用 v1 的 VFR 提示与按显示帧计数 |
| 磁盘占用 | 用户磁盘被占满 | 配额、清理、下载前检查空间 |
| 缓存损坏 | 打不开 | 校验 + 重新下载 + 错误提示 |
| 许可（内置下载器） | 分发合规 | ADR 评估；优先原生/外部，不随意捆绑 |

## 6. 分阶段路线（含验收门）

### Phase 0：决策与合规（1–2 天）

产出：

- 本提案确认版；
- `docs/adr/ADR-007-bilibili-acquisition.md`（解析器选型/网络边界/缓存/隐私）；
- `docs/spec-v1.0-delta.md`（把“零网络”改为“按需联网获取 + 离线播放”的新承诺）；
- 明确：公开免费内容、个人研究、不绕过付费/DRM/地区限制。

**Gate 0**：用户确认范围、登录策略、清晰度目标、缓存配额、解析器方向。

### Phase 1：可行性 spike（3–5 天，不接产品 UI）

用独立脚本/小工具验证 3–5 个公开 BV：

- 能否稳定解析元数据与播放地址；
- 能否下载视频+音频并封装；
- 封装后能否被现有 `MediaSession` 打开、索引、逐帧、seek；
- 记录：清晰度、文件大小、下载耗时、首帧/索引/seek、VFR/音画同步；
- 测试失败路径：无效 BV、不存在、需要登录、地区限制、网络断开、磁盘不足。

**Gate 1**：至少 3 个公开 BV 可稳定完成“解析→下载→封装→逐帧”；
若接口/合规不可行，停止，不进入产品代码。

### Phase 2：MVP 集成（1–2 周）

- BV 输入对话框/命令行 `--bv`（内部测试用）；
- 解析→下载→封装→打开的任务流；
- 进度、取消、重试、错误提示；
- 缓存目录/配额/清理；
- 已有缓存直接打开；离线模式；
- 联网确认与隐私说明。

**Gate 2**：真实窗口跑通“输入 BV→下载→首帧→PgUp/PgDn→波形→标记→截图”；
失败路径不崩溃/不冻结；缓存复用不联网。

### Phase 3：健壮性与合规（约 1 周）

- 断网/超时/限流/重试/断点残留；
- 缓存损坏、磁盘满、权限不足；
- Cookie/登录（若确认要做）：授权、加密、退出清除；
- 网络请求审计：启动/播放/标记/截图零请求；
- 错误文案与日志脱敏；
- 真实 B 站素材回归（公开、免费、用户有权访问）。

**Gate 3**：网络失败矩阵通过；无敏感信息落日志；离线模式零请求。

### Phase 4：研究闭环增强（约 1 周）

- B 站元数据展示（标题/作者/封面/时长/BV）；
- 最近打开/缓存列表；
- 恢复上次位置/标记；
- 标记/备注导出（CSV/JSON）作为下一候选；
- 真实 MAD 用户试用 3–5 条，记录“找片→研究”耗时。

**Gate 4**：3–5 位目标用户能独立完成核心工作流；无阻断性可用性问题。

### Phase 5：Beta 与发布（1 周+）

- 安装包/便携版、许可与隐私说明、B 站来源声明；
- 版本号、更新说明、已知限制；
- 失败上报（本地日志，不联网）；
- 发布前法务/ToS 检查。

**Gate 5**：Beta 用户反馈收敛；无 P0/P1 缺陷；发布说明明确“仅个人研究、
不绕过限制、不再分发”。

> 粗估：Phase 0–2 约 2–3 周，Phase 3–4 约 2 周；实际取决于 B 站接口、
> 登录策略与合规判断。先做 spike，再承诺日期。

## 7. 验收标准草案

**功能**

- 输入有效公开 BV：显示元数据，下载/封装后自动打开，停在第 0 帧；
- 已有缓存：不联网，直接打开；
- 逐帧/seek/波形/循环/标记/截图沿用 v1 验收；
- 缓存删除后重新下载可恢复；
- 缓存损坏时可识别并重新下载。

**错误**

- 无效 BV、视频不存在、需要登录、地区限制、付费/DRM、网络断开、磁盘不足：
  5s 内可读提示，不崩溃/不冻结；
- 下载中取消：无残留半成品被当作完整缓存；
- 解析接口变化：给“获取失败，请稍后重试/更新”的可读提示。

**性能（草案，spike 后定）**

- 缓存命中打开 ≤2s（1080p，SSD）；
- 下载速度不承诺（取决于网络/B 站）；
- 下载完成后首帧/索引/逐帧满足 v1 的 P1/P2/P7 口径（本地文件）；
- 缓存配额生效，不无限增长。

**隐私/合规**

- 启动/播放/标记/截图零网络；
- 仅用户主动获取时联网；
- 不记录 Cookie/token；不下载付费/DRM/地区限制内容；
- 不再分发缓存；隐私说明与用户确认。

## 8. 需要用户拍板的 5 件事

1. **登录**：MVP 是否支持 B 站登录/Cookie 以获取更高清晰度？还是先只做公开可用清晰度？
2. **清晰度**：默认 1080p H.264，失败回退 720p，是否接受？是否要 HEVC（硬解兼容性更复杂）？
3. **缓存**：默认目录/配额（如 20GB）是否接受？是否需要“下载后自动删除源缓存”选项？
4. **范围**：是否确认只做公开免费、个人研究、不绕过付费/DRM/地区限制、不再分发？
5. **解析器**：PoC 是否允许临时使用外部下载器（如 yt-dlp）验证？长期是原生还是内置？

## 10. 不做什么（防止跑偏）

- 不做成“B 站下载器/播放器”；下载只是入口，核心仍是逐帧研究。
- 不做推荐流/搜索/弹幕/评论/字幕/4K/HDR。
- 不做付费/DRM/地区限制绕过，不再分发。
- 不在启动/播放/标记/截图时联网。
- 不一次性规划所有“完整品”功能；先闭环“BV→本地→逐帧”。
- 不因为“AI 说能做”就跳过 spike 和合规判断。
