> **状态：提案，未拍板。** 本文把“完整品”的第一个闭环写成可执行路线；
> 不修改 `spec.md` v0.3，不写产品代码。需要用户确认边界后，才进入 spike/ADR。
>
> **v2 修订（2026-10-22）**：用户明确要“不显式下载、直接在线观看并逐帧研究”，
> 同时保留本地文件播放。本文因此从“下载后播放”改为“在线播放优先、边看边缓存”，
> 并明确：**完全零本地数据不可行；可行的是无显式下载步骤的流式缓存。**
>
> 背景：第一用户是**静止系 MAD 作者 / PV 作者**；第一工作流是：
> **B 站找到 MAD → 输入 BV → 在线加载 → 逐帧观看研究。**

## 1. 产品定义

**一句话**：给 MAD/PV 作者的“B 站参考片在线逐帧研究工具”——输入 BV，
几秒内开始播放，边看边缓存，用帧号/波形/循环/标记/截图把片子拆开看；
本地文件模式保持 v1 的能力。

**两种模式**：

| 模式 | 输入 | 数据 | 体验 |
|---|---|---|---|
| 本地模式（v1） | 本地文件 | 用户已有文件 | 零网络、帧精确、全功能 |
| 在线模式（v2） | BV/URL | 边看边缓存 | 几秒起播；已缓冲区域逐帧/seek；未缓冲显示“缓冲中” |

**关键产品判断**：

- **“在线”不等于“零本地数据”**：所有播放器都要缓冲；帧级 seek、波形、
  索引还需要更多数据。产品承诺应是“无显式下载步骤 + 自动缓存”，
  不是“磁盘上不落任何字节”。
- **帧精确优先于“纯流式”**：如果为了不缓存而牺牲 seek/逐帧，产品就失去
  差异化；宁可缓存，也要保证研究体验。
- **本地文件模式不能退化**：在线模式是新增路径，不能把 v1 的本地播放、
  零网络、性能预算改坏。
- **不做绕过**：只处理用户有权访问的公开免费内容；不做付费/DRM/
  地区限制绕过，不再分发，不批量抓取。

## 2. “在线逐帧”的技术现实

一段 B 站视频通常不是单个可直接 seek 的本地 MP4：可能是 DASH 音视频分离、
分片 CDN URL、带过期签名/防盗链。逐帧研究需要：

- 视频流可随机访问到关键帧；
- 音频流可解码，波形可生成；
- 帧索引/PTS 可建立；
- 网络抖动/断线时行为可预期。

因此有三种可行度不同的路线：

| 路线 | 做法 | 起播 | 逐帧/seek | 复杂度 | 建议 |
|---|---|---|---|---|---|
| **A. 渐进式缓存播放** | 从起点顺序下载视频+音频，边封装/边播放；缓存到本地 | 快（缓冲几秒） | 已缓存区域好；未缓存区域等待 | 中 | **MVP 首选** |
| **B. 分段流式 + Range 缓存** | 按 DASH 分片/字节范围点播，虚拟文件/AVIO 给 FFmpeg | 快 | 缓冲区内好；远跳需取分片 | 高 | spike 验证后演进 |
| **C. 直连 HTTP/DASH** | FFmpeg 直接打开远程 URL/MPD | 取决于网络 | seek/索引不可控，易卡 | 中 | 只作对照，不作为主路径 |
| D. 先完整下载再播放 | 下载完成才打开 | 慢 | 最好 | 低 | 只作“离线缓存”选项，不做默认 |

**推荐**：MVP 用 A（渐进式缓存播放），把“在线感”做出来；Phase 1 spike
同时验证 B 是否值得投入。不要一上来做 B，复杂度会拖垮进度。

### 2.1 A 路线的具体形态

```text
BV 输入
  → 解析元数据/清晰度（公开可用清晰度）
  → 选 1080p H.264（失败回退 720p）
  → 从起点顺序取视频+音频
  → 写入本地缓存（临时文件/分片）
  → 边写边用现有引擎打开/播放（或写够阈值后打开）
  → 后台继续取；UI 显示“已缓存 X%”
  → 已缓存区域：PgUp/PgDn、seek、波形、标记正常
  → 未缓存区域：显示“缓冲中”，取到后继续
```

- 用户感知：输入 BV → 几秒后开始播；没有“下载按钮/下载完成”步骤。
- 实际：字节落本地缓存；可在设置里看到缓存大小/清理。
- 可选“离线缓存”按钮：显式下完整片，之后零网络打开。

### 2.2 索引/波形/seek 的边界

在线模式下不能假装和本地一样：

- **总帧数**：优先用容器/元数据；索引未完成时显示“扫描中/≈”。
- **帧索引**：随缓存增长增量建立；未索引区域跳转先等待。
- **波形**：音频缓存到哪生成到哪；未完成显示“波形生成中”。
- **seek**：已缓存区域按本地逻辑；未缓存区域发起网络读取，显示进度。
- **帧步进**：缓冲区内走现有 P7 路径；缓冲区边缘需要等待，不承诺 80ms。
- **断网**：暂停取流、保留已缓存数据、可重试；不崩溃、不丢标记。

## 3. 范围（建议的在线 MVP）

**做**：

- 输入 BV 号（`BV1xx...`）或 B 站视频 URL；
- 解析标题/作者/时长/封面/可用清晰度；
- 默认 1080p H.264，失败回退 720p；
- 在线播放：缓冲阈值起播、进度/缓冲区间、取消、重试；
- 已缓存区域逐帧/seek/波形/标记/截图；
- 缓存目录/配额/清理；缓存命中直接打开；
- 可选“离线缓存”（显式下完整片）；
- 网络错误：BV 无效、不存在、需要登录、地区限制、付费/DRM、断网、磁盘不足、解析失败；
- 联网确认/隐私说明；本地模式保持零网络。

**不做（MVP）**：

- 不做信息流/推荐/搜索页/排行榜；
- 不做弹幕、评论、字幕；
- 不做批量下载/整个收藏夹；
- 不做 4K/8K/HDR/杜比；
- 不做付费/大会员/DRM/地区限制绕过；
- 不做后台自动预取（除当前播放的缓冲）；
- 不做账号体系/云同步；
- 不做再分发/导出成片。

## 4. 架构影响（需要 spike/ADR）

现有引擎假设“本地文件 + 可随机读”：

- `MediaSession`/`VideoDecoder`/`SeekEngine`/`FrameIndex` 都按文件读；
- `FrameIndex` 扫描会读到 EOF；在线模式下 EOF 可能只是“当前缓存末尾”；
- 波形生成按整段音频；在线模式要渐进；
- 缓存文件在增长时，FFmpeg 的 EOF/seek 行为需要验证。

可选实现：

1. **增长中的本地缓存文件 + 自定义 AVIO/等待逻辑**：把“当前缓存末尾”当临时
   EOF，读到末尾时阻塞等待下载；seek 超出缓存时触发下载。改动集中在 IO 层，
   播放/渲染尽量不动。
2. **本地 Range 代理**：本地小代理把缓存暴露为 `http://127.0.0.1/...`，
   FFmpeg 当普通 HTTP 打开；代理负责 Range/缓存/等待。实现快，但多一个进程/
   端口，需处理生命周期与安全。
3. **直接 FFmpeg DASH/HTTP**：只作 spike 对照；不承诺帧精确。

**Phase 1 必须先验证 1 或 2 的可行性，再决定 MVP 架构。** 不要先写 UI。

## 5. 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| B 站接口/签名/CDN 变化 | 解析或取流突然失效 | 解析层隔离、可更新、错误提示、spike 验证 |
| 防盗链/URL 过期 | 播放中途断流 | 及时刷新 playurl、重试、保留缓存 |
| 登录/清晰度限制 | 拿不到 1080p | 先支持公开可用清晰度；登录可选，需用户确认 |
| 反爬/风控/频率限制 | 请求被拒/封禁 | 单用户、低频、手动触发、退避；不做批量 |
| 版权/ToS | 法律与合规风险 | 仅个人研究、公开免费内容、不再分发；上线前评审 |
| 付费/DRM/地区限制 | 无法获取 | 明确报错，不绕过 |
| 网络抖动/断线 | 卡顿/花屏 | 缓冲阈值、重试、暂停、保留已缓存；不崩溃 |
| 索引/波形不完整 | 帧号/波形与本地不一致 | UI 明确“扫描中/生成中”；未完成不承诺精确 |
| 缓存增长 | 磁盘占用 | 配额、LRU/手动清理、下载前检查空间 |
| 缓存损坏 | 打不开 | 校验、重新取流、错误提示 |

## 6. 分阶段路线（含验收门）

### Phase 0：决策与合规（1–2 天）

产出：

- 本提案确认版；
- `docs/adr/ADR-007-bilibili-online.md`（在线模式/缓存/隐私/解析器）；
- `docs/spec-v1.0-delta.md`（“零网络”改为“本地模式零网络；在线模式按需联网”）；
- 明确：公开免费内容、个人研究、不绕过付费/DRM/地区限制。

**Gate 0**：用户确认 5 件事（见 §8）。

### Phase 1：在线可行性 spike（3–7 天，不接产品 UI）

用独立脚本/小工具验证 3–5 个公开 BV：

- 解析元数据/清晰度/播放地址；
- A 路线：顺序取流→缓存→边写边读→现有引擎打开/播放；
- B 路线：Range/分片缓存→虚拟文件/代理→seek；
- 记录：起播时间、缓冲阈值、已缓存/未缓存 PgUp/PgDn、远跳、波形、
  索引、断网、清晰度、文件大小；
- 失败路径：无效 BV、不存在、需要登录、地区限制、付费/DRM、断网、磁盘不足。

**Gate 1**：至少 3 个公开 BV 能“几秒起播 + 已缓存区域逐帧 + 未缓存有明确
缓冲提示”；否则回到 A 路线收窄或暂停在线模式。

### Phase 2：在线 MVP 集成（1–2 周）

- BV 输入、解析、选清晰度、缓冲/播放；
- 缓冲区间/进度/“缓冲中”状态；
- 已缓存区域逐帧/seek/波形/标记/截图；
- 缓存目录/配额/清理；缓存命中直接打开；
- 可选离线缓存；
- 错误/重试/取消；
- 本地模式回归（零网络、P1/P2/P7 不退化）。

**Gate 2**：真实窗口跑通“输入 BV→起播→PgUp/PgDn→seek→波形→标记→截图”；
本地模式回归通过；失败路径不崩溃。

### Phase 3：健壮性/合规（约 1 周）

- 断网/超时/限流/URL 过期/重试/缓存残留；
- 缓存损坏、磁盘满、权限不足；
- 登录/Cookie（若确认）：授权、加密、退出清除；
- 网络审计：本地模式零请求；在线模式仅播放所需请求；
- 日志脱敏；隐私说明；
- 真实 B 站素材回归。

**Gate 3**：网络失败矩阵通过；本地模式零网络；无敏感信息落日志。

### Phase 4：研究闭环（约 1 周）

- 元数据展示、最近打开/缓存列表、恢复位置；
- 标记/备注导出（CSV/JSON）作为下一候选；
- 3–5 位目标用户试用“找片→在线→逐帧→记录”；
- 记录起播/缓冲/操作耗时与阻断问题。

**Gate 4**：目标用户能独立完成核心工作流；无阻断性可用性问题。

### Phase 5：Beta/发布（1 周+）

- 安装包/便携版、许可/隐私/来源说明；
- 版本说明、已知限制（在线模式依赖网络/B 站接口）；
- Beta 反馈、法务/ToS 检查。

**Gate 5**：无 P0/P1 缺陷；发布说明明确“仅个人研究、不绕过限制、不再分发”。

> 粗估：Phase 0–2 约 3–4 周，Phase 3–4 约 2 周；实际取决于 B 站接口、
> 登录策略、在线缓存架构与合规判断。先做 spike，再承诺日期。

## 7. 验收标准草案（在线模式单列）

**功能**

- 输入有效公开 BV：几秒内起播；显示元数据/缓冲状态；
- 已缓存区域：PgUp/PgDn、seek、波形、标记、截图可用；
- 未缓存区域：显示“缓冲中”，取到后继续；不假装瞬时；
- 缓存命中：不联网直接打开；可选离线缓存后完全离线；
- 缓存删除/损坏：可重新获取；不崩溃。

**错误**

- 无效 BV、不存在、需要登录、地区限制、付费/DRM、断网、磁盘不足：
  5s 内可读提示；不崩溃/不冻结；
- 断网后保留已缓存数据；可重试；标记/备注不丢；
- 解析失败给“稍后重试/更新”的可读提示。

**性能（草案，spike 后定）**

- 在线起播：良好网络下 ≤5s（1080p，缓冲阈值可配置）；
- 已缓存区域 PgUp/PgDn：沿用本地 P7 口径（≤80ms，1080p）；
- 未缓存区域：不承诺 80ms，必须显示缓冲状态；
- 正常播放缓冲后：无 >200ms 的 UI/画面停顿（P5 口径，在线单列）；
- 本地模式 P1/P2/P7 不退化。

**隐私/合规**

- 本地模式启动/播放/标记/截图零网络；
- 在线模式仅用户主动输入 BV 后联网；不后台预取其他视频；
- 不记录 Cookie/token；不下载付费/DRM/地区限制内容；
- 不再分发缓存；隐私说明与用户确认。

## 8. 需要用户拍板的 5 件事

1. **在线语义**：接受“边看边缓存、已缓冲区域逐帧、未缓冲显示缓冲中”吗？
   还是要求“任意帧即时、完全不缓存”？（后者技术上不可行/不可靠）
2. **登录**：MVP 是否支持 B 站登录/Cookie 以拿更高清晰度？还是先只做公开可用清晰度？
3. **清晰度/缓存**：默认 1080p H.264、回退 720p；缓存配额（如 20GB）是否接受？
4. **范围**：确认只做公开免费、个人研究、不绕过付费/DRM/地区限制、不再分发？
5. **架构**：Phase 1 是否允许同时 spike “增长文件 + 自定义 AVIO”和“本地 Range 代理”，
   用数据选一个？是否允许 PoC 临时用外部下载器？

## 9. 会话拆分：什么时候开新对话、每个会话谈什么

**原则：一个会话 = 一个决策或一个交付物。** 不要把“产品讨论、技术 spike、
规格计划、编码”塞进同一个会话；也不要把一个会话拖成几十轮。

| 会话 | 什么时候开 | 输入 | 输出 | 这个会话禁止 |
|---|---|---|---|---|
| **S1 产品定义** | **现在**（本对话结束后） | AGENTS、spec、本提案、v1 现状 | 一页 `docs/product-v2-vision.md` + 5 个决定 | 写代码、定最终架构 |
| **S2 可行性 spike** | S1 的 5 个决定确认后 | vision、本提案、代码 | `ADR-007` 草案、`docs/perf/v2-online-spike.md`、go/no-go | 写产品 UI、改 spec |
| **S3 规格与计划** | S2 判定可行后 | vision、ADR、spike 报告 | `spec-v1.0-delta`、plan/tasks、验收标准 | 写代码 |
| **S4 实施** | S3 计划确认后 | 单个 task + 相关文档 | 代码、测试、bench、handoff；**一个 task 一个会话** | 顺手加别的功能 |
| **S5 验收/红队** | MVP 功能完成后 | 构建、测试矩阵、真实 BV | 验收报告、缺陷清单 | 加功能、改阈值 |
| **S6 发布** | S5 通过后 | 包体、隐私/许可/ToS | 发布说明、安装包 | 新功能 |

**开新对话的时机**：

1. **现在就开 S1**：本对话已经很长，且是 v1 收口；继续在这里讨论 v2 会污染上下文。
2. S1 结束、5 个决定写进文档后，再开 **S2**。不要在 S1 里顺手做 spike。
3. S2 给出 go/no-go 后，再开 **S3** 写规格/计划。不要在 spike 里直接写产品代码。
4. S3 通过后，按任务开 **S4**；一个任务一个会话，不要一个会话做五个任务。
5. MVP 完成后开 **S5**；S5 通过后再开 **S6**。

**每个会话的对话方式**：

- **S1（讨论/决策）**：AI 先访谈，不先给方案；每次只问一个问题；给 2–3 个选项和
  取舍；你拍板。不要写代码，不要写最终 ADR。
- **S2（研究/架构）**：AI 先列“未知点/假设”，再设计最小实验；用 3 个公开 BV 测
  起播/缓冲/逐帧/seek/波形/断网；用数据选 A 或 B 路线；写 ADR 草案。不要写 UI。
- **S3（规划）**：AI 把已确认的范围拆成 spec 增量、任务、验收、风险；你做 review；
  不要写代码。
- **S4（实施）**：AI 是 coding agent；先读 AGENTS/handoff/任务；5 行计划；实现；
  `ctest`/`dist`；一次可审查提交；写 handoff。不要改 spec/阈值。
- **S5（验收/红队）**：AI 以挑剔评审者身份找失败模式；用真实 B 站/网络/断网/
  缓存损坏/磁盘满测试；不要改代码或放宽标准。
- **S6（发布）**：AI 做清单/包体/说明；不要加功能。

### 9.1 S1 产品定义（现在开这个）

**会话目标**：把“在线逐帧”说清楚，产出 1 页 vision 和 5 个决定，不写代码。

**开场提示词**：

```text
你是我的产品合伙人。v1 已完成（本地帧级拉片器，ctest 22/22；T7.7 因缺真实
片单/基线机暂缓，按内部预览收口）。现在做 v2 产品定义，第一用户是静止系
MAD/PV 作者，核心工作流是“B 站找到 MAD → 输入 BV → 在线播放 → 逐帧研究”，
同时保留本地文件播放。

先读 AGENTS.md、spec.md v0.3、docs/product-v2-bilibili-proposal.md、tasks.md。

本次只做产品定义，不写代码、不写最终 ADR。请先访谈我，每次只问一个问题：
1. 确认在线语义：接受“几秒起播、边看边缓存、已缓存区域逐帧、未缓存显示
   缓冲中”吗？是否接受“缓存落盘但无显式下载步骤”？
2. 登录/Cookie：MVP 是否支持？还是先只做公开可用清晰度？
3. 清晰度/缓存：1080p H.264 回退 720p、缓存配额（如 20GB）是否接受？
4. 范围：只做公开免费、个人研究、不绕过付费/DRM/地区限制、不再分发？

访谈结束后，输出一页 docs/product-v2-vision.md：目标用户、核心工作流、
MVP 范围、非目标、5 个决定、成功指标、风险。不要写实现细节。
```

**S1 结束条件**：5 个决定都写进文档；你确认“可以做/不做/改范围”。

### 9.2 S2 可行性 spike（S1 后开）

**会话目标**：验证“边看边缓存”能不能做到可用，选架构，不写产品 UI。

**开场提示词**：

```text
你是技术负责人。先读 AGENTS.md、docs/product-v2-vision.md、本提案、
spec.md、plan.md、ADR-001–006。

本次只做 Phase 1 spike，不写产品 UI、不改 spec：
1. 列出在线播放的未知点：B 站解析/清晰度/CDN 时效/DASH 音视频分离/
   索引/波形/断网/缓存增长；
2. 用独立脚本验证 A（渐进式缓存播放）和 B（Range/分片缓存）两条路线，
   用 3 个公开 BV 测：起播时间、已缓存/未缓存 PgUp/PgDn、远跳、波形、
   索引、断网、清晰度、缓存大小；
3. 记录失败路径：无效 BV、不存在、需要登录、地区限制、付费/DRM、断网；
4. 输出 docs/perf/v2-online-spike.md 与 ADR-007 草案，给 go/no-go 结论；
5. 不做付费/DRM/地区限制绕过，不批量抓取，不再分发。

先给 5 行计划，再开始。不要改 v1 的阈值/基线，不要重写播放核心。
```

**S2 结束条件**：3 个公开 BV 能“几秒起播 + 已缓存区域逐帧 + 未缓存明确提示”；
否则收窄范围或暂停在线模式。

### 9.5 S5 验收/红队（MVP 后）

```text

起播、已缓存/未缓存逐帧、seek、波形、断网/重试、缓存损坏、磁盘满、

找 10 个失败模式，按概率×影响排序；给最小复现实验。
不要改代码、不要放宽标准、不要加功能。
```

### 9.6 S6 发布（S5 后）

```text

已知限制、回滚方案；输出发布清单。不要加功能。
```

## 10. 不做什么（防止跑偏）

- 不承诺“完全不缓存/任意帧即时”；在线播放一定缓冲，帧级研究需要缓存。
- 不做成 B 站下载器/播放器；核心仍是逐帧研究。
- 不做推荐流/搜索/弹幕/评论/字幕/4K/HDR。
- 不做付费/DRM/地区限制绕过，不再分发。
- 不在本地模式启动/播放/标记/截图时联网。
- 不一次性规划所有“完整品”功能；先闭环“BV→在线→逐帧”。
- 不因为“AI 说能做”就跳过 spike、合规和真实网络验证。
